# ADR-0028: 다크모드를 지원하기 전까지 시스템바를 라이트로 고정한다

> 상태·날짜·결정자·대체 관계는 위 frontmatter가 단일 출처. 본문은 결정 내용에 집중.

## 맥락

이 앱은 다크모드를 지원하지 않는다. `YGSemanticColorDefaults`의 `YGDarkColorScheme`가
`YGLightColorScheme`를 그대로 가리키고 있고(그 자리에 TODO가 붙어 있다) `-night` 리소스 한정자도
없다. 화면 배경은 어느 시스템 설정에서든 `YGScaffoldV2`의 기본 `containerColor`인 흰색이다.

그런데 시스템바만 다른 규칙을 따르고 있었다. `MainActivity`(`app`·`app-preview` 양쪽)가
`enableEdgeToEdge`를 인자 없이 부르는데, 그 기본값 `SystemBarStyle.auto`는 시스템의 다크모드
설정을 감지해 상태바·내비게이션 바 아이콘의 명암을 뒤집는다. **테마는 다크모드를 무시하고
시스템바만 따라가는 어긋남**이고, 결과는 흰 배경 위의 흰 아이콘이다. 시계·배터리·통신 상태가
사라진다.

증상이 화면마다 달라 보이는 데에는 이유가 하나 더 있다. 카메라 촬영 화면은
`CustomCameraScreen`의 `cameraFeed`가 시스템바 인셋을 받지 않고 화면 전체를 덮으므로, 상태바 뒤에
있는 것이 흰 배경이 아니라 라이브 카메라 영상이다. 여기서는 아이콘이 다크모드에서 오히려 잘 보이고
밝은 장면에서 묻힌다. 같은 원인이 화면 배경에 따라 반대 방향으로 드러난 것이다.

## 결정

**`SystemBarStyle.light`로 시스템바 아이콘을 어둡게 고정한다.** `MainActivity` 두 곳이
`enableEdgeToEdge(statusBarStyle = ..., navigationBarStyle = ...)`로 스타일을 명시한다.

- **`app`과 `app-preview`를 같이 바꾼다** — 컴포넌트 갤러리가 본 앱과 다른 시스템바를 쓰면
  갤러리에서 본 것이 본 앱의 모습이 아니게 된다(ADR-0027이 세로 고정에서 든 것과 같은 이유다).
- **내비게이션 바에만 스크림을 남긴다** — 밝은 내비게이션 바 아이콘은 API 27부터 지원되는데
  `minSdk`가 26이다. 그 한 버전에서는 아이콘이 밝은 채로 남으므로 프레임워크가 `darkScrim`을
  깔아 대비를 확보한다. 값은 androidx의 `enableEdgeToEdge` 기본값을 그대로 쓴다. 상태바는 API 23부터
  지원되므로 스크림이 필요 없고 투명이다.
- **카메라 화면에 예외를 두지 않는다** — 상태바 뒤가 라이브 영상이라 어떤 색을 골라도 어떤
  장면에서는 묻힌다. 예외를 두면 되돌릴 책임이 화면마다 생기는데, 그 대가로 사는 것은 "어두운
  피사체에서 잘 보인다" 하나뿐이고 밝은 장면에서는 반대로 나빠진다.
- **공용 헬퍼로 빼지 않는다** — `core:designsystem`이 `activity`를 의존하지 않아 확장 함수로
  올리려면 모듈 의존을 새로 만들어야 한다. 호출 두 곳의 중복보다 그쪽이 비싸다.

되돌릴 조건은 하나다. **다크모드를 실제로 지원하는 순간** 이 고정을 풀고 `YGCustomTheme`의
`darkTheme`과 같은 값을 보게 해야 한다. `YGSemanticColorDefaults`의 TODO가 그 지점을 가리킨다.

> ✅ **develop 머지(PR #395, 2026-08-27)** — 결정대로 들어왔다. 두 `MainActivity`가 상태바·내비게이션
> 바 스타일을 명시하고, 스크림 값은 각 파일의 최상위 `private val`로 따로 선언된다(공용 헬퍼로 빼지
> 않기로 한 결정의 귀결이다). 되돌릴 지점을 잃지 않도록 `YGSemanticColorDefaults`의 TODO에
> **이 ADR을 가리키는 한 줄**이 함께 붙었다 — 다크모드를 여는 사람이 시스템바도 같이 열어야 한다는
> 것을 그 자리에서 알게 된다.

## 대안

- **대안 A: 다크모드를 제대로 지원한다** — 시스템바가 테마를 따라가는 것이 원래 옳은 모습이고
  `enableEdgeToEdge`의 기본값도 그것을 전제한다. 그러나 다크 팔레트가 정책에 없다. 위키의 색
  규칙(Nametag 칩 12종·토스트 닉네임 컬러·캔버스 점 격자)은 전부 밝은 배경 위에서 실측된 값이라,
  지원한다는 것은 곧 색 정책을 새로 만든다는 뜻이다.
  **→ 기각:** 근거가 될 정책이 없고, 지금은 눈에 보이는 버그를 닫는 라운드다.
- **대안 B: 카메라 화면만 밝은 아이콘으로 전환한다** — 어두운 피사체를 찍을 때 상태바가 살아난다.
  그러나 밝은 장면에서는 정확히 반대로 나빠지고, 화면 진입·이탈마다 스타일을 되돌릴 책임이
  생긴다.
  **→ 기각:** 문제를 옮길 뿐 없애지 못하는데 유지 비용만 는다.
- **대안 C: 카메라 화면에서 상태바를 숨긴다** — 색 문제가 원천적으로 사라지고 뷰파인더가 방해받지
  않는다. 그러나 촬영 중 시계·배터리를 볼 수 없고, 스와이프로 상태바가 다시 나타날 때 잠깐
  어색하다.
  **→ 기각:** 정보를 없애는 것은 안 보이는 것을 고치는 방법이 아니다. C-101 정책에도 근거가 없다.
- **대안 D: 상태바 높이만큼 스크림을 깔고 밝은 아이콘을 쓴다** — 어떤 장면에서도 읽힌다. 그러나
  C-101 정책이 정한 것은 프레임 안팎의 블러이지 상단 스크림이 아니다.
  **→ 기각:** 정책에 없는 그래픽을 구현이 임의로 더하는 셈이라, 위키가 정본인 구도와 어긋난다.

## 영향

**긍정**

- 시스템 다크모드를 켠 사용자에게 상태바 정보가 돌아온다. 앱의 어느 화면에서도 거동이 같다.
- 테마가 다크모드를 무시한다는 사실이 시스템바에도 일관되게 반영된다. 두 축이 어긋난 상태가
  사라지므로, 다크모드를 실제로 여는 날 고칠 자리도 한 군데로 모인다.

**트레이드오프**

- 카메라 촬영 화면에서 밝은 하늘 같은 장면을 잡으면 상태바가 여전히 묻힌다. 의도적으로 남긴
  것이고, 촬영 화면은 체류가 짧다는 판단이 근거다.
- 기기를 다크모드로 쓰는 사용자에게 이 앱만 상태바가 밝은 쪽 규칙을 따르므로, 앱 전환 순간에
  이질감이 있다. 화면 자체가 흰 배경이라 이질감의 뿌리는 시스템바가 아니라 다크모드 미지원이다.

**위험·방어**

- **윈도 설정이라 유닛 테스트로 덮을 수 없다.** ADR-0027의 세로 고정과 같은 성격이고, 확인 수단은
  실기기·에뮬레이터에서 시스템 다크모드를 켜고 끄며 상태바를 보는 것뿐이다.
- API 26 기기의 내비게이션 바 스크림은 폰 대부분에서 드러나지 않는다. 3버튼 내비게이션을 쓰는
  API 26 환경에서 별도 확인이 필요하다.
