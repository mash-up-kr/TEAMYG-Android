# C-101-Loading Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `PictureConfirm` "다음" 뒤의 세그멘테이션 분석을 C-101-Loading 전용 페이지로 옮기고, 결과를 "1개 이상 → 대상 선택 / 그 밖 전부 → 편집 화면" 두 갈래로 줄인다.

**Architecture:** `NavKeySegmentation` 하나가 분석 중에는 로딩 페이지, 1개 이상이면 선택 UI를 그린다. 0개면 `goToAndPopCurrent(NavKeyToppingEdit(completion = RecordAndConfirm))`로 편집 화면이 되고, 편집 완료 시 초안을 기록해 확인 화면으로 `goTo`한다. 에러 화면·재시도·회복 사다리는 삭제한다.

**Tech Stack:** Kotlin, Jetpack Compose, Navigation3, Hilt assisted ViewModel, `BaseViewModel`(MVI), MockK + Turbine, Lottie(`YGLoadingLottie`).

**Spec:** [`docs/superpowers/specs/2026-09-30-c101-loading-design.md`](../specs/2026-09-30-c101-loading-design.md) — 백스택 표·상태 정의·문구는 스펙이 정본이다.

## Global Constraints

- 코드 주석·KDoc 규약: [`docs/code-conventions.md`](../../code-conventions.md)
- 배경 편집 경로(`PictureConfirm`의 `returnResultOnly = true`)는 동작을 바꾸지 않는다
- 편집 화면(`ToppingEditScreen`)의 뒤로·닫기는 팝업 없이 지금처럼 `onBack`
- 로딩 Lottie: `YGLoadingLottie(art = YGLoadingArt.Dark)`
- 문구(정확히):
  - 로딩 제목 `사진을 편집하고 있어요`, 부제 `잠시만 기다려 주세요...`
  - 팝업 제목 `사진 편집을 그만둘까요?`, 본문 `지금까지 편집한 내용은 저장되지 않아요.\n정말 그만두시겠어요?`, 보조 버튼 `그만두기`, 주 버튼 `계속 편집`
- 팝업: `YGModalPopup` + `DesignSystemR.drawable.ic_warning_round`, `secondary = 그만두기`, `primary = 계속 편집`, `onDismissRequest = 계속 편집과 같음`
- "그만두기" 이동: `navigator.popUpTo<NavKeyCanvasMain>()`
- 문자열은 segmentation, camera 모듈 `strings.xml`에 각각 둔다. 공용 팝업 컴포넌트를 만들지 않는다
- 검증: `./gradlew ktlintCheck`, 각 Task의 모듈 `testDebugUnitTest`

## Review Focus

- 팝업이 떠 있는 동안 분석이 끝남 → 결과 보류, "계속 편집"에서 적용, "그만두기"는 결과 버림 (Task 2 테스트)
- 0개 경로에서 원본 저장(`SaveBitmapUseCase`) 실패 → 그래도 편집으로 간다, `sourceImageUri` 사용 (Task 2 테스트)
- 확인 화면에서 `<`로 편집에 돌아와 다시 완료 → 다시 기록하고 다시 `GoToConfirm` (Task 1 테스트: 연속 두 번 기록)
- 선택 UI 상태에서 시스템 뒤로 → 팝업이 아니라 `PictureConfirm`으로 (Task 3, `BackHandler(enabled = isAnalyzing)`, 실기기)
- "그만두기" 뒤 분석이 끝나도 늦게 도착한 결과가 이동을 일으키지 않음 (Task 2 테스트: `ConfirmQuit` 후 effect는 `QuitToCanvas` 하나)
