# Spec: G-001 그룹 목록 화면 (GroupList)

> 상태·날짜·대상·관련은 frontmatter가 단일 출처. 본문은 설계에 집중.
>
> **사후 기록(post-hoc)**: 타 작업자 구현이 선작성 스펙 없이 develop 머지(#173·#176·#180, 2026-08-01)됨.
> as-built 역기록이고 **코드가 SoT**다. 위키 정책 [[무한-파르페-그리드]]·[[g-001-empty-툴팁]]과 대조했다.

> ⚠️ **as-built 갱신(2026-08-07, PR #194 develop 머지)** — 토핑 배치가 들어왔다. 골격만 있던 이 화면에
> `ToppingLayout`(지그재그 커스텀 `Layout`)이 신설되고 `GroupListParfaitLayout`이 `route/component/`로
> 옮겨가 크림 개수 애니메이션을 갖췄으며, 상단 인셋 소유가 `YGTopBarEmpty` 쪽으로 이동했다.
> **배치 좌표 정책은 [[G-001-무한파르페-간격-정책-v0.3]]과 일치**하지만 데이터는 여전히 mock이고
> 변형 타입 랜덤·툴팁 조건·크림 개수 규칙은 미이행이다(아래 [정책 대조](#정책-대조-위키--as-built)).
> PR 이력상 #187이 revert 후 재적용(reapply)된 브랜치다.

> 📌 **진입 경로 결선(2026-08-09, PR #220)** — 그동안 이 화면은 entry만 등록된 도달 불가 상태였다.
> 온보딩 약관 화면(`TermAgreeRoute`)이 `clearBackStack()` 후 `goTo(NavKeyGroupList)`로 넘어오면서
> `Splash → Login → TermAgree → GroupList` 체인이 이어졌다. 백스택이 1개라 이 화면에서 뒤로가기는
> no-op이다([navigation-flow](../../../architecture/navigation-flow.md) "앱 진입 체인"). 화면 내용은 불변.

> ⚠️ **as-built 갱신(2026-08-10, PR #222 develop 머지)** — 실패·새로고침 라운드. `GroupListErrorScreen`
> 신설(`isError` 분기), 목록·에러 두 화면이 `GroupListTopBar`·`GroupListPullToRefreshBox` 두 공유
> 컴포넌트를 함께 쓰게 리팩터, 본문에서 중복 날짜 헤더(`YGDate`)를 제거, 그리고 **A-005 그룹 생성
> 이동이 결선**됐다(`goTo(NavKeyGroupCreate(nickName))`, nickName은 mock). 에러 화면은 코드에 있지만
> **`isError`를 참으로 만드는 경로가 없어 런타임 도달 불가**다(아래 [에러·새로고침](#에러-새로고침-222)).

> ⚠️ **as-built 갱신(2026-08-15, PR #248 develop 머지)** — **그룹 목록이 서버에서 온다.**
> `GetMyGroupsUseCase`(GET `/api/parfait-groups`)가 붙으며 `MockToppingGroup`과 mock 4건 기본값이 삭제되고
> `UiState.groupList`가 `List<MyParfaitGroupVO>`가 됐다. 진입 시 1회 조회 + pull-to-refresh 재조회이고,
> 실패는 `isError = true`라 **도달 불가였던 실패 화면이 실제로 뜬다**. 상대시간은 `GroupTimestamp` 갈래 +
> 화면 문자열 매핑으로 계산하고, 토핑 이미지가 없는 그룹은 템플릿 그래픽으로 떨어진다.
> **남은 mock은 `nickName` 하나**(A-005로 넘기는 인자)다.
> ⚠️ 다만 시각 파싱이 서버 계약과 어긋난다(아래 [주의](#주의--열린-질문)).

> ⚠️ **as-built 갱신(2026-08-17, PR #297 develop 머지)** — **화면이 앞에 설 때마다 다시 묻는다.**
> `GroupListIntent.Enter`가 신설되고 Route의 `LifecycleResumeEffect`가 그것을 보내면서 VM `init`이
> 통째로 사라졌다(날짜 헤더 산출도 `Enter`가 한다). 되돌아온 목록이 갱신되지 않던 문제가 닫혔다
> (OQ-P-169). 함께 **조회 실패 규칙이 뒤집혔다** — 목록이 남아 있으면 화면을 유지하고 사용자가 직접
> 당긴 새로고침 실패만 토스트(`ShowRefreshError`)로 알린다. 토스트 호스트가 필요해 Route 컨테이너가
> `YGScaffold` → **`YGScaffoldV2`**로 옮겨졌다. 자세한 근거·테스트는
> [screen-resume-refetch 스펙](2026-08-17-screen-resume-refetch.md).

> ✅ **as-built 갱신(2026-08-20, PR #312·#320 develop 머지)** — **마지막 mock이 사라졌고 오버레이가
> 나가는 길에 접힌다.**
> **#312**: `UiState.nickName`이 하드코딩 리터럴에서 `GetMyAccountFlowUseCase` 구독으로 바뀌며
> **전역(계정) 닉네임으로 확정**됐다(OQ-P-197 해소). 구독은 `Enter`가 아니라 생성 시점이다 — 계정
> SSoT가 밀어 주는 값이라 화면에 설 때마다 끌어올 이유가 없고 갱신 주체는 로그인·가입·스플래시·
> 닉네임 변경 쪽이다. 타입이 `String?`이 되어 **아직 못 받은 상태를 값으로 표현**하고,
> `NavigateToCreateGroup`이 `data object`에서 **닉네임을 싣는 `data class`**가 되어 Route가
> `uiState`를 다시 읽지 않는다. ⚠️ 대가는 닉네임이 없을 때 그룹 만들기가 로그만 남기고 **조용히
> 안 열리는 것**이다(OQ-P-253).
> **#320**: 그룹 추가 오버레이가 두 이동 인텐트 모두에서 `closeAddGroup()`으로 접힌다 —
> ViewModel이 백스택에 살아 있어 켜 둔 채 나가면 돌아왔을 때 누른 적 없는 오버레이가 떠 있었고,
> 뒤로 가기 한 번을 그것을 닫는 데 쓰게 됐다.
> 두 라운드 합쳐 `GroupListViewModelTest`가 7건 늘었다.

> 🔁 **as-built 갱신(2026-09-04, PR #440 develop 머지)** — **파르페가 아래에서 위로 쌓이고, 실패의
> 갈림이 다시 바뀌었다.** ① 토핑이 `core:ui` `reveal/`의 순차 드러내기로 400ms 간격씩 나타나고
> (재진입에는 안 쌓는다), 높이만 따라 자라므로 크림도 함께 붙는다. ② 당겨서 새로고침이 **로띠 +
> 안내 문구 2줄**이 되고 당기는 동안 목록을 비운다. ③ 그래서 당긴 새로고침 실패는 목록이 남아
> 있어도 에러 화면이고, `ShowRefreshError` 토스트와 그 문자열·토스트 호스트가 걷혔다.
> ④ 초기 조회 덮개를 내리는 시점이 "조회 반환"에서 "캐시가 목록을 냄"으로 옮겼다.
> 아래 [에러·새로고침](#에러-새로고침-222)·[토핑 배치](#토핑-배치--toppinglayout-194-신설) 참고.

## 목표

앱 진입 후 소속 그룹을 파르페 메타포로 보여주는 메인 화면. 1라운드(#173·#176·#180)가 **화면 골격**
(상단 바 · 날짜 · 파르페 배경 · 그룹 추가 오버레이 · 온보딩 툴팁)이었고, 2라운드(#194)가 **토핑 배치**
(지그재그 레이아웃 · 크림 성장 애니메이션 · 상단 인셋)를, 3라운드(#222)가 **실패·새로고침 상태와
그룹 생성 이동**을 얹었다. **그룹 조회는 아직 mock**이다.

## API / 인터페이스

```kotlin
// domain (#248 신설)
class GetMyGroupsUseCase @Inject constructor(private val parfaitGroupRepository: ParfaitGroupRepository) {
    suspend operator fun invoke(): Result<List<MyParfaitGroupVO>>
}
// 🔁 #248: recentImageUploadedAt 타입이 kotlinx LocalDateTime → kotlin.time.Instant 로 바뀌었다
data class MyParfaitGroupVO(
    val groupId: GroupId, val groupName: GroupName,
    val recentImageUrl: String?, val recentImageUploadedAt: Instant?,
)

// impl — 상대시간은 갈래만 고르고 문구는 화면이 붙인다(#248 신설)
internal sealed interface GroupTimestamp { NoImage; JustNow; Minutes(v); Hours(v); Days(v) }
internal fun Instant?.toGroupTimestamp(now: Instant): GroupTimestamp
@Composable internal fun GroupTimestamp.toStringResource(): String

// impl — MVI
data class GroupListUiState(
    val groupList: List<MyParfaitGroupVO>? = null,  // 🔁 #248 mock 삭제 → 🔁 #307 미조회(null)와 0건 구분
    val nickName: String? = null,                // #222 신설(mock) → 🔁 #312 계정 SSoT 구독. A-005로 넘기는 인자
    val groupAddButtonSelected: Boolean = false, // 그룹 추가 오버레이 노출
    val isTooltipVisible: Boolean = false,       // 현재 렌더에 미사용(아래 주의)
    val isError: Boolean = false,                // #222 신설, #248부터 조회 실패가 세운다
    val isRefreshing: Boolean = false,           // #222 신설. pull-to-refresh 인디케이터
    val dateString: String = "",
    val dayOfWeekString: String = "",
) : UiState

sealed interface GroupListIntent : UiIntent {
    data object Enter                            // #297 — 화면이 앞에 설 때마다(재진입 포함)
    data object ClickTopBarChip; data object DismissedTopBarChip
    data object ClickCreateNewGroup; data object ClickEnterNewGroup
    data object ClickSideMenu; data object ClickTopping
    data object Refresh                          // #222
}
sealed interface GroupListSideEffect : UiSideEffect {
    data object NavigateToAppSideMenu; data object NavigateToCanvas
    data object NavigateToCreateGroup; data object NavigateToInviteCode
    data object ShowRefreshError                 // #297 — 당긴 새로고침 실패, 목록은 남아 있음
}

@HiltViewModel
class GroupListViewModel @Inject constructor(
    private val getMyGroups: GetMyGroupsUseCase,   // #248
) : BaseViewModel<…>(GroupListUiState())
```

- 인자 없는 `data object NavKeyGroupList`라 Assisted 주입이 아니다(생성자 의존은 #248의 UseCase 하나).
- 날짜는 `Clock.System.now()`를 기기 타임존 `LocalDate`로 접어 `DateFormat` 두 포맷으로 산출한다.
  화면은 이미 만들어진 문자열만 받는다. **#297부터 VM `init`이 아니라 `Enter`가 부르는 `updateToday()`가
  산출한다** — 앱을 켜 둔 채 자정을 넘겨도 머리말이 어제에 머물지 않게.

### 신설 공용 유틸

| 심볼 | 모듈 | 용도 |
|---|---|---|
| `DateFormat.FullMonthWithDay` / `.AbbreviatedDayOfWeek` | `core:util:jvm` `model/` | `kotlinx-datetime` `LocalDate.Format` 2종(영문 월+일 / 영문 요일 약어) |
| `Modifier.drawTooltipCornerTop(...)` | `core:util:android` `extension/` | 툴팁 상단 말풍선 꼬리. 바깥 삼각형(테두리색) 위에 안쪽 삼각형(배경색)을 덮어 선처럼 보이게 함 |
| `AnnotatedString.Builder.withStyle(textStyle) { }` | `core:util:android` `extension/` | `TextStyle` → `SpanStyle` 변환을 감춘 오버로드 |

## 동작 / 상태

- **사이드 메뉴**(`ClickSideMenu`) → `NavigateToAppSideMenu` → `goTo(NavKeyAppSetting)`.
- **그룹 추가 칩**(`ClickTopBarChip`) → `groupAddButtonSelected = true` → 오버레이 노출.
  오버레이 바깥(=오버레이 루트 `Column`) 클릭 → `DismissedTopBarChip` → false.
- **그룹 만들기**(`ClickCreateNewGroup`) → `NavigateToCreateGroup(nickName)` → `goTo(NavKeyGroupCreate(nickName))`
  (#222, 인자 출처는 #312에서 계정 SSoT가 됐고 **이펙트가 값을 싣는다**). 닉네임이 아직 없으면
  이펙트 자체를 안 쏜다(OQ-P-253).
- **그룹 들어가기**(`ClickEnterNewGroup`) → `NavigateToInviteCode` → `goTo(NavKeyGroupInviteCode)`.
- 위 둘은 **나가기 전에 그룹 추가 오버레이를 접는다**(`closeAddGroup`, #320).
- **토핑 클릭**(`ClickTopping`) → `NavigateToCanvas`(TODO stub). 현재 이 인텐트를 발신하는 UI가 없다.
- **화면 진입**(`Enter`, #297): `updateToday()` + 목록 조회. `LifecycleResumeEffect`가 보내므로
  **처음 열릴 때뿐 아니라 다른 화면에서 돌아올 때마다** 온다 → [screen-resume-refetch 스펙](2026-08-17-screen-resume-refetch.md).

  실제로도 조회가 돌고 있다는 코드 주석 — 약관 화면과 같은 관용구).
  성공은 `groupList` 교체 + `isError = false`.

> 📌 **첫 조회에 덮개가 붙었다(2026-08-30, PR #407 develop 머지)** — `isRefreshing` 옆에
> `isInitialLoading`이 하나 더 생겨 `YGScaffoldV2(isLoading = …)`로 간다(바로 아래 파일 구성의
> "`isLoading`은 넘기지 않는다" 주석은 이 PR로 뒤집혔다). **둘을 합치지 않는다** — 당겨서
> 새로고침 인디케이터와 화면 덮개는 그리는 자리가 다르다. 켜는 조건은 `groupList == null`

> 수 있어서**다(그 화면은 자기 인디케이터를 돌리고 있어 덮개까지 얹으면 표시가 겹친다).

> 조건이 캔버스 쪽과 따로 적혀 있는 것은 OQ-P-330.

- **조회 실패**(#248 → 🔁 #297에서 규칙 교체): **목록이 남아 있으면 화면을 유지**하고
  (`isError = groupList.isEmpty()`), 사용자가 직접 당긴 새로고침이었을 때만 `ShowRefreshError`를 보내
  토스트로 알린다. 목록이 비어 있으면 종전대로 `isError = true`로 실패 화면에 가고, 그 화면이 이미 실패를

  뒤로 온 것만으로 보던 목록이 사라지는 값이 돼 뒤집혔다. 사유(네트워크·서버·그 외)는 로그로만 갈린다.

### 상대시간 — `GroupTimestamp` (#248)

- ViewModel이 아니라 **화면 계층**에서 계산한다. `Instant?.toGroupTimestamp(now)`가 갈래를 고르고

- 두 시점의 차이라 기기 타임존과 무관하다.

### 토핑 이미지 선택 — `toToppingImage()` (#248)

### 파르페 레이아웃 — `GroupListParfaitLayout` (#194 재작성)

`SubcomposeLayout`으로 `cherry → top → middle* → bottom`을 **가운데 정렬 세로 스택**한다.
#194에서 `route/` → `route/component/`로 옮기고 크림 개수 변화를 애니메이션하도록 다시 썼다.

- 각 이음매를 겹침 상수만큼 당긴다: `CherryOverlap`·`TopOverlap`·`MiddleOverlap`·`BottomOverlap`
  (`GroupListParfaitDefaults`, 호출자 override 가능).
- **덮음 판정 기준이 바뀌었다** — 구현 초안은 `bottomSection`까지 포함한 전체 스택 높이와 `content`를
  비교했으나, 접시는 토핑을 받치지 않으므로 **`creamTop + middleHeight`(= 크림이 실제로 덮는 하단)** 과
  비교한다. 모자란 만큼 `middleSection`을 올림 나눗셈으로 반복 서브컴포즈하고, 겹침을 뺀
  실증가분(`middleStep`)이 0 이하면 반복하지 않는다(무한 루프 방어).
- **개수 애니메이션**: measure가 구한 목표 개수를 `Animatable`(`MiddleAnimationSpec`, `tween` +
  `FastOutSlowInEasing`)로 좇는다. 소수부 하나가 개수·위치·알파·bottom 위치를 동시에 정한다 —
  늘어날 때는 직전 크림 자리에서 미끄러져 내려오며 fadeIn, 줄어들 때는 제자리 fadeOut. 알파를
  위치보다 빠르게 채워야(`ALPHA_RAMP`) 전환 중 크림과 접시 사이가 비치지 않는다.
  배치는 `placeRelativeWithLayer`의 layer 블록에서 알파를 넘겨 recomposition·redraw 없이 처리한다.
- **첫 프레임 스냅**: measure 전(`NOT_MEASURED`)에는 아무것도 하지 않고, 첫 목표 개수는 `snapTo`로
  맞춘다(안 그러면 화면 진입마다 파르페가 자라 보인다). 오버슈트하는 `animationSpec`은 넘기면 안 된다.
- z: 체리·top·bottom은 `FRONT`, middle은 뒤로 갈수록 `FRONT - n`(앞선 크림이 위), `content`는 최상단.
- 프리뷰 2종(짧은 `content` / 긴 `content`)이 파일 안에 있다 — `@Preview` 단독(`@YGPreview`·`PreviewBox` 미사용).
- 에셋은 `feature/groups/list/impl` `res/drawable`에 있다(`parfait_cherry`·`parfait_cream_top`·
  `parfait_cream_default`·`parfait_cup`·`group_list_background`). 디자인시스템이 아니라 화면 소유다.

### 토핑 배치 — `ToppingLayout` (#194 신설)

`GroupListParfaitLayout`의 `content` 슬롯에 들어가는 **지그재그 커스텀 `Layout`**. 위키
[[G-001-무한파르페-간격-정책-v0.3]]의 좌표 모델을 파라미터로 표현한다.

| 파라미터 | 기본값 | 대응 정책 |
|---|---|---|
| `contentPadding` 좌/우 | 호출부가 `padding2` 주입(= `SizeTokens.Size4`) | 좌·우 인셋 4 |
| `overlap` | 12dp를 **빼는** 방향 | 같은 side 세로 갭 -12 |
| `alternateOffsetY` | 86dp | Right 열 = Left 열 + 86 |
| `contentPadding` top | 호출부가 `SPECIAL_RULE_THRESHOLD`(=3) 이하일 때 +12dp | 저개수 N=1/2/3 → y +12 내림 |

- `index % 2`로 좌/우 열을 가르고(짝수 Left), 각 열이 독립적으로 `높이 - overlap`만큼 내려간다.
  높이는 마지막으로 놓인 아이템의 실제 하단(`contentBottom`)으로 잡는다 — 열 커서(`leftY`/`rightY`)를
  쓰면 마지막 항목에서 `overlap`이 한 번 더 빠진다.
- 호출부(`GroupListContent`)가 `TOPPING_PLACEMENT_TYPES`(6타입 `Left/Right × 1/2/3`)를 **index로 순환**
  적용해 `YGToppingGroup(type = …)`에 넘긴다. 코드에 `// Todo : 로직 추후 변경하기`가 붙어 있고,
  정책은 **랜덤 재부여**라 여기서 갈린다(아래 정책 대조).
- ~~`Modifier.animateToppingPlacement`(+`ToppingLayoutDefaults.PlacementAnimationSpec`)가 같은 파일에
  있다.~~ 자리 밀림을 순간이동 대신 애니메이션하는 용도였고, KDoc이 "호출부에서 각 항목을 안정적인 key로
  감싸야 한다"고 요구했다. **사용처 0건으로 남다가 🔁 #514(2026-09-20)에서 둘 다 삭제됐다**
  (호출부가 여전히 `fastForEachIndexed`로 key 없이 그려 그 전제가 채워진 적이 없다)
  → [open-questions](../../../synthesis/open-questions.md) [2026-08-07].
- `ToppingLayout`이 **`public`**이다(같은 폴더 `GroupListParfaitLayout`은 `internal`).
  feature `impl` 내부 전용이라 가시성이 갈린다. #514 이후 남은 public 심볼은 이것 하나다.
- 📌 **아래에서 위로 하나씩 쌓인다(#440 develop 머지, 2026-09-04)** — `reveal: RevealState` 파라미터가
  붙고(기본값 `AllRevealed`라 종전 호출은 그대로다) 호출부가 `core:ui`의
  `rememberStaggeredRevealState(total, stepMillis = 400ms)`를 넘긴다. `ToppingLayout`이 하는 일은
  **아직 안 드러난 아이템을 높이 계산에서만 빼는 것**이다 — 파르페가 이 높이로 크림 개수를 정하므로
  높이가 한 칸씩 자라야 크림도 따라 붙고, 측정·배치를 그대로 둬야 이미지 요청이 이어진다. 가리는 것은
  `Modifier.revealed`(알파 0 + 시맨틱 제거)이고 클릭도 드러난 뒤에만 받는다. 호출부는 각 카드를
  `key(groupId)`로 감싸는데, 키가 없으면 목록이 바뀔 때 슬롯이 자리 기준으로 재사용된다.
  **재진입에는 쌓지 않는다** — 조회가 재진입마다 나가므로(`Enter`) 좁히지 않으면 돌아올 때마다
  파르페가 다시 자란다. 기준은 덮개와 같은 "아직 한 번도 못 받은 조회"다.
  ⚠️ 간격 400ms의 근거는 "크림이 내려오는 시간과 맞춘다"는 코드 주석뿐이고 정책 소스가 없다 → OQ-P-357.

### 에러·새로고침 (#222)

- **분기 위치**는 Route다. `uiState.isError`면 `GroupListErrorScreen`, 아니면 `GroupListScreen`.
  별도 목적지가 아니라 같은 `YGScaffold` 안의 상태 분기다.
- **`GroupListErrorScreen`** = `GroupListTopBar`(칩·툴팁 없음) + `GroupListPullToRefreshBox` +
  `LazyColumn`(가운데 정렬) 한 아이템: 안내 문구(`title.t03SB`/`Gray500`, `strings.xml` `group_list_error`)
  + `Spacer` + 파르페 컵 이미지(`parfait_cup`). 문구가 "아래로 당겨 다시 시도해 주세요"라 **복구 수단이
  pull-to-refresh 하나**다(재시도 버튼 없음).
- **`GroupListPullToRefreshBox`** = Material3 `PullToRefreshBox` 래퍼. 기본 동작(인디케이터만 내려옴)과
  달리 **콘텐츠도 함께 내려가도록** 안쪽 `Box`에 `graphicsLayer { translationY = state.distanceFraction *
  PullToRefreshDefaults.PositionalThreshold.toPx() }`를 건다. 목록·에러 두 화면이 같은 래퍼를 쓴다.
- **인디케이터는 Material3 기본**이다 — 위키 [[무한-파르페-그리드]]가 요구한 "자체 로딩 그래픽"이 아니다.
- **도달 불가**: `isError = true`는 `GroupListErrorScreen` 프리뷰에만 있다. 인텐트도 조회도 없어
  실기기에서는 이 화면이 뜨지 않는다 → [open-questions](../../../synthesis/open-questions.md) [2026-08-11].
- 화면 상수 3종(콘텐츠 상단 패딩·문구↔컵 간격·컵 폭)이 파일 상단 private `val`의 raw dp다. 프리뷰는
  `@Preview`+`PreviewBox`(같은 라운드의 `GroupListScreen`은 `@YGPreview`).

🔁 **재작성(#440 develop 머지, 2026-09-04)** — 디자인 두 프레임(둘 다 이름이 `G-001-Error`다:
하나는 새로고침 중, 하나는 실패)을 근거로 셋이 바뀌었다.

- **인디케이터가 로띠 하나에서 로띠 + 안내 문구 2줄이 됐다**(`group_list_refreshing` 신설,
  `group_list_refresh_error` 삭제). 문구는 **새로고침이 확정된 뒤에만** 뜬다 — 임계값이 벌리는 틈에는
  로띠밖에 안 들어가므로, 문구가 붙는 순간 열리는 틈을 실측 블록 높이만큼 더 벌린다. 알파는
  `animateFloatAsState`가 몰고, 인디케이터의 세로 기준도 그 알파를 따라 늘려야 블록 높이가 안 튄다.
  문구가 완전히 사라진 뒤에는 컴포지션에서도 빼는데, 알파만 0으로 두면 **TalkBack이 안 보이는 문구를
  읽기** 때문이다.
- **당기는 동안 목록을 비운다** — 디자인의 새로고침 프레임이 빈 컵이다. 비우는 자리는 캐시도
  `UiState`도 아닌 **화면**이다(`isRefreshing`이면 빈 목록을 그린다). 캐시는 `StateFlow`라 같은 목록을
  다시 받으면 재방출하지 않아, 거기서 비우면 그 값이 그대로 굳는다.
- **당긴 새로고침 실패는 목록이 남아 있어도 에러 화면이다.** 화면이 이미 목록을 비운 뒤라 실패를
  받아 줄 자리가 거기뿐이라서다. 그래서 `ShowRefreshError` 토스트가 도달 불가가 되어 이펙트·문구·
  Route의 토스트 호스트가 함께 걷혔다. 재진입 조회 실패만 낡은 목록을 남긴다
  (`isError`는 **켜기만 하고 끄는 것은 성공한 조회뿐**이다 — 끄면 실패한 재진입 조회가 앞선 실패를
  덮어 낡은 목록이 표시 없이 돌아온다) → OQ-P-348 · [state-management](../../../architecture/state-management.md).
- ⚠️ **디자인의 세로 위치와 구현이 다르다** — 디자인은 로띠·문구 블록을 화면 중앙 근처에 두고 콘텐츠를
  더 크게 내리는데, 구현은 임계값이 여는 틈 안에 넣어 블록 높이 + 로띠가 남기던 여백만 연다.
- **초기 조회 덮개도 내리는 자리가 옮겼다** — 조회가 반환한 시점이 아니라 **캐시가 목록을 실제로 낸
  시점**이다(그 사이 틈에 토핑 없는 빈 파르페가 드러났다). 캐시 구독은 시작하자마자 `null`을 한 번
  내므로 그때는 안 내리고, 조회 실패는 캐시가 아무것도 내지 않으므로 실패 갈래에서 따로 내린다.
