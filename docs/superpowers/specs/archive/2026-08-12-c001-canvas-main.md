# Spec: C-001 캔버스 메인 화면

> 상태·날짜·대상·관련은 위 frontmatter가 단일 출처. 본문은 설계 내용에 집중.
>
> 📌 **심볼 리네임(2026-08-17, #278)** — 아래 본문의 `CanvasImageAdd*`는 **당시 이름**이다. 현재 코드는 **`CanvasMain*`**(`NavKeyCanvasMain`·`CanvasMainRoute`/`Screen`/`ViewModel`/`UiState`/`Intent`/`Effect`, `strings.xml` 키 `canvas_main_*`). 이름만 바뀌고 시그니처·동작은 불변이라 본문은 기록대로 둔다.

> ⚠️ **사후 스펙(as-built)** — 선작성 스펙 없이 PR #199(`feature/#193-canvas-default-screen`)가
> develop에 머지됐다(2026-08-11). 화면 껍데기(`CanvasImageAddRoute`·`Screen`·`ViewModel`)는 그
> 전부터 있었고 본문이 `Text` + Material3 `Button` 2개였다. 이번 PR이 **디자인시스템 캔버스 5종을

> 흡수했다. 아래는 머지 코드를 역기록한 것이며 설계 대조가 아니라 **규약(parfait)·정책(위키)
> 대조**로 드리프트를 표기한다.

## 목표
그룹의 오늘자 캔버스를 화면 크기와 무관하게 위키 [[캔버스-반응형-레이아웃]] 규칙대로 그리고,
토핑 추가 진입(카메라·갤러리)을 캔버스 하단 메뉴로 연다.

## 범위
- **포함**
  - `YGCanvas` **반응형 배치 흡수** — 좌우 패딩·상하 최소 gap·세로 중앙 정렬·세로 부족 시 축소를
    컴포넌트가 계산한다(직전까지는 `fillMaxWidth` + `aspectRatio`뿐이었다).
  - `Modifier.ygBackgroundDotGrid()` 신설(`core:designsystem` `component/ygbackgrounddotgrid/`) —
    화면 배경 점 격자.
  - `YGCanvas.onDimClick` 신설 — Dim 탭으로 확장 메뉴를 닫는다.
  - 인접 테두리 겹침 — `YGCanvasMenu` 버튼 행·확장 스택과 `YGCanvas`의 Area↔Menu 접합을
    `spacedBy(-1.dp)`로 겹쳐 접합선을 1dp로 만든다.
  - 화면 조립 — `YGTopBarCanvas`(그룹명 + 멤버 칩 슬롯 + 메뉴) + `YGCanvas`(`weight(1f)`),
    메뉴 펼침 상태는 화면 로컬 `remember`.
  - `feature/groups/canvas/impl` `strings.xml` 신설(빈 캔버스 안내·메뉴 라벨 4·`+N` 포맷).
  - UiState에 `groupName`·`memberChips`·`canvasDate`·`canvasDay` 신설(전부 mock/로컬 계산).
- **제외**(이번 라운드에서 안 함)
  - 그룹·토핑 데이터 연동 — 그룹명·멤버 칩은 ViewModel 하드코딩, 토핑 슬롯(`content`)은 비어 있고
    `isEmpty`가 상수 `true`다.
  - ~~날짜 선택(캘린더)·상단 메뉴·캔버스 편집~~ — 이 라운드에선 콜백이 전부 빈 람다 + TODO였다.
    캔버스 편집은 #231, **날짜 선택은 #259**에서 결선됐고 상단 메뉴만 남았다(아래 "동작 / 구조").
  - 화면 진입 경로 — `NavKeyCanvasImageAdd`로 `goTo`하는 호출자가 develop에 없다.

## 동작 / 구조

### 화면 구성
- 엔트리는 규약대로 `entry<NavKeyCanvasImageAdd> { YGScaffold { innerPadding -> … } }`이고
  인셋은 `YGScaffold` 기본값이다(G-001의 탑바 흡수형과 다른 형태 →
  [open-questions](../../../synthesis/open-questions.md) [2026-08-07]).
- `CanvasImageAddScreen`은 세로 `Column`이고 배경이 `Gray.White` + `ygBackgroundDotGrid()`다.
  위에서부터 `YGTopBarCanvas` → `YGCanvas`(`weight(1f)`·`fillMaxWidth`).
- 화면 최외곽 컨테이너 `YGScreen`은 쓰지 않는다(G-001·A-002와 같은 규약 이탈).

### 캔버스 반응형 배치 (`YGCanvas`)
컴포넌트가 `BoxWithConstraints`로 자기 배치를 계산한다(`calculateCanvasLayoutMetrics`).

| 조건 | 결과 |
|---|---|
| 높이 제약 없음(`hasBoundedHeight` false) | 기본 폭(좌우 `padding7`) + 최소 gap(`padding5`) |
| 세로 여유 있음 | 기본 폭 유지, 상하 gap = 남는 높이의 절반(중앙 정렬) |
| 세로 부족 | gap을 최소값에 고정하고 **캔버스를 축소** — 좌우 패딩이 기본값보다 커진다 |

- Canvas-Area만 `aspectRatio` 9:16이고 메뉴 높이(`SizeTokens.Size44`)는 비율 계산 밖에서 더해진다.
- 총높이에서 1dp를 빼 Area↔Menu 테두리 겹침분을 보정한다(그만큼 하단 gap이 상단보다 1dp 크다).
- 확장 메뉴는 예전대로 `Spacer(Size44)`로 자리를 예약해 총높이를 유지한다.

### 토핑 추가 메뉴
- "토핑 추가"(`addAction`) 클릭 → 화면 로컬 `isMenuExpanded = true` → `isDimmed`·`isMenuExpanded`가
  동시에 켜진다(Figma `Status=Expanded` 조합).
- 확장 항목 2종("카메라로 촬영"·"갤러리에서 선택")은 각각 자기 람다에서 메뉴를 먼저 닫고 Intent를 쏜다.
- Dim 탭(`onDimClick`)으로도 닫힌다. Dim은 `clickable(indication = null)`이라 아래 레이어 터치를
  계속 소비한다(직전 구현의 소비 전용 `pointerInput`을 대체).
- Intent → SideEffect → `navigator.goTo` 경로는 그대로다. 다만 **이름과 목적지가 어긋난다** —
  `OnClickCanvas` 인텐트와 `NavigateToCanvas` 이펙트가 실제로는 갤러리(`NavKeyCustomGalleryPicker`)로 간다.
- `ResultEffect<String>` → `CacheImage` → `AddRecentImageUseCase` → `NavigateToSegmentation` 경로는
  이번 PR 이전 그대로인데, C-102 갤러리가 결과 반환을 끊어 **호출되지 않는다**
  → [open-questions](../../../synthesis/open-questions.md) [2026-08-04].
- 📌 **날짜 선택 결선(2026-08-16, PR #259)** — `onClickDateSelect`가 `OnClickDateSelect` 인텐트로
  이어져 `isCalendarVisible`을 토글하고, `YGCanvas`의 `calendarContent` 슬롯에 화면 로컬
  `CustomCalendar`가 들어간다. **Dim이 메뉴와 캘린더를 겸한다** — `isDimmed = isMenuExpanded ||
  isCalendarVisible`이고 `onDimClick`이 둘 다 닫는다. 다만 **고른 날짜가 캔버스·상단 날짜 라벨을 바꾸지
  않는다**(달력도 닫히지 않는다) → [c201 스펙](2026-08-16-c201-canvas-calendar.md).
- 📌 **캔버스 편집 결선(2026-08-15, PR #231)** — `YGCanvas`의 `editAction`이 C-301 배경 편집으로
  간다. 다만 그 화면이 고른 배경은 돌아오지 않고(확인 이펙트가 TODO) C-001은 여전히 `YGCanvas`에
  `background`를 넘기지 않아 기본값 `Solid(Gray100)`이다. 같은 PR에서 `NavKeyCameraCustom`·
  `NavKeyCustomGalleryPicker`가 `data class`로 승격돼 이 화면의 호출부도 `NavKeyCameraCustom()`·
  `NavKeyCustomGalleryPicker()` 생성자 호출로 바뀌었다(인자는 전부 기본값 — 가이드 토스트 노출·
  세그멘테이션 전진이 종전대로다) → [c301 스펙](2026-08-15-c301-canvas-background-edit.md).

### 상단 바
- `YGTopBarCanvas(title = 그룹명, memberContent = …)`의 **첫 실사용처**다.
- 멤버 칩은 `YGNametagChip(chip = Style28)`을 `Arrangement.spacedBy(-12.dp)`로 겹쳐 최대 5개까지
  그리고, 초과분은 `YGColorChipType.NametagChipPlus` 칩에 `+N`을 얹는다.

### 배경 Dot Grid
- `drawBehind`로 `spacing` 간격 격자를 그리는 `Modifier` 확장이다. 기본값은 지름 `SizeTokens.Size2`·
  색 `YGAtomicColors.Gray.Gray100`·간격 `SizeTokens.Size20`으로 위키 정책 값과 같다.
- 원점은 이 Modifier가 붙은 요소의 좌상단이다.

## 정책 대조

| 위키 정책 | 코드 | 판정 |
|---|---|---|
| `Canvas = Canvas-Area + Canvas-Menu`, 하단 gap 없이 이어짐·별도 탭바 없음 | `Column(spacedBy(-1.dp))` 2단 | 일치(테두리 1dp 겹침) |
| Canvas-Area**만** 16:9, 메뉴는 고정 높이로 별도 가산 | `CANVAS_AREA_ASPECT_RATIO` + `Size44` | 일치 |
| 상하 최소 gap 12·좌우 패딩 20·세로 중앙, 세로 부족 시 캔버스 축소 | `padding5`/`padding7` + `calculateCanvasLayoutMetrics` | 일치 |
| 좌상단 컷 도형 + 날짜 라벨(높이 고정·너비 가변) | `canvasCutCornerShape()` + `YGCanvasDateSelectButton` | 일치 |
| Dot Grid 지름 2·Gray-100·간격 20 고정, 개수만 증가 | `Size2`·`Gray100`·`Size20`, `drawBehind` 타일링 | 일치 |
| Dot Grid는 화면 전체(상단바·하단바 포함) 뒤, 앵커 화면 좌상단 (0,0) | `YGScaffold` `innerPadding` 안쪽 | **불일치**(드리프트 2) |
| 캔버스 영역은 배경이 Dot Grid를 덮어 가림 | Area 배경 `Solid(Gray100)` 기본값 | 일치 |
