### 1. 개요

#### 1.1 목적

파르페에 푸시 알림을 도입한다. 목적은 두 가지다.

1. **그룹 활동 인지** — 그룹원이 사진·텍스트를 쌓거나 배경을 바꿨다는 사실을 즉시 알린다.

1. **마감 사이클 인지** — 캔버스가 매일 03:00 KST에 마감된다는 서비스 구조상, 마감 전에 참여할 기회를 안내한다.

#### 1.2 확정 사항 요약

| 항목 | 결정 |
| --- | --- |
| 알림 종류 | P-01 사진 등록<br>P-02 오전 리마인드<br>P-03 저녁 리마인드<br>P-04 텍스트 등록 (신규)<br>P-05 배경 변경 (신규)<br>P-06 활동 묶음 알림 (신규, 알림 모아 받기 ON 수신자 한정) |
| 알림 번호 원칙 | 기존 P-01~P-03 번호는 유지하고 신규는 뒤에 붙인다. 서버·클라이언트에서 이미 쓰는 번호를 바꾸지 않기 위함 |

#### 2.6 P-06 — 활동 묶음 알림 (신규)

- S-105 **'알림 모아 받기' ON** 수신자에게만 적용한다. OFF(기본값)면 P-01·P-04·P-05를 지금처럼 개별 발송한다.

- 묶음 대상은 **P-01·P-04·P-05**다. 리마인드(P-02·P-03)는 묶지 않고 정시 발송한다.

| 항목 | 내용 |
| --- | --- |
| 성격 | **정보성** (그룹 내 활동 누적 사실 통지) |
| 윈도우 단위 | **(수신자, 그룹, 캔버스 date)**마다 독립. 본인 활동은 제외되므로 같은 그룹이어도 수신자마다 윈도우 시작 시점과 N이 다를 수 있다(정상) |
| 윈도우 길이 | **10분**. 앱 UI에는 노출하지 않는다 (S-105 정책 P-4) |
| 발송 대상 | 윈도우가 끝났을 때 누적 활동이 1건 이상인 수신자 |
| 시간 제한 | **없음** |
| 진입 화면 | **C-001** (해당 그룹의 해당 일자 캔버스). 딥링크는 P-01과 동일 |

##### 발송 규칙

| # | 규칙 |
| --- | --- |
| 1 | 열린 윈도우가 없을 때 들어온 활동은 **즉시 개별 발송**(P-01·P-04·P-05 문구 그대로)하고, 그 시점부터 10분 윈도우를 연다 |
| 2 | 윈도우 안에서 들어온 활동은 발송하지 않고 누적한다 |
| 3 | 윈도우가 끝나면 누적분을 **P-06 1건**으로 발송한다. 누적이 0이면 발송하지 않는다 |
| 4 | 윈도우가 끝난 뒤 들어온 활동은 다시 1번(즉시 발송 + 새 윈도우)으로 처리한다. 묶음 발송 직후에 들어온 활동도 즉시 발송한다 |
| 5 | 윈도우는 고정 주기로 반복하지 않는다. 활동이 없으면 아무것도 하지 않고 대기한다 |

```plain text
예시 (수신자 1명, 그룹 1개 기준)
10:00  활동 → 즉시 발송 (개별 문구)    윈도우 10:00~10:10
10:03  활동 → 누적 1
10:10  윈도우 종료 → P-06 발송 (N=1)
10:11  활동 → 즉시 발송 (새 첫 알림)   윈도우 10:11~10:21
10:15  활동 → 누적 1
10:21  윈도우 종료 → P-06 발송 (N=1)
10:40  활동 → 즉시 발송 (새 첫 알림)   윈도우 10:40~10:50
10:50  윈도우 종료, 누적 0 → 발송 없음
```

- 활동이 계속되는 그룹이면 수신자당 **10분에 최대 2건**(첫 알림 1건 + 묶음 1건)이 발송된다.

##### N 집계 (서버 회신 대기 — 확정 시 갱신)

- 윈도우 안에서 누적된 활동 수. 즉시 발송된 첫 알림은 포함하지 않는다.

- 사진 등록·텍스트 등록·배경 변경을 각 1개로 센다. 본인 활동은 제외한다(E-01).

- 발송 시점에 다시 집계해 그사이 삭제된 활동은 뺀다. 결과가 0이면 발송하지 않는다(E-26).

- N 표기 상한(두 자리 이상일 때 처리 등)은 서버 회신 후 확정한다.

##### 문구

```plain text
제목: {그룹명} 파르페에 체리가 또 톡!
본문: 그사이 새 소식이 {N}개 쌓였어요
```

- 사진·텍스트·배경 변경 구분 없이 문구를 통일한다.

- 닉네임을 노출하지 않으므로 작성자 탈퇴·나가기 치환(E-05)이 필요 없다.

- 그룹명은 발송 시점의 그룹명을 쓴다(E-28).

### 3. 권한 정책

#### 3.1 요청 시점

- **A-004(그룹 참여) 또는 A-005(그룹 생성) 완료 직후, G-002 진입 전 1회.**

#### 3.2 요청 전 안내

'토핑' 제거 (기존 제목: 그룹원이 토핑을 쌓으면 알려드릴까요? / 기존 본문: 새 토핑 소식과 캔버스 마감 안내를 받을 수 있어요.) — **클라이언트 문구라 앱 업데이트 필요**

```plain text
제목: 그룹원이 캔버스를 꾸미면 알려드릴까요?
본문: 그룹원의 새 소식과 캔버스 마감 안내를 받을 수 있어요.
      알림은 언제든 기기 설정에서 끌 수 있어요.
버튼: [알림 받기]  [나중에]
```

- `[알림 받기]`  → OS 권한 다이얼로그 호출

- `[나중에]` → OS 다이얼로그 호출하지 않고 G-002 진입. **재노출 없음** (v0.1 기준)

#### 3.3 거부 시 동작

- 서버에 토큰이 등록되지 않으므로 **발송 시도 자체를 하지 않는다.**

- 앱 내에서 권한 재요청 배너·모달을 띄우지 않는다.
  - 예외: 이용자가 직접 S-105(알림 설정)에 들어왔고 OS 알림이 꺼져 있으면, 화면 안에 꺼짐 상태 안내와 이동 버튼을 노출한다. 팝업 재요청이 아니라 설정 화면의 상태 표시다. 자세한 동작은 S-105 정책 §3.4·§4 참고

- 이용자가 스스로 켜려면 **기기 설정 > 알림 > 파르페**에서 허용한다. 이 경로는 S-004(약관 및 개인정보 처리방침) 화면과 개인정보처리방침 본문에 안내한다.

#### 4.3 도착 후 예외

- **날****짜가 넘어간 경우**: 푸시의 `date` 기준 캔버스로 진입한다. 오늘자로 리다이렉트하지 않는다. 해당 캔버스가 이미 마감(03:00 경과)됐어도 그 일자의 C-001로 진입한다(마감 캔버스는 편집 불가).

- **해당 사진·텍스트가 신고·삭제된 경우**: 캔버스는 정상 진입하되 토스트 `해당 사진은 삭제됐어요` / `해당 텍스트는 삭제됐어요` (클라이언트 문구라 앱 업데이트 필요)

- **P-05로 진입했는데 그 사이 배경이 또 바뀐 경우**: 별도 처리 없이 현재 배경으로 보여준다.
