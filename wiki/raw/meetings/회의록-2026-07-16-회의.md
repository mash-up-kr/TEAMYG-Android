## 1. 세션 A — 무한 파르페 은유 + 서비스 정체성 (H1·H2 통합)

### 가설

라벨·온보딩 설명 없이도 사용자는

1. G-001 무한 파르페를 **내가 속한 그룹들의 목록**으로 읽고,

2. 그룹을 추가할수록 파르페(스크롤)가 길어지는 것을 "**내 그룹이 쌓인다**"로 직관하며,

3. 이 서비스를 **혼자 쓰는 사진 편집툴이 아니라 여럿이 함께 쌓는 기록 서비스**로 인지한다.

### 사전 세팅

- 테스트 계정: 이미 로그인 상태, **그룹 0개 = Empty G-001**로 시작.

- 참가자에게 온보딩·설명 없이 화면 노출 상태로 기기 전달.

- A-005 생성용 그룹명은 참가자 자유 입력, A-004 참여용 초대코드는 진행자가 제공.

- **UT 프로토타입 조작 2가지**

    - **스크롤 성장 앞당김**: 실제 개발은 2-1-2-1 행 기준 대략 3개 단위마다 세로 성장이지만, UT에서는 **N=2 시점부터 이미 세로 스크롤이 생기게** 세팅.

        > 목적: **"그룹이 늘어난다 = 스크롤이 늘어난다"**를 직관적으로 보여주기.

    - *그룹 추가 2회 이후부턴* **GNB 그룹추가 shortcut**: 상단 GNB '그룹 추가하기' 버튼 탭 시, **참여/생성 절차와 C-001 진입 없이** G-001에서 바로 토핑 +1 & 파르페 성장. (UT 전용 데모 장치 — 실제 진입 정책 아님)

### 플로우 (연속 · 토핑 누적)

```plain text
[G-001 · Empty(0개)]
   └ (게이트 0 : 첫인상·정체성)
   └ Task A : 새 그룹 만들기   A-005 → G-002 → C-001
   └ Task B : "초대코드를 복사하고 처음 화면으로 돌아오기"  C-001 → [G-001 · 1개]
   └ Task C : 초대코드로 그룹 들어가기  A-004 → G-002 → C-001
   └ "처음 화면으로 돌아오기"  C-001 → [G-001 · 2개 · 스크롤 성장 시작]
   └ (게이트 1 : 변화 인지)
   └ Task C : 상단 GNB '그룹 추가하기' 버튼 2~3회 탭
              → 매 탭마다 절차 없이 즉시 토핑 +1 & 스크롤 성장
   └ (게이트 2 : 성장 귀인 · 핵심)
```

> 설계 의도: Task A·B는 "그룹은 이렇게 들어가는구나"를 정식 경로로 심고,
> Task C는 절차를 걷어내 **"그룹 수 ↑ = 파르페/스크롤 ↑"** 인과만 순수하게 노출.
