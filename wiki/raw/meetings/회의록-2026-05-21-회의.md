    # 회의록

    ## 개요

    스프린트 진행 상황 공유와 핵심 기능 결정, 서비스 명칭 투표 방식을 논의한 팀 회의. 참여자들은 개발, 디자인, 제품 관리를 담당하며, MVP(최소 기능 제품) 범위와 관련된 기술적, 디자인적 우선순위가 다루어짐.

    ## 참가자 & 역할

    - **개발팀**: 안드로이드, iOS, 서버(백엔드) 담당

    - **디자인팀**: UI/UX, 카메라 디자인 책임

    - **프로덕트 및 기획**: 기능 우선순위, 스프린트 계획, 도메인 정리

    - **운영·QA**: 테스트 계획 및 이슈 관리

    - **스프린트 리더**: 회의 진행 및 결제 감독

    ## 결정 사항

    | 항목 | 내용 |
    | --- | --- |
    | **MVP 기능 범위** | - 사진 업로드 후 위치 고정(수정 금지) <br> - 다중 선택이 아닌 한 대상을 선택 <br> - 좌표 정보만 서버에 저장, 이미지 자체는 무시 |
    | **카메라 UI** | - 디자인팀이 먼저 시안 제시 <br> - 버튼 수는 3개 이하로 제한 <br> - 완료 후 기능 우선순위 **B** 로 평가 |
    | **서비스 명칭 투표** | - 후보를 카톡방에 제시 후 투표 <br> - 가장 높은 득표율을 가진 명칭 선택 |
    | **도메인 정리** | 서비스명 정해진 뒤 즉시 도메인 확보 진행 |
    | **레포지토리 및 템플릿** | - 팀별 저장소 구조 확정 <br> - 라퍼스토리(wrapper story) 생성 시 서비스명 기준 수행 |
    | **인터뷰 질문** | 기존 질문 검토 후 필요 시 소수 편집 |

    ## 행동 항목

    - **서비스명 후보 공유** – 카톡방에 투표용 메시지 업로드 (담당자: SPR-C언니)

    - **카메라 디자인 시안 최종화** – 디자인팀에서 시안 리워드 (기술적 검토 필요)

    - **서버 좌표 처리 구현** – 백엔드팀에서 API 설계 및 테스트 (MVP 단계)

    - **도메인 예약** – 인프라팀에서 도메인 신청 및 설정

    - **레포지토리 정리** – 팀별 저장소 설정 완료 및 문서 (노션) 업데이트

    - **인터뷰 질문 최종안** – 기획팀에서 최종 확인 후 인쇄/디지털 자료 배포

    ## 토론 포인트

    - **수정 기능 유무**: MVP 단계에서 정렬 후 수정 금지 논의 → 서버 좌표 저장 방식이 핵심, 추후 필요 시 기능 추가 예정

    - **UI 복잡성**: 카메라 UI 디자인이 개발 난이도에 미치는 영향 평가 → 간단 UI 결정 시 개발 리스크 감소

    - **투표 방식**: 카톡방에서 후보 제출 후 자동 투표 vs. 직접 회의 결정 방안 비교

    - **MVP 범위 확장**: 다중 사진 선택, 사용자 사진 고정 기능의 장기적 필요성 논의 → MVP 종료 후 단계별 기능 확대 계획

    - **서비스 명과 도메인**: 브랜드 아이덴티티와 도메인 일관성 확보의 중요성 강조
