# S-002 앱닉네임 정책

# 1. 초기 닉네임 자동 생성

## 1.1 생성 시점 및 로직

- **계정 생성 시 1회**, `형용사/동사` 리스트 1개 + `파르페 재료` 리스트 1개를 랜덤 조합하여 앱 닉네임을 자동 부여한다.
- 조합 형식: `{형용사/동사}{재료}` (공백 없이 붙여쓰기). 예: `녹는딸기`, `몽글한푸딩`.
- 생성된 닉네임은 **계정 생성 즉시 DB에 저장**되며, 이후 재계산되지 않는다. (재렌더링 시점에 다시 뽑지 않음 — G-001 토핑 회전 로직의 `Math.random()` 금지 규정과는 별개 사안. 토핑 회전은 매 렌더마다 동일 결과가 나와야 하는 반면, 닉네임은 1회성 부여 후 고정값이므로 난수 소스 제약이 다르게 적용됨.)
- 생성 주체(서버/클라이언트) 미정 — **[K2] 서버에서 생성 후 응답으로 내려주는지, 클라이언트가 생성해서 서버로 올리는지 확정 필요.** 계정당 유일성이 필요 없다면(중복 허용) 클라이언트 생성도 가능하나, 어뷰징/치우침 방지 관점에서는 서버 생성 권장.

# 2. 수정 시 유효성 규칙

## 2.1 허용 문자

- **한글, 영문, 숫자, 공백(스페이스바)** 만 입력 가능.
- 특수문자·이모지 입력 불가.

## 2.2 글자 수 제한

- **최소 1자 ~ 최대 15자.**
- 글자 사이 공백(띄어쓰기)도 **1글자로 카운트**.

## 2.3 공백(띄어쓰기) 제한

- 맨 **앞·맨 뒤에는 공백을 넣을 수 없음**.
- 글자 사이 공백은 **1칸만 허용**, **연속 공백은 제한**.

---

# 3. 입력 예시 가이드

## 3.1 통과 케이스

- `열다섯글자열다섯글자열다섯글자` — 공백 없이 15자 충족.
- `홍 길동` — 글자 사이 공백 1칸이므로 가능.

## 3.2 불통과 케이스

- `   ` — 공백으로만 채운 닉네임 → 불가.
- ` 길동` 또는 `길동 ` — 시작/끝에 공백 포함 → 불가.
- `홍  길동` — 글자 사이 공백 2칸 연속 → 불가.
- `열 다 섯 글 자 열 다 섯 글 자 열 다 섯 글 자` — 15자 초과 → 불가.

---

# 4. 정책 적용 범위

- **그룹 내 닉네임**: 2~3장 유효성 규칙 적용.
- **앱 닉네임**: 계정 생성 시 1장(초기 자동 생성)이 우선 적용되며, 이후 사용자가 수정할 때부터 2~3장 유효성 규칙이 적용됨.
