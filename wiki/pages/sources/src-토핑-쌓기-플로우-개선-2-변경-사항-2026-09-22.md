# [260922] 토핑 쌓기 플로우 개선_2 — 변경 사항

## 요약

**토핑 추가·편집 흐름을 다시 짠 변경 목록**이다. Figma `[디자인] 파르페 v0.1`의
캔버스 페이지에 있는 섹션 "[260922] 토핑 쌓기 플로우 개선_2" 안의 텍스트 레이어
하나이고, **Detail Type 카드가 없다.** 그래서 판본 번호·작성자 표기가 없고, 날짜는
섹션 이름의 `260922`에서만 나온다.

**UX_1의 설계 문서다.** [[src-회의록-2026-09-21-우선-순위-정의-회의]]가 1순위로
올린 "토핑 추가 플로우 개선"이고, [[src-회의록-2026-09-22-회의]]가 "디자인 회의
확정 내용은 Figma에 있다"고 적은 그 Figma 내용으로 읽힌다. UX_1은 10/15에
배포됐다([[src-회의록-2026-10-20-회의]]).

**하루 앞선 초안이 따로 있다.** Development 페이지의 "[260921] 토핑 편집 플로우
개선 방향"([[src-figma-주석-Development-페이지]])이 같은 제목들을 먼저 적었다. 이
문서는 그 초안을 고친 것이다. 다만 그 초안은 여러 주석을 담은 페이지의 일부라
판본 대체로 묶지 않는다.

## 변경 사항

각 항목은 원본이 AS-IS / TO-BE로 적었다.

| 항목 | AS-IS | TO-BE |
|---|---|---|
| **캔버스 편집 → 배경 변경** | 캔버스 편집 안에 토핑 편집·배경 변경이 탭으로 묶였고 **기본 탭이 배경 변경이라 토핑 편집이 인지되지 않음.** 둘 다 2뎁스 | **토핑 편집 진입은 본인 토핑 터치로 축소.** 캔버스 편집 버튼은 **배경 변경**이 되어 바로 배경 변경 페이지로 |
| **테두리 수정 무조건 거치기, 중간 페이지 삭제** | 대상 선택 후 `다음`을 누르면 편집을 건너뛰고 바로 배치로 감 | `C-103-Select`에서 대상을 고르면 **바로 대상 영역 선택 페이지**로. 거기서 누끼 결과를 보고 바로 수동 편집하거나 `다음`으로 **`C-106`** 배치로. `C-106`에서 **테두리·회전·크기·위치**를 정하고 `캔버스에 쌓기` |
| **하단 탭 일괄 폐지** | 기본 탭이 아니면 인지되지 않음. 탭에 따라 `<`/`✓` 바 위치가 달라짐 | 위 항목대로 페이지를 정리 |
| **회전·확대는 두 손가락** | 토핑 모서리에 회전·확대·삭제 아이콘 | **삭제 아이콘만.** 회전·확대는 두 손가락 제스처 |
| **헤더 규칙 통일** | `X`/`✓` 바가 상단·하단에 섞임 | 상단 `<`/`X` 바, 하단 풀폭 버튼 하나. 화면명 표기 |
| **누끼 감지 실패 랜딩** | 감지 실패 → `C-103-Error` → [편집 없이 사용] / [직접 편집] | **에러 페이지 없이 `C-104`로 직행** + 토스트 `대상 감지에 실패했어요, 영역을 직접 선택해 주세요` |

### 테두리는 페이지가 아니라 패널이다

테두리 설정은 **배치 화면 안의 패널**로 언제든 펼치고 접는다. **반드시 거쳐야
쌓을 수 있지만** 페이지로 두지 않고 회전·크기·위치와 한 화면에 합쳐 **뎁스를
늘리지 않는다.**

### 헤더 버튼의 뜻

- `<`는 **직전 단계**로 간다.
- `X`는 편집·추가 기능 자체를 닫고 `C-001`로 간다. **변경이 있으면 "정말
  그만두겠냐"는 팝업을 1회** 띄운다.
- 한 화면에서 끝나는 기능(배경 편집)에는 `X`만 있다.

### 되돌리기는 `C-104`에만

테두리 편집 화면의 `<`·`>`(되돌리기·다시하기) 버튼을 없애고 영역 수정 화면에만
둔다. **근거가 적혀 있다.**

- `C-105`의 색·굵기는 컨트롤 자체가 현재 상태를 보여 주므로 되돌리기는 "직전 값
  다시 고르기"와 같다. 없음으로 돌아가려면 `없음` 칩을 누르면 된다. 이력이 쌓이는
  화면이 아니라 버튼만 는다.
- **`C-104`(영역 수정)는 브러시 획이 이력으로 쌓여** 손이 미끄러졌을 때 복구할
  방법이 필요하다.

### 에러 페이지를 지운 근거

**"기존 에러 페이지의 두 선택지가 결국 둘 다 `C-104`로 이어져서, 중간에 고르게
하는 단계 자체가 의미 없음."**

## 기존 위키와 어긋나는 것

- **누끼 실패 분기가 플랫폼별로 갈리던 것이 사라진다.** [[src-기능정의서-v7]]은
  `C-103-Error`에서 Android는 다시 시도·직접 편집, iOS는 **편집 없이 사용**·직접
  편집으로 갈랐다([[topping-placement-pipeline]]). 이 문서는 에러 화면을 없애고
  양쪽을 `C-104`로 보낸다. **"편집 없이 사용"이 같이 사라진다.** 원본이 든 근거
  ("두 선택지가 둘 다 `C-104`로 이어진다")는 v7의 iOS 선택지("편집 없이 사용 →
  `C-106`")와도 맞지 않는다.
- **자동 누끼 성공 시 목적지가 바뀐다.** v7은 성공하면 `C-105` 테두리 편집으로
  직행했다. 이 문서는 **대상 영역 선택 페이지(`C-104`로 읽힌다)를 항상 거친다.**
- **토핑 편집 진입이 하나로 줄었다.** v7의 `C-304`(배경 탭 ↔ 토핑 탭)가 배경
  변경 전용이 되고, 토핑 편집은 [[src-C-202-토핑-편집자-확인-규칙-v0.1]]이 처음
  밝힌 **본인 토핑 탭** 하나만 남는다.
- **`C-105`·`C-106`이 다시 합쳐졌다.** 테두리(`C-105`)가 배치(`C-106`)의
  패널이 됐다. 이 문서는 아직 배치 화면을 `C-106`이라 부르지만, 사흘 뒤
  [[src-사진-편집-플로우-v0.1]]은 같은 화면을 **`C-105-Arrange`**로 부른다
  ([[screen-id-scheme]]).
