# 무한 파르페 정책 v0.4 (G-001)

## 요약

`G-001`(그룹 목록 — 무한 파르페) 정책서의 `v0.4`다. 날짜 **2026-09-20**, 노션
최종 편집 `DSN-B`. 적용 화면은 `G-001` / `G-001-Empty` / `G-001-Error`다.

**문서명이 "정책 설계"에서 "정책"으로 바뀌었으나 같은 계열이다.** 원본 머리말이
이전 버전을 **"G-001 무한 파르페 정책 설계 (v0.1~v0.3)"**라 적고, 개정이력이 그
셋을 이어 받는다. 그래서 [[src-G-001-무한파르페-정책설계-v0.3]]을 대체한다.

| 버전 | 날짜 | 내용 |
|---|---|---|
| v0.1 | 2026-06-13 | 초안(2-1-2-1 기준) |
| v0.2~v0.3 | **2026-07-24** | 최종 확정본 — 지그재그, 좌표·갭, 크림, 온보딩 툴팁, 80px 말줄임 |
| **v0.4** | 2026-09-20 | 레거시 보관함에서 기획문서 쪽으로 이동. **기능정의서 v7(운영 v1.0.1) 반영** — 정렬 동률 규칙, `G-001-Error`, 토핑 템플릿 그래픽 고정, Timestamp 컬러 매핑, PTR 로딩. **불일치 3건 표시** |

**날짜가 없던 두 판본에 날짜가 붙었다.** [[src-G-001-무한파르페-정책설계-v0.2]]와
`v0.3`은 원본에 날짜·작성자가 없었는데, 이 개정이력이 둘을 **07-24**로 묶는다
([[open-questions]]).

**방향이 뒤집혔다.** 지금까지는 정책서가 정한 것이 기능정의서로 넘어가지 않는 게
문제였다. 이 판본은 **기능정의서 v7을 읽고 정책서를 맞췄다** — 그리고 맞출 수
없는 셋을 **"클라이언트 확인 필요"**로 표시했다([[spec-version-history]]).

## 개요와 진입

> 그룹이 늘수록 파르페 템플릿이 아래로 무한히 길어지고, 각 그룹의 최신 대표
> 토핑이 지그재그(행당 1개, 좌/우 번갈아)로 크림 위에 쌓인다.

- 플랫폼: Android, iOS
- 진입: `A-001`, `S-001`, **`P-02`·`P-03` 푸시**([[push-notification]])
- 다음: `A-004`, `A-005`, `G-002`, `S-001`, `G-001-Error`

## 데이터와 조회

| 필드 | 노출 |
|---|---|
| 그룹 ID | 미노출 |
| 프리뷰 이미지(대표 토핑) | 고정 사이즈 |
| 그룹 이름 | 노출 |
| 최근 활동 시각 | 상대시간 |

- **1회 API 호출**로 전체 조회, 페이지네이션 없음.
- 정렬: **최근 활동순**, 밀리초까지 같으면 **그룹 생성일시 최신순.**
- 그룹 목록은 캐싱하지 않고 재진입 시 자동 재조회. **프리뷰 이미지만 지연 로딩 +
  캐싱.**

**정렬 타이브레이크가 이 계열에 들어왔다.** [[src-G-001-무한파르페-간격-정책-v0.3]]이
07-27에 더했고 정책설계 `v0.3`에는 없던 것이다 — **두 계열 사이에서 전파되지 않던
결정 하나가 v7을 거쳐 돌아왔다**([[infinite-parfait]]).

## 상태별 동작

| 상태 | 화면 |
|---|---|
| 초기 로딩 | 자체 로딩 그래픽 |
| 조회 성공 | 전체 리스트 + 스크롤 |
| 그룹 0건 | `G-001-Empty` 온보딩 툴팁(0건인 동안 상시) |
| **페이지 조회 실패** | **`G-001-Error`(프레임 4종) + 새로고침** → 재조회 |
| 특정 토핑 조회 실패 | 칩은 정상, 토핑 자리에 물음표 형태 조회 실패 그래픽 1종 |
| 토핑 안 이미지 없음(아직 아무도 안 쌓음) | **`Template01`~`06` 중 1종을 랜덤 최초 부여 후 고정.** 새로고침·재접속·다른 그룹 갱신에도 바뀌지 않음 |

**`G-001-Error`가 이 계열에 처음 들어왔다.** 프레임이 4종이라는 것까지만 있고
각각이 무엇인지는 없다.

**빈 그룹 템플릿을 이름이 아니라 에셋 번호로 적는다.** 정책설계 `v0.3`은 딸기 /
키위 / 오레오 등 **디저트 6종**을 들었고,
[[src-G-001-그룹-토핑-템플릿-정책-v0.2]]는 **별·음표·소용돌이**로 바꿨다. 이 판본은
어느 쪽 이름도 쓰지 않는다 — **디저트 목록이 정책설계 계열에서 빠졌다는 사실만
확인된다**([[open-questions]]).

**고정 값을 어디에 저장하는지는 여전히 없다.** 목록을 캐싱하지 않는데 "재접속에도
바뀌지 않는다"려면 서버가 그룹마다 부여값을 들고 있어야 한다.

## 갱신

- **Pull-to-Refresh**: 전체 교체 + 스크롤 최상단. 로딩은
  `Lottie_Loading_Dark.lottie`(44×44 / 60fps / 2초 120프레임, loop, 중앙) —
  [[src-common-공통-로딩-정책-v0.1]]의 다크 에셋이다.
- 화면 재진입 시 자동 재조회.

### 그룹 나가기

- 해당 토핑을 지우고 **빈자리 없이 뒤 토핑이 한 칸씩 당겨진다.**
- side를 `index % 2`로 다시 계산하므로 **당겨진 지점 이후 좌/우·타입·회전이
  바뀐다** — 원본이 **"정상 동작"**이라 적었다. 변형 번호도 함께 랜덤 재부여.
- 크림이 수축하고 접시가 올라온다. **반영 시점은 저장·화면 재진입**이다.

## 배치

- 지그재그, 위→아래 좌→우 반복. **`index 0` = Left 고정.** `index % 2` → 0 Left /
  1 Right.
- x: 전체 템플릿(가로 **324.3**) 기준 Left 좌측 인셋 **4** / Right 우측 인셋 **4**
  (x=160.3). 좌표 컨테이너는 크림이 아니라 템플릿 전체. Left↔Right 가로 -3.7은
  파생값.
- y(N ≥ 4): Left 268, 416, 564… / Right 354, 502, 650… — 같은 side 세로 갭 -12,
  스텝 +148.

### 정책서와 기능정의서가 어긋나는 셋

원본이 표로 나란히 적었다.

| 항목 | 정책서 `v0.3` | 기능정의서 v7 |
|---|---|---|
| N = 0 크림 | **기본 3개** + 접시 | 크림 **최소** + 접시 |
| N = 3 | 스크롤 없음, 각 토핑 y **+12**(L 280 / R 366 / L 428) | "N=3까지 스크롤·세로 성장 없음" — **+12 적용 여부 미기재** |
| 접시 ↔ 스크롤 인디케이터(스크롤 시에만) | 최소 **16** | 최소 **-16** |

N = 1·2(+12, 스크롤 없음)와 N ≥ 4(스크롤, +12 없음, 첫 토핑 y 268, 크림 1:1 성장)는
양쪽이 같다.

**§10이 셋 모두 "클라이언트 확인 필요 — 실제 운영 값으로 정책서와 기능정의서를
맞춘다"**로 끝난다. **문서끼리 판정하지 않고 구현을 기준으로 삼겠다는 선언이다** —
설계가 구현을 따라가는 방향으로 정본이 옮겨 가는 첫 서술이다.

접시 갭 부호는 이 위키가 이미 미결로 붙들고 있던 것이다
([[src-G-001-무한파르페-간격-정책-v0.3]] -16 → 정책설계 `v0.3` 16). **원본도 같은
어긋남을 찾아 표시했다**([[open-questions]]).

나머지 템플릿 고정 갭 둘은 그대로다 — 체리↔첫 토핑 **-65**, 마지막 토핑↔접시
**-48**(side 무관).

### 토핑 규격과 타입

- 토핑 = `Img` + `Grouptag-Chip`, 6타입(`Left-1~3` / `Right-1~3`). 프레임 160×160,
  `Img` 96×96(정중앙). **오버플로우 없음.**
- Chip 회전 없음, Z 항상 `Img` > Chip.
- **Chip 기준점 = 프레임 중앙 하단 / `Img` 중앙 하단.**
- 변형 번호(1/2/3)는 **목록 조회 응답 1회마다 랜덤 재부여**(그룹 ID 고정 시드
  아님). 리렌더·셀 재사용 시 재추첨 금지.

| Type | Translate X | Translate Y | Rotate | Chip Offset |
|---|---|---|---|---|
| Left-1 | 26 | 16 | 6° | -7 |
| Left-2 | 24 | 11 | 12° | -5 |
| Left-3 | 25 | 16 | -8° | -8 |
| Right-1 | 26 | 16 | -6° | -6 |
| Right-2 | 22 | 8 | -16° | -3 |
| Right-3 | 25 | 16 | -8° | -8 |

**Chip 기준점이 정책서 계열에 돌아왔다.** 정책설계 `v0.2`에서 항목째 빠져 `v0.3`까지
없었고 v7이 먼저 적었던 값이다. `Left-3`와 `Right-3`가 같은 값인 것은 그대로다.

## 요소

- **체리** — MVP 이후 기능 가능성, `TBD`.
- **토핑** — 이미지 뷰어 없음. 탭하면 그 그룹의 `C-001`로 간다.
- **라벨(`Grouptag-Chip`)** — 한 줄 고정, 토핑 우측 하단. 그룹명 80px 초과 시
  `…`, 시간 텍스트는 항상 전체 노출, 칩 폭은 내용 기준.
- **크림** — 고정 이미지·비율 고정·중앙 정렬(화면 폭 비추종).
- **접시** — 기능 없음.
- Z-index: 토핑/라벨 4 > 체리 3 > 크림 2 > 접시 1(토핑 안은 `Img` > Chip).

### Timestamp 컬러를 본문에 직접 실었다

**Timestamp 텍스트 컬러 = 그 그룹에 마지막으로 변화를 가한(토핑 추가·토핑
편집·배경 추가·배경 변경) 유저의 `Nametag-Chip` 타입에 강제 매핑.** 그룹 단위
규칙이고 개별 멤버 컬러 규칙(`S-101`)과는 별개라고 적는다.

| 칩 컬러(타입) | Timestamp |
|---|---|
| 연핑크(1,2) | Cherry-100 |
| 진핑크(3,4) | Cherry-200 |
| 체리(5,6) | Cherry-300 |
| 그레이(7,8) | White |
| 멜론(9,10) | Melon |
| 푸딩(11,12) | Pudding |

[[src-S-101-프로필-이미지-및-그룹칩-내-타임스탬프-컬러-규칙-v0.1]]의 표와 같다.
**앞 판본들이 옛 문서명("프로필 이미지 및 토스트 닉네임 텍스트 컬러 규칙")을
가리키던 참조 빗나감이 끝났다** — 가리키는 대신 값을 옮겨 적었다.

상대시간(`방금 전` / `N분 전` / `N시간 전` / `N일 전` / 7일 이상 `오래 전`)과 NEW
해제 조건(`C-001` 진입 시에만)은 그대로다.

## G-001-Empty 온보딩 툴팁

- `+ 그룹 추가하기` 버튼 아래, 꼬리 위 방향.
- **가입 그룹 0건 자체가 조건** — 최초 1회 플래그 없음.
- 툴팁 밖 탭으로 닫힘, X 없음, 닫힘 상태 저장 안 함 → 0건이면 재진입 시 다시 뜬다.
- 딤·드롭섀도 없음.

[[src-G-001-Empty-툴팁-노출-조건-정책-v0.1]]의 노출·닫기 조건을 **그대로 담고
위치·X 없음·딤 없음을 더했다.** 다만 이 판본이 그 문서를 대체한다고 적지는
않았다. **문구는 여기에도 없다**([[open-questions]]).

## 다른 `G-001` 문서들과의 관계

**대체를 선언한 것은 정책설계 계열 하나뿐이다.** 같은 화면을 다루는 다른 계열은
내용이 겹치거나 흡수됐어도 선언이 없어 그대로 둔다([[purpose]]).

| 문서 | 이 판본과의 관계 |
|---|---|
| [[src-G-001-무한파르페-간격-정책-v0.3]] | 좌표·인셋·타이브레이크를 거의 다 담는다. **접시 갭만 이 판본이 16, 간격 `v0.3`이 -16**으로 갈린다 |
| [[src-G-001-토핑-정책-v0.1]] | 180×180 / 3타입은 여기서도 160×160 / 6타입으로 적힌다. 폐기 선언은 여전히 없다 |
| [[src-G-001-그룹-토핑-템플릿-정책-v0.2]] | 랜덤 부여·고정만 겹친다. 6종의 정체(별·음표·소용돌이)는 이 판본에 없다 |
| [[src-G-001-Empty-툴팁-노출-조건-정책-v0.1]] | 내용을 전부 담는다. 선언 없음 |
