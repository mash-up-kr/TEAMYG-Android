# [BL_1] 텍스트 업로드 기능 추가 정책 v0.1 (C-106)

## 요약

**캔버스에 텍스트를 올리고, 고치고, 지우는 기능**을 정한다. 카드가 셋이다 —
"텍스트 입력 / 규칙"과 "키보드 노출 / 규칙"이 **26.10.09**(`DSN-B`), "텍스트 타입 -
컬러 / 매핑 규칙"이 **26.10.13**(`DSN-B`, `DSN-A`). 모두 `v0.1`이고 개정이력 행은
없다. Figma 캔버스 페이지의 "UX_1 반영 후 플로우" 아래 섹션에서 옮겼다.

**텍스트 회의 세 번의 결정을 정책으로 옮긴 문서다** —
[[src-회의록-2026-10-04-텍스트-기능-정의-회의]],
[[src-회의록-2026-10-06-회의]], [[src-회의록-2026-10-10-디자인-회의]]. 정책·디자인
확정일은 10/15였고([[src-회의록-2026-10-13-회의]]) 배포 후 피드백은
[[src-회의록-2026-11-03-회의]]에 있다.

**캔버스에 올라가는 것이 사진 하나에서 둘이 된 첫 정책서다.** 텍스트는 누끼를
거치지 않는다([[topping-placement-pipeline]]).

원본에는 정책 본문 외에 **"iOS · Android 개발 확인 필요"** 목록이 길게 붙어 있다.
작성자가 "여기 클로드가 적어줬어요 개발에서 정해서 댓글 주시면 수정하겟슴"이라
적었다 — 결정이 아니라 질문 목록이다.

## 진입

- **업로드**: `C-001` 하단 1Depth `[추가 +]` → 2Depth 3단 `[카메라로 촬영 /
  갤러리에서 선택 / 텍스트 입력]` → `[텍스트 입력]` → **`C-106`**. 2Depth가
  펼쳐지면 캔버스는 딤, **`[배경 변경]`은 비활성**, 메뉴 밖을 탭하면 닫힌다.
- **수정**: `C-001`에서 내 텍스트 탭 → 배치 상태(포커스 + 모서리 `X`) → 한 번 더
  탭 → `C-106` 편집.
- 남의 텍스트 탭 → 토스트 `XX님이 N분 전에 쌓았어요`만, 진입하지 않는다.

`Canvas-Menu`가 2단에서 3단이 된다는 10-04 결정이 여기서 화면으로 내려왔다. 하단
메뉴가 `[추가 +]`와 `[배경 변경]` 둘이라는 것도 읽힌다 —
[[src-토핑-쌓기-플로우-개선-2-변경-사항-2026-09-22]]이 캔버스 편집을 배경 변경으로
바꾼 결과다([[canvas]]).

## `C-106` 화면

- 헤더: `배치` + `✓`(완료, 키보드 내림). **키보드가 올라와 있는 동안 `X`는
  숨긴다.**
- **Text-Area**: 캔버스 상단 ~ 툴바 위. 높이 = 캔버스 높이 − 키보드 높이 − 툴바
  52px(디자인 기준 335×347). 새 텍스트는 그 가운데에 생긴다. **레이아웃용이라
  터치를 받지 않는다.**
- 키보드 바로 위 플로팅 툴바 한 줄: `[색] [타입] [정렬] · 글자 수`.
- 남의 사진·텍스트는 딤 아래에 보인다.

## 스타일

| 항목 | 규칙 |
|---|---|
| 폰트 | 한·영·숫자 **SUIT Regular**, 일본어 **Line Seed JP Regular**, 중국어 **Line Seed TW Regular**. 행간 140%. 굵기·기울임·그림자·투명도 없음 |
| 글자 크기 | **최대 24px, 자동.** 텍스트가 Text-Area 높이를 넘으면 다 들어갈 때까지 연속으로 줄인다. **하한 없음.** 줄이 줄면 24px까지 다시 키운다. 핀치 배율과 별개 |
| 타입 | `기본` → `배경`(네모배경) → `배경+테두리`. `[타입]`을 누를 때마다 순환. 글자 자체 테두리는 없다 |
| 색 | `[색]` → 컬러칩 팝오버. 색 세트는 별도 정의. 매핑표의 색은 White·Black·Pink·Orange·Yellow·Green·Blue·Violet 여덟 |
| 정렬 | 가운데 → 왼쪽 → 오른쪽 순환 |
| 기본값 | 기본 타입, 가운데 정렬 |

팝오버는 같은 버튼으로 닫히고, 열려 있어도 타이핑할 수 있다. **타입이나 정렬을
눌러도 색 팝오버는 닫히지 않는다** — 색을 고르며 타입별 모습을 바로 비교하라는
뜻이다.

### 네모배경

- 가로 최대 335px은 **글자만의** 기준이다.
- 여백은 자동이고 글자 크기에 비례한다 — **좌우 × 1/3, 상하 × 1/6**(24px →
  8px / 4px). 모서리 반경 0.
- `배경+테두리`의 테두리는 **글자 크기 × 1/24**(24px → 1px), 박스 바깥쪽.
- 핀치 배율은 박스 전체에 걸린다. 사용자가 여백·테두리를 직접 조절하는 기능은
  없다. **캔버스 밖으로 넘친 부분은 잘린다**(사진과 같다).

## 입력

- 시스템 키보드. **엔터는 줄바꿈이지 완료가 아니다.**
- **100자**(띄어쓰기·줄바꿈·이모지 각 1자). 도달하면 추가 입력을 무시하고 카운터가
  빨개진다. 붙여넣기로 넘치면 앞 100자만 남긴다.
- **줄 수나 높이로는 막지 않는다** — 글자 크기가 줄어 대응한다.
- 지원 언어: 한·영·일·중·숫자·이모지.
- **비속어 필터, 신고, 접근성 기준은 이번 범위가 아니다.**

## 키보드와 터치

| 키보드 ↑에서 | 결과 |
|---|---|
| 텍스트 탭 | 커서 이동 |
| 길게 누르기 | 시스템 선택·복사/붙여넣기 |
| 끌기 | 일정 거리 이상이면 키보드 ↓ + 그대로 이어서 이동 |
| 두 손가락 핀치 | 키보드 ↓ + 크기·회전 이어짐 → `C-106-Arrange` |
| 박스 밖 탭 | **열린 것부터 하나씩 닫힘**(팝오버 → 키보드). 닫는 탭은 닫기만 |

키보드를 내리는 법은 `✓`, 박스 밖 탭, 끌기, 핀치, Android 뒤로가기다. 어느 쪽이든
편집 내용은 남는다. 키보드가 내려간 배치 상태(`C-106-Arrange`)에서는 포커스 +
모서리 `X`, 한 손가락 이동, 두 손가락 크기·회전이고 다시 탭하면 키보드가 올라온다.

**공백·줄바꿈만 남으면 빈 내용이다.** 새 텍스트를 빈 채로 내리면 `C-106`이 닫히고
`C-001`로 간다(팝업 없음). 빈 내용이면 끌기·핀치가 안 된다.

## 저장·삭제·권한

- 키보드를 내려도 화면에만 반영된다. **저장은 `[캔버스에 쌓기]`에서만.** 삭제(모서리
  `X`, 빈 내용)도 그때 반영된다.
- 헤더 `X` → 변경이 있으면 확인 팝업 1회 → 전부 취소(지운 텍스트도 복구). 원본
  화면 주석은 이 팝업을 **`Modal-Quit-Add-Text`**라 부른다.
- **텍스트 객체로 저장한다**(이미지로 합성하지 않음).
- 작성·편집 중에 **03:00 마감이 오면 사진 업로드 중 마감과 똑같이 처리해 업로드
  안 됨.**
- 수정·삭제는 작성자 본인만. **마지막에 쌓은 게 맨 위.** 남의 텍스트·사진 위에도
  쌓을 수 있고 개수 제한이 없다.

## 개발 확인 목록에서 뽑은 것

질문 목록이라 결정은 아니지만, 정책이 무엇을 미뤘는지 드러난다.

- **기기마다 키보드 높이가 달라 같은 텍스트도 자동 크기가 다를 수 있다.** 제안:
  **작성자 기기에서 정한 크기·배율을 저장하고 보는 쪽은 다시 계산하지 않는다.**
  작성자가 다른 기기에서 고치면 그 기기 기준으로 다시 저장한다.
- 저장 필드 제안: 내용, 타입, 색 ID, 정렬, 자동 크기, 핀치 배율, 회전, 위치(원래
  자리 기준), 레이어 순서, 작성자.
- **편집 중에 실시간·10초 폴링으로 남의 변경이 들어오면 어떻게 할지**가 열려 있다.
  "사진 편집과 같게 갈 수 있는지"라 적는데, 사진 쪽 규칙도 위키에 없다
  ([[canvas]]).
- 글자 수는 **화면에 보이는 글자 단위**로 센다 — 조합 이모지도 1자.
- 대안까지 적혔다: 키보드 ↑ 상태에서 끌기·핀치 구분이 어렵다면 **막고 `✓`·박스 밖
  탭으로만 내리기.**

## 원본 안의 어긋남

> ⚠️ [2026-11-13] [[src-회의록-2026-10-06-회의]] 와 상충 — 회의는 **업로드 후 수정
> 불가**로 정했고 이 문서의 흐름도 `U-6`도 "텍스트 객체로 저장 (이후 수정 불가)"인데,
> 본문 §8은 **"올린 뒤에도 수정 가능"**, §1과 수정 흐름(`E-1`~`E-5`)은 **내용·스타일
> 수정**까지 적는다 → [[open-questions]]

- **수정 가능/불가가 한 문서 안에서 갈린다.** 본문 §1 "수정: 내 텍스트 탭 → … →
  `C-106` 편집", §8 "올린 뒤에도 수정 가능", 수정 흐름 `E-5` "위치·크기·회전·
  **내용·스타일** 갱신", 화면 프레임 `C-106-Arrange(수정 중일 시)` — 이쪽은 수정이
  된다. 흐름도 `U-6` "이후 수정 불가" — 이쪽은 안 된다. 10-06 회의는 수정 불가였고
  10-10 디자인 회의는 "수정 버튼 없음"을 와이어프레임 반영 항목으로 체크했다.
  **문서 날짜(10-09)가 회의 뒤인데도 본문이 수정 가능으로 적힌다.** 어느 쪽이
  배포됐는지는 이 위키 소스로 판정되지 않는다.
- **100자는 낡았다.** [[src-회의록-2026-11-03-회의]]가 **500자**로 늘렸고
  [[src-회의록-2026-11-10-회의]]가 완료로 올렸다. 이 문서는 고쳐지지 않았다.
- **중국어 자간이 "-1% (24px 기준 -0.264px)"다.** -0.264px는 -1.1%의 값이다. 다른
  두 폰트는 -1.1%다.
- 흐름도의 타입 표기가 **`01→04→06`**이다. 본문의 세 타입과 대응은 짐작되지만
  번호 체계의 설명은 없다.

## 기존 위키와의 관계

- **`C-106`의 뜻이 바뀌었다.** v7의 `C-106`은 사진의 "캔버스에 배치"였다. 이
  문서에서 `C-106`은 **텍스트 입력 화면**이고, 사진 배치는
  [[src-사진-편집-플로우-v0.1]]부터 `C-105-Arrange`로 불린다. 번호 재사용 목록에
  하나가 더 붙는다([[screen-id-scheme]]).
- **일본어·중국어 폰트가 정해졌다.** [[src-회의록-2026-10-10-디자인-회의]]는 후보로
  LINE Seed JP 한 줄만 두고 일·중 지원 여부, 중국어 범위, 번들 vs 폴백을 모두 비워
  뒀다. 이 문서는 **Line Seed JP / TW를 앱에 포함**한다고 적는다(개발 확인
  목록 "SUIT 영문/국문, Line Seed JP/TW를 앱에 포함"). **번들 쪽이다.** TW라
  번체로 읽히나 간체 지원 여부는 없다.
- **마감 시점의 작성 중 객체가 처음 규칙을 얻었다** — "업로드 안 됨". 다만 기준으로
  든 "사진 업로드 중 마감" 규칙이 위키 어디에도 없다([[canvas]],
  [[open-questions]]).
- 범위 밖으로 민 것(비속어·신고·접근성)은 회의의 결정과 같다
  ([[mvp-scope-limits]]).
