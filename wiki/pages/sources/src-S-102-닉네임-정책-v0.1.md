# 닉네임 정책 v0.1 (S-102)

## 요약

닉네임 입력 유효성 규칙을 정한다. 2026년 7월 2일자 `v0.1`이고 작성자는 `DSN-B`다.

[[src-S-002-앱닉네임-정책-v0.1]]이 참조하던 문서이고, **본문이 그 문서와 글자
하나까지 같다.** 규칙은 [[account]]에 정리돼 있다 — 여기서 되풀이하지 않는다.

**[[src-S-102-닉네임-정책-v0.2]](26.07.25)가 대체한다.** 그 판본도 짝과 본문이
완전히 같아 **"본문 동일, 헤더만 다름"이 두 판본 연속으로 반복됐다.**

## 두 문서가 같은 규칙을 두 번 등록한다

`S-002` 문서와 이 문서는 **헤더만 다르다.**

| | `S-002` 문서 | 이 문서 |
|---|---|---|
| 적용 화면 | `S-002` (계정 정보) — 앱 닉네임 | `S-102` (닉네임 수정) **등 닉네임 입력 지점** |
| 텍스트 | 앱 닉네임 입력 유효성 정책 (계정 레벨) | 닉네임 입력 유효성 정책 (앱 / 그룹 내) |
| §1 생성 규칙 | | **동일** |
| §2 입력 예시 | | **동일** |
| §3 적용 범위 | 그룹 내 닉네임 + 앱 닉네임 | **동일** |

날짜(07-02), 작성자(`DSN-B`), 버전(`v0.1`)도 같다.

**§3이 결정적이다.** 두 문서 모두 적용 범위로 **그룹 내 닉네임과 앱 닉네임 둘
다**를 든다. 서로의 범위를 완전히 포함하므로 어느 쪽도 다른 쪽을 대체하거나
보완하지 않는다 — **순수한 중복이다.**

그래서 둘 다 `status: current`로 둔다. 판본 관계가 아니다.

## 그룹명과의 관계를 원본이 못박는다

연관 문서 항목이 적는다 — `A-005` 그룹명 정책과 **"규칙 구조 동일, 글자수 상한만
다름 — 그룹명 10자 / 닉네임 15자"**.

[[src-S-002-앱닉네임-정책-v0.1]]을 ingest할 때 예시 문자열의 길이를 근거로
[[src-A-005-그룹명-정책-v0.1]]이 닉네임 정책서의 사본이라고 판정했다. **원본이
그 관계를 직접 확인해준다.**

## 닉네임 입력 지점은 여럿이다

적용 화면이 "`S-102` 등 **닉네임 입력 지점**"으로 열려 있다. 실제로 닉네임을
받는 자리는 넷이다.

| 화면 | 무엇 | 비고 |
|---|---|---|
| `A-002` | 계정 생성 시 랜덤 부여 | **10자 이내** — 이 규칙의 15자와 다르다 |
| `A-004`·`A-005` | 그룹 가입 시 그룹 내 닉네임 | v4가 넣었고 v5에서 표기가 사라졌다 |
| `S-002` | 앱 닉네임 수정 | |
| `S-102` | 그룹 내 닉네임 수정 | |

이 문서도 [[src-S-002-앱닉네임-정책-v0.1]]과 마찬가지로 **앱 닉네임과 그룹 내
닉네임이 서로 어떤 관계인지는 말하지 않는다.** 규칙이 같다는 것까지다.

## 미결

- 앱 닉네임과 그룹 내 닉네임이 독립인지, 한쪽이 다른 쪽의 기본값인지.
- 초기 랜덤 부여 10자와 수정 상한 15자가 왜 다른지.
- 닉네임 중복 허용 여부와 금칙어. 이 문서도 다루지 않는다.
- **같은 규칙이 두 문서로 존재한다.** 한쪽만 고쳐질 위험이 있다.
