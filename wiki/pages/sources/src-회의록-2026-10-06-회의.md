# 회의록 2026-10-06 전체회의

## 요약

2026년 10월 6일(화) 22:30 Discord 전체회의, 약 1시간 5분이다. 안건은 일곱이고
제품에 닿는 것은 넷이다 — 텍스트 기능의 수정 가능 여부와 저장 방식, 팀 활동
지속 기준, **첫 업로드 부재 이슈(10/5 업로드 0건)**, 그리고 CSAE 대응을 위한 수동
삭제 가능 여부.

원본은 정리본과 "회의록 원본(댓글 보존용)" 하위 페이지 두 벌을 담고 있다.
정리본이 더 자세하고 결론이 같다. 아래는 정리본을 따랐다.

**이 위키에서 처음으로 실사용 수치와 사용자가 왜 안 쓰는지에 대한 서술이
나온다.**

## 결정 사항

### 텍스트 기능 — 수정 불가, 텍스트 개체 저장, 폰트 고정

[[src-회의록-2026-10-04-텍스트-기능-정의-회의]]의 정의를 재확인하고 남은 둘을
닫았다.

| 논의 | 결정 | 원본이 든 근거 |
|---|---|---|
| 업로드 후 수정 | **수정 불가** | 사진도 수정이 안 되는데 글자만 되면 일관성이 깨진다 / 지우고 다시 올리면 된다 / 수정 버튼으로 depth가 늘어난다 / 「수정됨」 표시 자리가 없고 예쁘지 않다 |
| 저장 방식 | **텍스트 개체 유지** (이미지 합성 안 함) | 이미지 저장 비용 / 이미지는 키우면 깨진다. 사진 토핑도 값만 내려받아 뷰로 그리므로 같게 처리 가능 |
| 폰트 | **시스템 폰트 미사용, 1종 고정.** 후보 SUIT | Android/iOS 시스템 폰트가 달라 같은 글자가 다르게 보인다 |

- 신고·필터링 불필요의 근거: **"사진도 신고 기능 없음"**. 접근성 불필요의 근거:
  **"친구끼리 놀 때 쓰는 용도"**.
- SUIT는 일본어·한자 글리프가 없다. **"일단 찾아보고 안 되면 제외"** — 일·중
  지원이 공수를 키우면 뺀다.

### 팀 활동 지속 기준

- 11/30까지 목표를 못 이루면 팀 활동을 접는다. 기준은 **"활동 종료 전 마지막
  2주 간의 평균 DAU (우리 계정 제외) 50"**.
- 다운로드 수는 "바이럴 하루만 터져도 오르는 수치라 운영 가치의 지표로는
  부적합"해 버렸다.
- 회의 시점 수치: Android 전 버전 다운로드 83, iOS 163. **10/5 DAU는 iOS 18 +
  Android 5 = 23.**

### 첫 업로드 부재 — 문제 정의

원본이 상자로 강조했다: **"매일 빈 캔버스로 시작 → 첫 타자만 부담을 짐 → 아무도
안 올림. 목표: 올릴 게 없어도 올리게 만들기. 푸시는 안 씀"**.

왜 안 올렸나(원본 그대로):

- 올릴 사진이 없음 — **3시~3시에 찍은 사진만 가능**, 출근 사진 정도가 전부
- 첫 타자가 민망함. 예쁜 걸 올려야 할 것 같은데 나한테 예쁜 게 없음
- 그룹과 무드가 안 맞으면 더 올리기 어려움
- 들어올 계기가 없음. **푸시는 많으면 그냥 끔**

### 첫 업로드 부재 — 제안과 판정

| 안 | 결정 | 이유 |
|---|---|---|
| A. 단톡 공유 (텍스트 올린 뒤 카톡으로 캔버스 링크) | **기각** (표에서는 보류) | 제안자가 B/C 우선으로 접음 |
| B. `C-001` Empty state 개편 — 더미 사진(예쁜 것 + 일부러 별로인 것)으로 「뭐든 올려도 된다」를 보여줌, 쌓기 버튼 위계 상향 | **추진** | 공수 무난. 개수·랜덤 여부 미정 |
| C. 홈 화면 위젯 — 사진은 모자이크/블러/실루엣, 닉네임 + 시간대만 | **추진, iOS만** | Android는 개발 난이도로 제외. 1:1, 그룹 통틀어 최근 토핑 1개(그룹명·닉네임·타임스탬프·토핑). 그룹별 위젯은 제약으로 어려움 |
| D. N개 올라오기 전까지 블라인드 | **기각** | 꾸미려는 사용자에게 당혹스러운 업데이트 |
| 찌르기 | 보류 | 푸시 기반이라 방침과 충돌 |
| 시간 기반 알림 (듀오링고식) | **기각** | 푸시 지양 |
| 연속 일수 스트릭 | 보류 | 첫 타자 문제엔 효과 없음 + 구조 대개편 |
| 오늘의 주제 | 보류 | 효과 약함 |
| 무드별 그룹 나눠 쓰기 | 보류 | UX_1로 잡은 직관성이 다시 깨질 수 있음 |
| 공개 피드 (인스타 스토리처럼 남의 것도 봄) | 참고 기록만 | 무드 불일치 해소용이나 공수가 위젯 이상 |

**3시~3시 사진 규칙:** "지킬 가치가 있는 정체성인가, 바꿔도 되는 장치인가"를
물었다. 「왜 3시까지냐」에 답하기 어렵고 타협한 느낌이 강하다는 의견에 따라
**"갤러리 시간 제한을 일단 없애보고, 써보면서 판단 (안 되면 되돌림)"**으로
정했다. 그룹 내 무드 불일치는 위 건 해결 뒤로 미뤘다.

우선순위: 갤러리 시간 범위 조정 4위, `C-001` Empty 더미 배경 9위, 위젯 PoC 10위.

### CSAE 대응 — 수동 삭제

플레이스토어 카테고리를 **소셜**로 바꾸면서 아동 안전 표준(CSAE) 페이지가
필요해졌다. 어드민 화면 없이 DB/스토리지 직접 처리로 충분하다고 봤다.

| 질문 | 답 |
|---|---|
| 특정 사진 직접 삭제 | 가능 |
| 병합 캔버스·갤러리 저장본 반영 | 이전 캔버스는 조회 때마다 서버에서 가져오므로 반영됨. **이미 갤러리에 저장된 것은 불가** |
| 계정 정지·삭제 | 임의로 가능 |
| 정지 계정 재가입 차단 | **현재 불가.** 정지 컬럼 추가 시 가능(추가 개발) |
| 신고 접수 후 삭제까지 | **24시간**으로 정책 기재 |
| 삭제 담당 | 서버(`SPR-A`) |

## 범위·정책에 미친 영향

- **03시 경계가 갤러리에서 풀린다.** [[canvas]]·[[topping-placement-pipeline]]은
  `C-102`(그리고 그것을 재사용하는 `C-303`)에 "당일 03시~익일 03시" 시간 창이
  걸린다고 적는다. 이 회의가 그 창을 **실험적으로 해제**하기로 했고,
  [[src-회의록-2026-10-13-회의]]에서 양 플랫폼 반영이 확인됐다. 캔버스 마감·생성
  경계 03:00 자체는 건드리지 않았다.
- **푸시를 늘리지 않는다는 방침이 명시됐다.** "푸시는 안 씀", "푸시 지양"이 세
  안을 기각·보류한 근거다([[push-notification]]).
- **사용자 서술이 처음 나왔다.** 팀이 그리는 사용자는 **"친구끼리 놀 때"** 쓰는
  사람이고, 불편은 **첫 타자의 부담과 올릴 사진이 없음**이다. 이 위키의
  "누구를 위한 것인가"([[purpose]])에 대한 첫 원본 서술이다 — 다만 조사 결과가
  아니라 팀의 진단이다.
- **신고 기능이 없다는 서술이 `S-104`와 겹친다.** [[group]]은 v7에서 그룹
  신고(`S-104`)가 동작을 얻었다고 적는다. 이 회의의 "사진도 신고 기능 없음"은
  콘텐츠(토핑) 단위 신고를 말하는 것으로 읽힌다. 한편 CSAE 대응은 **신고 접수 후
  24시간 내 수동 삭제**를 약속한다 — 신고가 들어오는 창구가 무엇인지는 적히지
  않았다.
- 범위 밖으로 민 것: 홈 위젯의 Android, 공개 피드, 단톡 공유, 블라인드, 시간 기반
  알림, 텍스트 수정, 이미지 합성 저장, 시스템 폰트([[mvp-scope-limits]]).
