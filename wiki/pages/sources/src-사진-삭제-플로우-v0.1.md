# 사진 삭제 플로우 v0.1 (C-105-Arrange)

## 요약

**편집 화면에서 본인 사진을 지우는 흐름**을 정한다. 카드 일자 **26.10.06**, `v0.1`
초안, 작성자 `DSN-B`다. 카드 대상은 "`C-001`에서 내 토핑 탭 / `C-105-Arrange`에서
X아이콘 터치"다. Figma 캔버스 페이지에서 옮겼다.

[[src-사진-편집-플로우-v0.1]](09-25)의 화면 위에서 동작하며 그 문서의 규칙(패널이
열리면 무엇을 탭하든 패널만 닫힘, 헤더 `X` 확인 팝업)을 그대로 쓴다.

## 삭제는 확정이 아니라 변경 사항 하나다

- **삭제는 즉시 서버에 반영되지 않는다.** 포커스된 사진의 모서리 `X`를 누르면
  캔버스에서 바로 사라지지만, **`[캔버스에 쌓기]`를 눌러야** 다른 수정과 함께
  일괄 반영된다.
- **삭제는 `C-105-Arrange`(패널 닫힘)에서만 된다.** 패널이 열려 있으면 `X`를
  눌러도 패널만 닫힌다.
- 삭제, 이동, 확대, 회전, 테두리 변경은 **모두 같은 변경 사항**이다. 하나라도
  있으면 헤더 `X`에 확인 팝업이 뜬다.

## 삭제 직후

| 무엇 | 상태 |
|---|---|
| 포커스 | 없음 |
| 본인의 나머지 사진 | 활성 유지 |
| 남의 사진 | 딤 유지 |
| `테두리 설정` 바 | **비활성** — 적용 대상이 없다 |
| 본인의 다른 사진 탭 | 포커스 이동, 바 다시 활성 |

## 끝내는 법

| 동작 | 결과 |
|---|---|
| `[캔버스에 쌓기]` | 삭제한 사진이 서버에서 지워지고 반영된 `C-001`로 |
| 헤더 `X` | 변경이 있으므로 **`Modal-Quit-Edit`** |
| `Modal-Quit-Edit` [그만두기] | **삭제를 포함한 모든 변경 폐기**, 지운 사진이 남은 `C-001`로 |
| `Modal-Quit-Edit` [계속 편집] | 팝업만 닫힘 |

### 케이스

- **A. 들어오자마자 삭제** — `C-001`에서 사진 A 탭 → A 포커스 → `X` → A 제거 →
  `[캔버스에 쌓기]` → A가 지워진 `C-001`. 대신 헤더 `X` → [그만두기]면 A가 남는다.
- **B. 다른 사진을 고치다 또 다른 사진 삭제** — A를 이동·확대·회전하거나 테두리를
  바꾼다(로컬 유지). 패널이 열려 있으면 먼저 닫는다. B를 탭하면 포커스가 B로
  옮겨 가고 A의 변경은 남는다. B를 지우고 `[캔버스에 쌓기]`를 누르면 **A의 변경과
  B의 삭제가 한 번에 저장된다.** [그만두기]면 둘 다 폐기된다.

**한 번의 편집 세션이 여러 사진에 걸친다.** 포커스를 옮겨 가며 고친 것과 지운
것이 `[캔버스에 쌓기]` 하나로 묶인다.

## 원본 안의 어긋남

- 절 번호가 1, 3, 4, 5, 6이다 — **2가 없다.** "3-1. 만약 3에서"는 케이스 A의
  3번째 단계를 가리킨다.
- `[캔버스에 쌓기]`를 두 군데서 **"헤더 [캔버스에서 쌓기]"**라 적는다. 다른 모든
  곳에서 이 CTA는 하단 버튼이다.
- "커스된 사진"은 "포커스된 사진"의 오타로 읽는다.

## 기존 위키와의 관계

- **v7의 삭제는 `C-305` 토핑 편집 안에 있었다**([[topping-placement-pipeline]]).
  이 문서는 그 자리를 `C-105-Arrange`로 옮긴다 — [[src-사진-편집-플로우-v0.1]]과
  같은 이동이다.
- **확정 전 삭제가 다른 그룹원에게 보이는지**는 적히지 않았다. "즉시 서버 반영 X"라
  보이지 않는 쪽으로 읽힌다. 편집 중에 다른 사람의 변경이 폴링으로 들어오면
  어떻게 되는지도 없다([[canvas]]).
- **전부 지웠을 때 `G-001`의 빈 토핑 템플릿이 돌아오는지**는 여기에도 없다
  ([[infinite-parfait]], [[open-questions]]).
