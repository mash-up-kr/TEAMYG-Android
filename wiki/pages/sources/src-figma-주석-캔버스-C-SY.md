# Figma 주석 — 캔버스 (C / SY)

## 요약

Figma `[디자인] 파르페 v0.1`의 `ㄴ 캔버스 (C / SY)` 페이지 스냅숏이다.
2026-11-13 수집. 이 위키가 가진 Figma 주석 중 가장 크다.

**페이지가 두 흐름으로 나뉘어 있다** — `~UX_1 반영 전 플로우`와 `UX_1 반영 후
플로우`. UX_1은 10/15에 배포된 토핑 추가·편집 흐름 개편이다
([[src-회의록-2026-09-29-회의]], [[src-회의록-2026-10-20-회의]]). 반영 후 흐름
아래에 후속 백로그 섹션이 달려 있다.

| 섹션 | 무엇 | 따로 분리된 문서 |
|---|---|---|
| `[260922] 토핑 쌓기 플로우 개선_2` | UX_1 설계 중간본 | [[src-토핑-쌓기-플로우-개선-2-변경-사항-2026-09-22]] |
| `[BL_1] 텍스트 업로드` | 캔버스 텍스트 추가 (카드 6장, 10-13) | [[src-BL_1-텍스트-업로드-기능-추가-정책-v0.1]] |
| `BL_06` | 카메라 줌 | 없음 |
| `가이드라인 추가 버전 (261105)` | 배치 중 정렬 가이드 | [[src-토핑-중앙-정렬-및-각도-가이드-스냅-v0.1]] |
| `[BL_30]` | 인스타그램 스토리 공유 | 없음 |
| `[UX_1] 해당 화면 제거` | `C-103-Error` 제거 | — |

**반영 전 흐름이 지워지지 않고 남아 있다.** 아래 비교는 반영 후 흐름과 백로그
섹션을 현재 상태로 읽는다.

## 화면 ID — v7과 비교

### 같은 ID가 다른 화면을 가리킨다

**UX_1이 `C-104`~`C-106`과 `C-301`의 뜻을 바꿨다.** 이 위키가 경고해 온 ID 재사용
([[screen-id-scheme]])이 다시 일어났다.

| ID | v7 (09-21) | Figma 반영 후 (카드·주석으로 읽은 것) |
|---|---|---|
| `C-104` | 수동 누끼 편집 | **대상 영역 선택** — "누끼 결과 노출 및 수동 편집" |
| `C-105` | 테두리 편집 | **배치** — "테두리 설정 및 배치". `C-105-Arrange`와 같은 화면의 두 상태 |
| `C-106` | 캔버스에 배치 (토핑 쌓기) | **캔버스 텍스트 추가** (`BL_1`). `C-106-Arrange` 동반 |
| `C-301` | **삭제** | **배경 변경** — 독립 페이지로 돌아왔다 |

- **`C-106`이 사진 배치에서 텍스트 추가로 넘어갔다.** 09-22 설계 중간본까지는
  "배치페이지인 C-106"이었고, 10-13 `BL_1` 카드부터 텍스트다. v7의 `P-01` 발송
  시점 "`C-106` 배치 확정 저장"이 **어느 화면을 가리키는지 바뀐다**
  ([[push-notification]]).
- **`C-301`은 v2의 뜻으로 돌아갔다.** v2의 `C-301`이 "캔버스 배경 변경"이었고 v3~v6가
  편집 모드 진입으로 쓰다 v7이 지웠다. 근거는 [[src-figma-주석-Development-페이지]]의
  "캔버스 편집 → 배경 변경으로", "탭 일괄 폐지".

### v7에 있고 반영 후 흐름에 없는 것

`C-103-Error`, `C-103-Loading`, `C-102-Error`, `C-304`, `C-305`, `C-306`,
`Tutorial-1`~`5`. 전부 **반영 전 흐름에만** 프레임이 있다.

- **`C-103-Error`는 제거가 명시됐다** — "C-103에서 누끼 대상 감지에 실패한 경우
  기존 Error 페이지로 랜딩이 아닌, C-104로 곧바로 이동시킨 뒤 '대상 감지에
  실패했어요, 영역을 직접 선택해 주세요' Toast를 노출한다." **v7의 플랫폼별 버튼
  구성(Android 다시 시도 / iOS 편집 없이 사용)이 통째로 사라졌다.** 제거 섹션의
  메모가 이유를 단다 — "저 두 버튼 중 무엇을 눌러도 C-104로 이동".
- **`C-304`·`C-305`·`C-306`은 해체됐다.** 편집 허브의 배경 탭은 `C-301`로, 토핑
  탭과 토핑 편집·테두리 편집은 **"사진 편집 및 삭제" 카드(09-24)와
  `C-105`/`C-105-Arrange`**로 옮겨졌다([[src-사진-편집-플로우-v0.1]],
  [[src-사진-삭제-플로우-v0.1]]).
- **튜토리얼 5종은 반영 후 흐름에 하나도 없다.** v7은 4·5만 "다음 빌드에서 삭제"라
  적고 1~3은 말이 없었다. 프레임 부재는 삭제 선언이 아니다 — 다만
  [[src-figma-주석-Development-페이지]]가 "튜토리얼을 없애고"를 설계 목표로 적는다.

### v7에 없고 Figma에 있는 것

- 화면: **`C-101-Loading`**(사진 확인 뒤 이동하는 로딩), **`C-105-Arrange`**,
  **`C-106-Arrange`**, **`C-001-Save`**, `C-001-Save-Image`, `C-001-Save-Video`
  (`BL_30`).
- 토스트·상태: `C-104-Toast`, `C-105-Arrange-Toast`, `C-001-Shared-Toast`,
  `C-102-Toast`, `C-001-2Depth`.
- **`C-302-Confirm`·`C-303-Confirm`** — v7은 `C-302`·`C-303`을 "전용 프레임 없음,
  `C-101`/`C-102` 재사용"이라 적었다. 이제 **화면 코드를 따로 받는다**(아래).
- **취소 모달 다섯** — `Modal-Quit-Add`, `Modal-Quit-Add-Img`,
  `Modal-Quit-Add-Text`, `Modal-Quit-Edit`, `Modal-Quit-Background`. `C-` 접두사가
  없는 **화면 ID 체계 밖의 식별자**다.
- `푸시알림 예외케이스 코드 E-04`·`E-07` — v7이 "상세 내용 확인 필요"로 둔 그
  프레임이다. 주석은 **"정상 케이스에 대해서는 토스트 없음 / 자세한 사항은
  정책문서 참고"**뿐이다.

## 정책 문서에 없는 동작 주석

### 배경 변경 (`C-301`·`C-302`·`C-303`)

- **"화면 코드는 별도로 부여하며, UI만 동일하게 구성한다"** — 이유가 **"클릭 이벤트
  데이터 수집을 위해"**다. 화면 ID가 **분석 이벤트의 키**로 쓰인다는 첫 서술이다.
- 배경용 갤러리는 **`C-102`의 '최근 쌓은 사진'과 Toast를 노출하지 않는다.**
  `C-102`에 **"최근 쌓은 사진" 영역이 있다는 것** 자체가 위키에 없던 사실이다.
- `C-302-Confirm`·`C-303-Confirm`에서 다음은 **`C-301`로 이동**한다. v7은
  `C-302`·`C-303`의 다음 단계를 **`C-103`(누끼)**로 적었다 — **배경 사진은 이제
  누끼를 거치지 않는 것으로 읽힌다.**
- 배경을 안 고르면 **기본 White**이고 그래서 토핑 추가 버튼은 Disabled되지 않는다
  (반영 전·후 같음).

### 닫기(X)와 취소 모달

화면마다 X의 결과가 적혀 있다 — 모달 없이 `C-001`, 또는 `Modal-Quit-Add`·
`Modal-Quit-Edit`·`Modal-Quit-Background`. `Modal-Quit-Edit`는 **"해당 화면에서
수정사항이 있음"**을 포함한 두 조건을 모두 충족할 때만 뜬다(원본 번호가 수집에서
빠져 두 번째 조건은 읽히지 않는다). 규칙의 근거는 Development 페이지의 "X는 …
변경 사항이 있으면 정말 그만두겠냐는 팝업을 1회"다.

### 남의 사진 터치

- 패널이 닫힌 상태에서 남의 사진을 터치하면 Toast.
- **패널이 열린 상태에서는 패널만 닫히고 Toast가 없다.**

### 저장과 공유

- **다운로드 버튼은 편집 마감 전후와 관계없이 무조건 `C-001-Save-Preview`로 간다.**
  v7과 같다.
- **`BL_30` 인스타그램 스토리 공유** — 아이콘을 누르면 캔버스가 `Status: Save`가
  되고 `C-001-Save-Image` 또는 `C-001-Save-Video`로 간다. 사진·영상 저장은
  `C-001-Saved-Toast`, **공유 오류는 `C-001-Shared-Toast`**. **영상 저장이 있다.**
  v7 `C-001-Save-Preview`가 외부 공유 CTA가 없는 이유로 든 **"외부 공유 기능
  미존재"**가 이것으로 끝난다([[mvp-scope-limits]]).
- **초대는 시스템 공유 바텀시트**다 — "클릭시 시스템 공유하기 바텀시트 올라옴".
  반영 전 흐름은 "복사하기 클릭시 복사완료로 문구 변경"이었다. 같은 주석에
  **"인원수 1명으로 선택한 경우 해당 버튼 안뜸 (iOS기준 현행 유지)"**가 있다 —
  그룹 생성에 인원 선택이 없다는 v7(`A-005` "최대인원수 상한 12명 고정")과 맞지
  않아 **무엇을 가리키는지 읽히지 않는다.**
- v7 `C-001-Save-Preview`는 "파르페 내 바텀시트 사용처가 0곳"을 풀스크린의 근거로
  들었다. 시스템 공유 시트는 OS 것이라 그 판단과 직접 부딪치지는 않는다.

### 카메라 줌 (`BL_06`)

> 버튼 디폴트 값은 1x / Camera-Zoom 버튼 클릭 시 1x → 2x → 0.5x 순서로 반복

**[[src-회의록-2026-11-10-회의]]의 Android 서술과 다르다** — 회의록은 Android가
**"0.5 · 1.0 · 1.5 · 2.0 배율 버튼만"**이다. Figma는 **한 버튼이 세 값을
순환**하고 1.5x가 없다. 어느 쪽이 현행인지 원본으로 가릴 수 없다.

### 텍스트 (`BL_1`)

- `C-106`에서는 텍스트가 캔버스 너비에 닿으면 자동 줄바꿈, **`C-106-Arrange`에서는
  줄바꿈 없이 핀치 확대가 제한 없이 동작**, 캔버스 밖은 사진 토핑과 같이 잘린다.
- 기본값 **White-Default-Center**(컬러-타입-정렬). 타입은 **3종**(Default, Fill,
  Fill + Stroke). Development 초안은 6종이었다.
- 컬러 팝오버가 열린 채로도 정렬·타입을 바꿀 수 있다.
- **`C-106-Arrange(수정 중일 시)` 프레임이 있다.** [[src-회의록-2026-10-06-회의]]는
  텍스트를 **"수정 불가"**로 정했다. 세부는
  [[src-BL_1-텍스트-업로드-기능-추가-정책-v0.1]]이 다룬다.
- 디자이너 메모: "+ 버튼 말구 **추가 버튼**이라고 바꿔줄수있남".

### 반영 전 흐름에만 있는 디자인 상수

반영 전이라 현행 여부는 알 수 없다. 기록만 한다.

- 배경 색상: White(Empty), Black, Cherry-200, `#FCE7C2`, `#F9F9AB`, `#C5FFD7`,
  `#C2E4FC`, `#DCC2FC` + 갤러리·카메라.
- 테두리 색상: 없음, White, Black, Cherry-200, 위와 같은 다섯 색.
- 브러시: `#F63050` 50%, 스트로크 Cherry-500. 크기 조정 시 이미지 중앙에 크기 표시.

[[src-회의록-2026-09-29-회의]]가 `P-03`의 "올리러"를 QA 결함으로 고친 규칙과 맞지
않는다([[src-figma-주석-그룹-사이드-메뉴-S-10n]]).
