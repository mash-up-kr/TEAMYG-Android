# 5/28 전체회의 — 1차 UT 범위, 사진 소스, 편집 권한, 서비스명

## 요약

2026-05-28 21:00 Discord 전체회의. 1차 UT 기능 정의, 사진 소스 정책, 캔버스 편집
권한 정책, **서비스명 확정**, 일정 수정, 기능명세서 v1 수정이 안건이다. 각
플랫폼이 회의 전 기술 검토 결과를 올리고 그 위에서 정했다.

## 1차 UT 기준

1차 UT는 실제 개발이 아닌 **목업**(화면 이미지·피그마 프로토타입)이다.

| 성공 신호 | 실패 신호 |
|---|---|
| 사용자 입에서 **"친구들이랑" / "같이" / "함께"**가 자연스럽게 나옴 | **"사진 편집 앱이네요"** / **"혼자 써도 되겠다"** |

[[src-회의록-2026-05-24-회의]]가 정한 정체성(공유 캔버스, 친밀한 그룹)을 그대로
판정 기준으로 옮겼다.

범위 — 포함: **공유 캔버스(동시 채우기)**, **그룹 생성/초대(12명, 카톡 로그인)**.
누끼는 "포함 여부 논의 필요", 테두리·두께 설정과 색·배경 설정은 "제외 여부 논의
필요"로 남았다. 목업이니 **전체 플로우를 다 보여주자**는 제안이 붙었다. 원본의
목적 달성란은 "1차 UT 범위 최종 확정 ✅"이다.

## 결정 사항

| 안건 | 결정 |
|---|---|
| A. 사진 소스 | **A안 확정** — 촬영 + 갤러리 둘 다, 갤러리는 **"오늘 사진" 디폴트(기간 제한 O)**. 안드로이드는 시스템 피커로 고른 뒤 날짜를 검사하는 방식, iOS는 앨범에서 당일 사진만 필터링 가능 |
| B① 실시간 편집자 표시 | **MVP 제외, 확장 기능으로.** 다른 그룹원이 업로드 중일 때 상단 칩·점선 글로우로 보이는 안이었다. 안드로이드는 "가능하나 엣지 케이스 정의가 많다"(2분 무동작 기준, 통화 복귀 충돌) |
| B② 편집 중 콘텐츠 잠금 | **잠금 대신 "자신이 올린 사진만 편집(이동) 가능"** — 완벽한 락은 네트워크 지연으로 불가능하고, 선택마다 서버 제어권을 요청하면 매번 로딩이 생긴다는 안드로이드 검토에서 나온 차선책이 채택됐다 |
| B④ 실시간 동기화 수준 | **"편집 저장하면 그때 동기화."** Spring 검토는 웹소켓 대신 **폴링(5s)** |
| B⑤ 편집 상태 해제 트리거 | ①과 같은 맥락이라 **추가 기능으로** |
| 서비스명 | **파르페(parfait) 확정** — "완전한, 완벽한" + "아이스크림에 과일 등을 쌓아 만든 디저트" |
| 기능명세서 v1 수정 | "인터뷰 세션 이후 기획 반영" ✅ — 이틀 뒤 [[src-기능정의서-v2]](05-30) |

## 범위·정책에 미친 영향

- **동시 편집 충돌을 구조로 없앴다.** 본인 토핑만 움직일 수 있으면 같은 객체를
  둘이 잡는 일이 없다. 뒤의 `C-202` 규칙 — 타인 토핑은 Spotlight, 본인 토핑은
  편집 — 과 [[toast]]의 `내 토핑만 편집할 수 있어요`가 이 결정에서 나온다
  ([[canvas]], [[src-C-202-토핑-편집자-확인-규칙-v0.1]]).
- **실시간 반영은 저장 시점 동기화 + 폴링이다.** 기능정의서가 v4까지 "WebSocket
  또는 폴링"을 미정으로 달고 있었는데, 방향은 이 회의에서 이미 폴링이었다.
  [[src-기능정의서-v7]]은 주기를 **10초**로 적는다 — 이 회의의 5초는 서버 검토안이다.
- **실시간 편집자 표시와 편집 상태 해제는 MVP 밖**으로 밀렸다. 근거는 플랫폼
  검토의 엣지 케이스·규모다([[mvp-scope-limits]]).
- 갤러리 '오늘 사진' 디폴트가 기능으로 확정됐다. 하루 경계는 아직 자정이다
  ([[src-회의록-2026-06-04-회의]]).
- 제품명이 정해졌다([[parfait]]).
