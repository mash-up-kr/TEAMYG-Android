# 캔버스 정책 v0.3 (C-001)

## 요약

`C-001`(캔버스 메인)의 화면 구조·레이아웃·메뉴 정책 `v0.3`이다. 문서 날짜는
**2026-09-18**이고 노션 최종 편집은 09-20(`DSN-B`)이다. 출처는 Figma
`C-001-Empty` / `C-001` / `C-001-2depth` / `C-304-Img` **실측**이라고 원본이 적었다.

[[src-C-001-캔버스-정책-v0.2]]를 대체한다. 개정이력 요지가 **"Figma 현행 전면
반영"**이고 바뀐 것을 여섯으로 든다.

1. 3탭 모드 스위칭 폐기 → 1뎁스/2뎁스 캔버스 메뉴
2. Background Blur 상시 적용 폐기 → Dot Grid 배경
3. 날짜바는 탑바가 아니라 캔버스 내부 오버레이
4. 탭바 개념 삭제
5. 저장 아이콘 노출 조건 확정
6. `C-301` 폐기 반영

**이 문서는 지금까지 [[src-기능정의서-v7]]의 `기타` 열 전재로만 읽을 수 있었다.**
원본이 들어오면서 전재본과 대조할 수 있게 됐다 — 아래 "전재본과 무엇이
다른가"를 본다.

| 요소 | 값 |

| Status Bar | 375×48 |
| Top Bar | `y=48` `h=60` — 뒤로 / 그룹이름 / 그룹원 칩 / `☰` |

| Canvas-Area | **335×596**, **9:16** 비율 영역. `Background` 레이어를 가진다 |
| `Canvas/Button-Date-Select` | 335×44, `Canvas-Area` `y=0` 오버레이 — **탑바가 아니다** |

**9:16은 `Canvas-Area`에만 걸린다.** `Canvas-Menu` 44px는 비율 계산에서 빠지고
컴포넌트 전체 높이가 640이다.

## 반응형

**세로 모드 전용, 태블릿·가로모드 미고려** — 근거는 이번에도 없다
([[mvp-scope-limits]]).

우선순위 셋은 [[src-C-001-캔버스-정책-v0.2]]와 같은 순서다.

1. `Canvas-Area` **9:16 무조건 유지** — 원본이 "가로 9 : 세로 16 — 세로 고정"이라
   풀어 적었다.
2. 상단 gap(탑바↔캔버스)과 하단 gap(메뉴↔홈 인디케이터)은 **항상 동일, 최소
   12px.**
3. 좌우 패딩 **20px** — 가능한 한도 내에서.

375×812 실측은 상·하단 gap **각 16px**다. 세로가 모자란 기기에서는 12px를 먼저
지키느라 캔버스가 줄고 좌우 패딩이 20px보다 커진다 — **"캔버스가 탑바보다 좁아
보일 수 있음"**을 원본이 결과로 받아들였다. 내부 요소는 전부 캔버스 크기에
비례해 스케일된다.

## 날짜바

- 좌: 캘린더 아이콘 + 날짜 라벨(`May 20 (Wed)`) → `C-201`
- 우: 저장 아이콘 → `C-001-Save-Preview`([[src-C-001-저장-미리보기-정책-v0.2]])
- 날짜 라벨은 **크기 고정**(화면 크기와 무관하게 스케일 안 됨), 위치는 캔버스
  기준 좌상단 고정
- **`C-304` 편집 모드 진입 시 `hidden`**

**저장 아이콘 노출 조건이 확정됐다(09-18)** — **Empty 상태(토핑 0개)에서만
미노출**, 그 밖에는 **마감 여부와 무관하게 항상 노출.** 구 정책 「저장 버튼은
마감 시에만 노출」은 폐기다.

> **날짜 라벨 크기가 `v0.2`와 다르게 적혔다.** `v0.2`는 "높이만 고정, 너비는
> 캔버스 크기 따라 변함"이었고 이 판본은 "크기 고정"이다. 날짜바 자체는 335×44로
> 캔버스 폭과 같다 — **바와 라벨을 구분해 읽으면 양립하지만** 원본이 그렇게 가르지
> 않는다([[canvas]]).

## Canvas-Menu

| 뎁스 | 구성 |
|---|---|
| 1뎁스 | `Menu-Container` 335×44, `Button-Stroke` **167.5px 2분할**. 좌 `토핑 추가 +` → **2뎁스 펼침**(페이지 이동 아님), 우 `캔버스 편집 >` → `C-304` |
| 2뎁스 | 335×44 → **335×132**, `y=596` → **`y=508`**로 위로 펼쳐 `Canvas-Area` 하단 88px를 덮는다. 1 `카메라로 촬영` → `C-101`, 2 `갤러리에서 선택` → `C-102`, 3 기존 1뎁스 유지 |

Empty 상태에서도 1뎁스는 똑같이 보인다.

**2뎁스의 Dim**은 Canvas 인스턴스 안에 335×640 벡터로 들어가 **캔버스 전체(메뉴
포함)만 덮는다.** Top Bar와 Dot Grid는 딤 대상이 아니다. Fill은
`Transparency/Black-25` `#0E0E0E40`이다.

## Empty State (`C-001-Empty`)

`Canvas-Area` 중앙(x=74, y=302, 187×36)에 두 줄이다.

> 아직 캔버스가 비어 있어요 / 첫번째 토핑을 올려 캔버스를 채워보세요

저장 아이콘은 없고 메뉴는 1뎁스다.

원본이 **카피 수정 권고**를 달았다 — `올려`가 **브랜드 동사 규칙(쌓다 확정,
올리다 금지)**과 충돌하니 `첫번째 토핑을 쌓아 캔버스를 채워보세요`로 바꾸라는
것이다. **권고이지 확정이 아니다.** 그 규칙 자체는
[[src-common-서비스-공통-규칙-2026-09-20]]의 팀 용어 표에 있다.

**Empty의 정의가 "토핑 0개"다.** v7 프레임 정리는 `C-001-Empty`를 "캔버스
토핑·**배경** 미설정 상태"라 적는다 — 배경만 있고 토핑이 없는 캔버스가 Empty인지
두 서술이 갈린다.

## 배경 레이어 — Blur 폐기, Dot Grid

원본이 🚫 표시와 함께 **구 `v0.2` 「2. Background Blur 정책」을 삭제**한다고 적는다
— 배경 종류와 무관하게 `Black-25` / Uniform / Blur 4 도형을 상시 까는 규칙이다.

현행은 화면 전면(375×812)의 **Dot Grid**다.

| 항목 | 값 |
|---|---|
| 도트 간격 | **22px** (x·y 동일) |
| 도트 크기 | 2×2 |
| 역할 | 캔버스 영역 바깥의 앱 배경 |

캔버스 자체 배경(단색/이미지)은 `Canvas-Area > Background` 레이어가 맡고 **그
위에 덮이는 상시 블러 도형은 없다.** 유일한 오버레이는 2뎁스 Dim이다.

**도트 컬러는 적히지 않았다.** 디자인 토큰 절에 `gray-100 #ECECEE`가 있으나 Dot
Grid에 배정된다는 말은 없다. `v0.2`는 `Gray-100`이라 적었다.

## 폐기 항목과 사유

원본이 표 하나에 모았다. **폐기마다 사유를 붙였다** — 이 계열에서 폐기 사유를
표로 정리한 첫 문서다.

| 폐기된 정책 | 사유 |
|---|---|
| 3탭 모드 스위칭(파르페 홈 / 쌓기 / 배경) | 디자인에서 탭 구조 자체가 사라짐. 1뎁스/2뎁스 메뉴로 대체 |
| 하단 플로팅 탭바·탭바 좌우 패딩 20px | 탭바 없음. 캔버스 하단 부착 메뉴로 대체 |
| Background Blur 상시 적용 | Dot Grid 배경으로 대체 |
| 헤더(탑바) 안 날짜·저장 아이콘 배치 | 날짜바는 캔버스 내부 오버레이 |
| 저장 버튼 = 마감 시에만 노출 | Empty에서만 미노출로 확정 |
| `C-301` 파르페 편집 모드 진입 | `C-304`가 배경·토핑 탭으로 흡수 |

**사유가 전부 "디자인이 그렇게 됐다"다.** 왜 탭 구조를 없앴는지, 왜 Blur를
버렸는지는 없다 — Figma 현행을 문서가 따라간 기록이다([[mvp-scope-limits]]).

## 디자인 토큰

해당 프레임이 쓰는 토큰을 나열한다 — `Transparency/Black-25`·`White-75`,
`Color/Base/White #FAFAFA`, gray 100~900, `cherry-50~500`, `Pudding-500 #FFFF93`,
`Melon-500 #2FFFC1`. Padding `8 / 12 / 16`, Radius `99999`. 서체는 **SUIT**
(`B01_R 16` / `B02_R 14` / `C01_R 12`, line-height 1.5, letter-spacing -1.1).

## 개정이력이 위키의 `v0.2`와 맞지 않는다

> ⚠️ [2026-11-13] [[src-C-001-캔버스-정책-v0.2]] 와 상충 — 이 문서의 개정이력은
> `v0.2`를 **2026-07-24 "비율 표기 오기 정정 — 16:9 → 9:16"**으로 적는다. 위키가 가진
> `v0.2` 원본은 **07-22자, 개정 요지 "Dot grid 추가 및 캔버스 정책 변경"**이고 본문은
> 여전히 **16:9**다 → [[open-questions]]

어긋남이 둘 겹친다.

- **날짜와 내용이 다르다.** 위키의 `v0.2`가 바꾼 것은 탭바·Bottom-Bar·Dot Grid였고
  비율 표기는 손대지 않았다.
- **폐기 대상 절 번호가 다르다.** 이 문서는 "구 `v0.2` 「2. Background Blur
  정책」"을 폐기한다고 적는데, 위키의 `v0.2` 원본에서 §2 자리는 이미 Dot Grid였고
  Blur 절이 없었다.

**두 읽기가 양립한다** — 위키가 받은 `v0.2` 캡처(07-22) 뒤에 같은 판본 번호로
07-24 수정이 있었거나, 개정이력이 `v0.1`과 `v0.2`의 내용을 섞어 적었다. **어느
쪽인지 원본으로 판정되지 않는다.** 판본 사슬(`v0.1` → `v0.2` → `v0.3`) 자체는
문서명·버전 번호·개정이력이 모두 가리키므로 유지한다.

## 전재본과 무엇이 다른가

[[src-기능정의서-v7]]의 `C-001` `기타` 열은 이 문서의 §1~§7을 **문장 단위로 거의
그대로** 싣는다. Dot Grid 22px, 2뎁스 좌표, Empty 카피 권고까지 같다.

전재본에 **없는 것**은 넷이다.

- 머리말(날짜·버전·출처 Figma 프레임)과 **개정이력 표** — 위 상충은 원본에서만
  보인다
- **폐기 항목 표의 사유 열** — 전재본은 3탭 폐기만 한 줄 적는다
- **디자인 토큰** 절
- 원본의 `☰` 기호가 전재본에서 `≡`로 바뀌었다(표기 차이)

거꾸로 전재본에만 있는 것은 **프레임 정리**(`C-001 (Default)` 명칭 통일,
`C-001-2depth`·`C-001-Empty`·`C-001-Saved-Toast`가 별도 페이지가 아님,
`C-001-Error`·`C-001-Loading` 독립 행)다 — 기능정의서가 덧붙인 것이다.

**전재가 원본을 바꾼 자리는 없다.** v7 전재에서 Dot Grid 간격 22px와 `v0.2`의
20px가 어긋났던 것은 전재 탓이 아니라 **판본 차이**로 확인된다 — 원본도 22px다.
