# 8/27 전체회의 — 2차 UT 설계안과 인터뷰 기록

## 요약

2026-08-27(목) 20:00 Discord 전체회의다. 안건은 진행 상황·심사 일정, 2차 UT
인터뷰이·참석자·시연 방식·진행자 확정, 심사 문서 같이 읽기.

하위 페이지 둘이 본문 대부분이다 — **`무한 파르페 — 2차 UT 설계안`**과
**`2차 UT용 서기 템플릿`**. 서기 템플릿에는 **실제 인터뷰 답변이 채워져 있다**
(08-29 진행분). 관찰 체크박스는 거의 비어 있고 인터뷰 답변만 남았다.

**이 문서가 1차 UT 결과를 처음으로 집계했다** — [[src-회의록-2026-07-16-회의]]의
발화를 ①~⑧로 정리하고 각각 2차에서 어떻게 다룰지 정했다.

## 결정 사항

- **심사** — 9/1보다 여유 있게. Android가 먼저 끝나면 먼저 제출하고 iOS는 준비되는
  대로 제출. 디자인은 심사용 스크린샷 준비 중.
- **2차 UT 인원** — 1타임 2명 / 2타임 1명. 설계안은 4명(2인 페어 × 2타임)이었고
  **실제로는 3명**이다. 2타임은 진행자가 페어 상대 역할을 맡는다.
- **시연** — 데모앱으로 전체 시연하고 **Android로 진행**한다(진행 속도가 더
  빨라서). 설계안의 태스크별 매체 표는 **iOS 데모앱**을 적어 두어 회의 결정과
  다르다.
- 진행자 `DSN-A`·`DSN-B`, 서기는 타임별로 `iOS-B`·`AOS-C`.

## 2차 UT 설계 — 1차와 무엇이 다른가

| | 1차 | 2차 (08-29) |
|---|---|---|
| 질문 | "이거 팔릴까? 방향 맞나?" | **"실제로 쓰기 편한가? 어디서 막히나?"** |
| 재료 | 피그마 프로토타입 + UT 전용 조작 | **데모앱(실제 클라이언트)**, 미구현분만 피그마 |
| 태스크 | 잘게 쪼갠 Task A~D | **실사용 시나리오 하나를 처음부터 끝까지** |
| 데이터 | 더미 계정 1개, 혼자 | **실제 사진 + 2명 동시 접속** |
| 결과물 | 발화록 | 발화 + 정량(완주율·개입·시간·SEQ) |

원본이 1차의 한계로 꼽은 셋 중 셋째가 핵심이다 — **"'매일 리셋'이라는 서비스의
코어 메커닉을 아무도 검증하지 않았다."** 1차 발화에 "하루마다 생기는 거구나"류가
반복된 것을 **인지 실패 신호**로 읽고 2차 최우선 가설(H1)로 올렸다.

### 1차 결과 → 2차 처리 방침

| # | 1차 발견 | 2차 처리 |
|---|---|---|
| ① | Empty에서 뭘 할지 모름(**6명 중 3명**이 "그룹 만들어야겠다"까지만) | **개선 반영됨 — 그룹 생성 유도 팝업.** 2차에서 검증 |
| ② | 초대 코드 복사 후 어디로 갈지 헷갈림 | 미반영, 핵심 태스크로 재검증 |
| ③ | `새 그룹` 버튼을 그룹 **입장** 통로로 오인 | 미반영, 관찰 포인트 |
| ④ | 상단 토스트가 어색 / 사라지면 복사 못 하나 | 미반영, 관찰 포인트 |
| ⑤ | 날짜 리셋·과거 기록 열람 인지 안 됨 | 미반영, **2차 최우선 가설** |
| ⑥ | 누끼+스트로크만으론 심심, 스티커·텍스트 필요(**4명**) | 미반영 — **"MVP 범위 논의 중"**. 마무리 질문으로만 |
| ⑦ | 파르페 은유 자체 회의 — 그룹마다 파르페 하나가 낫다 | **"UT로 못 고침. 제품 결정 사항."** 2차 범위 밖 |
| ⑧ | "쌓아서 뭘 하나 / 굳이 이걸 써야 할 이유" | 재방문 의향으로 최소 측정만 |

**⑦이 제품 결정으로 넘겨진 뒤 결론이 이 문서에 없다**([[infinite-parfait]]).

### 가설

- **H1 매일 리셋 인지(최우선)** — 안내 없이 "오늘 하루짜리, 내일 새로 시작"을
  알고 과거 날짜 기록을 찾아 연다. 화면 범위 `G-001` → `C-001` → 날짜 선택 →
  `C-201` → 과거 캔버스. 날짜 버튼을 10초 안에 찾는지 본다.
- **H2 그룹 참여** — 초대 코드로 개입 없이 입장하고 `새 그룹`과 `코드로 참여`를
  혼동하지 않는다. `G-001` → `A-004` → `G-002` → `C-001`.
- **H3 토핑 쌓기 효율** — `C-001` → `C-102` → `C-102-confirm` → `C-103` →
  `C-105` → `C-106`. **반드시 갤러리 실제 사진으로**(더미로는 누끼 품질 문제가 안
  드러난다).
- **H4 다중 그룹 탐색** — 그룹 4개 이상에서 특정 그룹을 3탭·15초 안에 찾는다.
  원본이 이것을 **⑦ 의사결정의 근거 데이터**라 적었다. 세션 순서 줄에는 "H4·T6
  드롭"이 적혀 있으나 서기 템플릿에는 T7(다중 그룹)이 남아 있다.
- **H6 소유·섞임** — 남의 토핑과 섞이는 것을 긍정·중립으로 받아들이고, **"내
  토핑은 나만 옮길 수 있다(타인은 이동 불가)"**는 소유권 제약을 안내 없이
  수긍한다. 진행자가 상대 사진을 옮겨 보라고 시킨다 — 실제로는 안 움직인다.

이 설계안이 **제품 사실 몇 가지를 명시**한다.

- 토스트는 Figma상 **y=108, Top Bar 바로 아래**다.
- 초대 코드 복사 경로는 `C-001` → 사이드 메뉴 → **`S-101`** → 복사 버튼
  (`WDIDCJ` 꼴 6자). `S-101`의 "1명 남음" 표시로 정원 제한이 있다.
- 어제 날짜 더미는 **03시 리셋 배치**로 사라질 수 있다(설계안 본문은 "자정"이라
  했다가 서기 템플릿에서 "03시"로 적었다).

## 2차 UT 답변 — 무엇이 나왔나

참가자 셋(1타임 둘, 2타임 하나)의 인터뷰 답변이다.

### 누구와 쓰겠는가

- **"친구들"**, **"친구/가족 — 혼자 쓰는 앱은 아닌 것 같다"**, **"잘 꾸밀 줄
  알고 꾸미는 걸 좋아하는 친구들이랑. 내 애인은 잘 못할 듯"**.
- 한 문장 설명: **"누끼 셋로그"**(둘), **"사진 하나 같이 만드는 앱"**. "캔버스"라는
  말은 남에게 쓰지 않겠다고 했다.
- 첫인상: "음식 관련 어플", "무슨 앱인지 모르겠다", "체리가 예쁘다".

**[[purpose]] 질문 2에 처음 닿는 직접 답이다** — 혼자가 아니라 친구·가족 단위,
꾸미기를 즐기는 사람.

### 매일 리셋 — 셋 다 몰랐다

**"이전 날짜로 가기 전까지 몰랐다"**(1타임 둘), **"예전 것 들어가 보려 했을 때
앎"**(2타임). H1이 겨냥한 인지 실패가 2차에서도 그대로다. 과거 캔버스는 "갤러리에
저장하고 싶을 때", "우리가 어땠지? 할 때 — 스토리 보관함처럼" 쓰겠다고 했다.

### 그룹 참여 — 여전히 헷갈린다

"초대 코드를 받았을 때 어디로 들어가야 할지 모르겠다", **"`그룹 추가하기`가
생성처럼 보인다. 생성/참여 버튼을 따로 두었으면"**. Empty에서는 **툴팁 덕에
`그룹 추가하기`가 가장 먼저 눈에 들어왔다**는 답이 둘
([[src-G-001-Empty-툴팁-노출-조건-정책-v0.1]]).

### 토핑 쌓기

- "귀찮은 데 없었다"가 둘. **누끼가 가장 재미있었다**(좋았던 순간으로 둘).
- 누끼가 마음에 안 들면 "삭제하고 다시"(둘) — **수동 보정이 있는지 몰랐다.**
  2타임 참가자는 편집 기능이 있다는 설명을 듣고 **"기본적으로 테두리가 있으면
  수정해야겠다는 생각이 들 듯, 있는 줄 몰랐다"**.
- `C-106`에서 **회전과 크기가 분리된 버튼이 어렵다, 하나가 낫다.**
- 언제 올리나: 밥 먹을 때, **"비리얼처럼 푸시 알림이 오면 좋겠다"**, **"친구가
  올리면 알림이 오면 그때 올릴 것"**, 아무 때나.

### 섞임·소유

- 섞임: "여러 사람이 한 공간을 꾸미니 당연", "동시에 겹치는 거 좋다, 같이 하는
  느낌", "나중 사람이 내 걸 다 덮으면 별로". **"이 사진을 누가 올렸는지 알 수
  있나요?"**
- 이동: 수긍 둘("납득이 간다", "서로 옮기면 더 수고롭다"), 남의 것 옮기는 게 더
  재밌겠다 하나.
- **남이 내 것을 지우는 것: 셋 다 싫다.**

### 다중 그룹

활동 최신순이면 괜찮다(둘), **이름보다 사진으로 기억한다**, 10~20개가 되면 검색이
필요하다 vs 파르페라 검색은 불필요하다.

### 마무리

- 아쉬움: **"왜 파르페지? 길면 길수록 뭐가 있나? 기대감이 있는데 아무것도
  없다"**, **"토핑을 파르페에 올리는 게 재밌을 것 — 저번 UT와 동일"**. 홈·파르페
  화면 꾸미기 요청.
- 원하는 기능 하나: **누끼 올라간 순서대로 동영상**, **인스타 스토리 올리기(갤러리
  저장 → 인스타)**, **쌓이는 애니메이션을 스토리에 바로**. 셋 다 공유·영상 쪽이다.
