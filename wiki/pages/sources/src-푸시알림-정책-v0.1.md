# 푸시알림 정책 v0.1

## 요약

푸시 알림 계열의 첫 정책 문서다. 날짜는 **2026-08-30**, 버전은 `v0.1`이다. 화면 번호에
종속되지 않는 공용 정책이고 화면 ID 대신 알림 ID `P-01`~`P-03`을 쓴다.

개정이력 한 줄이 범위를 요약한다 — **"알림 3종 정의(토핑 등록 / 데일리 리마인드 2회),
권한 요청 시점, 딥링크 시나리오, 예외 케이스 18종, 법적 요건 정리".**

**[[src-기능정의서-v7]](09-21)보다 3주 앞선다.** 이 위키는 지금까지 푸시를 v7의
`P-01`~`P-03` 세 행으로만 알았다([[push-notification]]). v7이 적은 정책은 이 문서의
요약본이고, v7이 "문구만 정의한다"면서 빠뜨린 **문구와 예외 케이스 전문이 여기
있다.**

[[src-푸시알림-정책-v0.4]](10-31)가 이 문서를 대체한다. `v0.2`(10-07)와
`v0.3`(10-27)은 원본이 수집되지 않아 v0.4의 개정이력으로만 안다.

### 원본이 08-30 그대로가 아니다

- **최종 편집이 10-07(`DSN-B`)이다.** v0.4 개정이력상 `v0.2`가 "v0.1 복제 후
  보강"한 날과 같다.
- 본문에 **"운영 확인 결과 미동작 … 운영 백로그 등록(2026-09-20)"** 주석이 두 군데
  붙어 있다. 08-30 초안에 9월 운영 관찰이 덧붙은 상태다.
- 개정이력이 "법적 요건 정리"를 적는데 **그런 절이 본문에 없다.** 수집본은 §5 예외
  케이스에서 끝난다.
- Notion의 글자 색은 수집 과정에서 빠졌다.

## 목적 — 두 가지

1. **그룹 활동 인지** — 그룹원이 토핑을 쌓았다는 사실을 즉시 알린다.
2. **마감 사이클 인지** — 캔버스가 매일 03:00 KST에 마감되므로 마감 전에 참여할
   기회를 안내한다([[canvas]]).

## 확정 사항

| 항목 | 결정 |
|---|---|
| 알림 종류 | `P-01` 토핑 등록, `P-02` 오전 리마인드, `P-03` 저녁 리마인드 |
| 토핑 알림 발송 | **개별 발송, 상한 없음** |
| 리마인드 시각 | **10:00 / 20:00 KST** |
| 권한 요청 시점 | **첫 그룹 참여(`A-004`)·생성(`A-005`) 완료 직후** |
| 수신 거부 수단 | **OS 시스템 알림 설정 only** |
| 시간대 | **서버 KST 고정** |

## 세 알림과 문구

| ID | 트리거 | 대상 | 진입 | 제목 | 본문 |
|---|---|---|---|---|---|
| `P-01` | `C-106` 배치 **확정 저장** | 본인 제외 전체 그룹원 | `C-001`(해당 일자) | `{그룹명} 파르페에 체리 얹을 타이밍!` | `{그룹 내 닉네임}님이 새 토핑을 쌓았어요` |
| `P-02` | 스케줄러 10:00 KST | 가입 그룹 1개 이상 + 권한 허용 + 유효 토큰 | `G-001` | `새벽 3시에 오늘의 새 캔버스가 열렸어요` | `오늘의 첫 토핑을 쌓아볼까요?` |
| `P-03` | 스케줄러 20:00 KST | `P-02`와 동일 | `G-001` | `새벽 3시에 오늘의 캔버스가 마감돼요` | `오늘의 마지막 토핑을 올리러 가볼까요?` |

- 셋 다 **정보성**으로 설계했다. `P-01`은 **시간 제한 없이 24시간 발송**한다.
- `P-01` 발송량은 **"1 업로드 = 1 발송. 묶음·상한·쿨다운 없음"**이다. v7이 옮긴
  문장과 같다. **근거는 이 문서에도 없다.**
- 발송 큐 처리 중 작성자가 탈퇴·나가기하면 본문을 `누군가 새 토핑을 쌓았어요`로
  바꾼다.

`P-03` 본문의 "올리러"는 [[src-common-서비스-공통-규칙-2026-09-20]]의 팀 용어
규칙("쌓기 — `올리다` 사용 금지, 푸시 문구에도 적용")과 어긋난다. 이 문서가 그
규칙보다 3주 앞선다.

## 권한 — 한 번 묻고 다시 묻지 않는다

- 시점: `A-004` 또는 `A-005` 완료 직후, `G-002` 진입 전 **1회.**
- 프라이밍 모달 문구: 제목 `그룹원이 토핑을 쌓으면 알려드릴까요?`, 본문 `새 토핑
  소식과 캔버스 마감 안내를 받을 수 있어요. 알림은 언제든 기기 설정에서 끌 수
  있어요.`, 버튼 `[알림 받기]` `[나중에]`.
- `[나중에]` → OS 다이얼로그 없이 `G-002`로. **재노출 없음.**
- 거부하면 토큰이 서버에 없으므로 **발송 시도 자체를 하지 않는다.** 앱 안에서 재요청
  배너·모달도 띄우지 않는다.
- **다시 켜는 경로는 기기 설정 > 알림 > 파르페다.** 이 경로를 `S-004`(약관 및
  개인정보 처리방침) 화면과 개인정보처리방침 본문에 안내한다고 적었다.

**[[push-notification]]이 "나중에 켜는 경로가 어느 행에도 없다"고 적은 것에 대한
답이 이 문서에 있었다.** 앱 안의 경로가 아니라 OS 설정이고, 안내는 약관 화면이
맡는다.

## 앱 안 알림 설정은 MVP 범위 밖이었다

**§3.4 원문: "OS 시스템 알림 설정에서 전체 끄기가 유일한 수단이다. 앱 내 알림 설정
화면·개별 토글은 MVP 범위 외."**

범위를 좁힌 결정인데 **근거가 적혀 있지 않다**([[mvp-scope-limits]]). 이 결정은
두 달 뒤 [[src-푸시알림-인앱-알림-제어-정책-v0.3]]의 `S-105`로 뒤집힌다.

## 딥링크와 앱 상태

`P-01`은 `G-002`에서 권한을 검증한 뒤 `C-001`(해당 date)로 간다. 그룹에 접근할 수
없거나 그룹이 삭제됐으면 `G-001` + 토스트(`E-04`). `P-02`·`P-03`은 `G-001`로 간다.

| 앱 상태 | 동작 |
|---|---|
| 종료(cold start) | `A-001` → 토큰·버전 체크 → **목적지로 직행**(`G-001` 경유 없음). 세션 저장 후 1회 소비 |
| 미로그인 | **딥링크 폐기.** 로그인 후 `G-001` 일반 진입 |
| 강제 업데이트 대상 | 스토어 안내 우선, 딥링크 폐기 |
| 백그라운드 | 현재 스택 위에 push. 뒤로가기로 직전 화면 |
| 포그라운드 · 해당 그룹 `C-001` 체류 | **OS 배너 억제, `C-001` 상단 알림 띠로 대체** |
| 포그라운드 · 그 밖 | 인앱 배너, 탭하면 같은 딥링크 |
| 토핑 올리기(`C-101`~`C-106`)·본인 토핑 수정(`C-305`·`C-306`) 중 | **인앱 배너 억제**, 알림센터에만 적재 |

**억제 규칙 둘은 운영에서 동작하지 않았다.** 원본이 직접 "OS 푸시가 그대로 오고
알림 띠는 안 뜸", "본인 토핑 수정 중에도 푸시가 옴"이라 적고 09-20 백로그 등록을
남겼다. [[src-푸시알림-정책-v0.4]]가 두 규칙을 폐기하고 동작하던 쪽을 정책으로
올린다.

도착 후: 날짜가 넘어갔어도 **푸시의 `date` 캔버스로 진입**한다(오늘자로 돌리지 않음,
마감분은 편집 불가). 토핑이 신고·삭제됐으면 캔버스는 열고 토스트 `해당 토핑은
삭제됐어요`.

## 예외 케이스 18종

| # | 케이스 | 처리 |
|---|---|---|
| `E-01` | 본인 토핑 | 본인에게 안 보냄 |
| `E-02` | 권한 미허용 | 토큰 없음, 발송 시도 없음 |
| `E-03` | 수신자가 그룹을 나간 뒤 큐 소비 | 발송 직전 재검증, 취소 |
| `E-04` | 그룹 삭제(마지막 1인 나가기) 또는 도착 후 본인이 나감 | 발송 취소. 이미 간 건은 탭하면 `G-001` + 토스트 `참여 중이 아닌 그룹이에요` |
| `E-05` | 작성자가 업로드 직후 탈퇴·나가기 | `누군가 새 토핑을 쌓았어요` |
| `E-06` | 03:00 경계 | 푸시 `date`의 `C-001` |
| `E-07` | 토핑 신고·삭제 뒤 탭 | 캔버스 진입, 토스트 `해당 토핑은 삭제됐어요` |
| `E-08` | 12인 동시 업로드 | 개별 발송 유지. 수신자당 최대 11건. 초당 발송량 제한만 |
| `E-09` | FCM/APNs 장애 | TTL — `P-01` 6시간, `P-02`·`P-03` 1시간. 리마인드는 **21:00 이후 도착 금지** |
| `E-10` | 토큰 만료·무효 | 서버에서 삭제, 재로그인 시 재등록 |
| `E-11` | 다른 기기 로그인 | 구 토큰 즉시 폐기 ("5절" 참조라 적었으나 5절이 이 표 자신이다) |
| `E-12` | 앱 삭제 | OS가 무효화 → `E-10` |
| `E-13` | 탈퇴 후 재가입 | 신규 이용자. 권한 요청도 다시 |
| `E-14` | 해외 체류 | **KST 고정 발송**, 처리방침·약관에 명시 |
| `E-15` | 포그라운드에서 해당 캔버스 열람 | 상단 알림 띠로 대체 (운영 미동작) |
| `E-16` | 토핑 올리기·본인 토핑 수정 중 | 인앱 배너 억제 (운영 미동작) |
| `E-17` | 미로그인 탭 | 딥링크 폐기 |
| `E-18` | 강제 업데이트 | 스토어 우선, 딥링크 폐기 |

**v7이 "상세 내용 확인 필요"로 둔 `E-04`·`E-07`이 이 표의 행이다.** v7은 이 문서의
번호만 가져가고 내용을 옮기지 않았다. `E-` 축은 **푸시 정책의 예외 케이스 일련번호**다
([[screen-id-scheme]]).
