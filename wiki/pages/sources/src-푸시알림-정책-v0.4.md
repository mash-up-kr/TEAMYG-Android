# 푸시알림 정책 v0.4

## 요약

푸시 알림 계열의 `v0.4`다. 날짜는 **2026-10-31**, 최종 편집은 11-03(`SPR-A`)이다.
[[src-푸시알림-정책-v0.1]](08-30)을 두 달 만에 대체한다.

**`v0.2`·`v0.3` 원본은 수집되지 않았다.** 둘 사이에 무엇이 바뀌었는지는 이 문서의
개정이력으로만 안다.

| 버전 | 날짜 | 개정이력 요지 |
|---|---|---|
| `v0.1` | 08-30 | 초안. 알림 3종, 권한 시점, 딥링크, 예외 18종, 법적 요건 |
| `v0.2` | 10-07 | **용어 변경(토핑 → 사진).** `P-04` 텍스트 등록·`P-05` 배경 변경 추가. 텍스트 미리보기 규칙. 리마인드·권한 문구에서 토핑 제거. `E-19`~`E-22` |
| `v0.3` | 10-27 | 푸시알림 인앱 제어 정책 추가 |
| `v0.4` | 10-31 | **알림 모아 받기** — `P-06` 활동 묶음 알림. 리마인드 인앱 ON/OFF(`E-23`). `S-105` 진입 시 OS 꺼짐 안내를 §3.3 예외로 허용. **열람·편집 중 억제 규칙 폐기.** `E-08`·`E-09` 수정, `E-24`~`E-28` |

원본은 변경분을 빨간 글씨로, 폐기분을 취소선으로 표시했다. **빨간 글씨는 수집
과정에서 색이 빠졌다** — 취소선만 남아 있어, 무엇이 v0.2 이후 추가분인지 본문만으로
가릴 수 없다. 위 표의 개정이력이 유일한 단서다.

`S-105`(알림 설정) 화면 정책은 별도 문서
[[src-푸시알림-인앱-알림-제어-정책-v0.3]]으로 갈라졌다. 이 문서가 발송 트리거·문구·
묶음 규칙의 **단일 출처**이고, `S-105` 문서가 그것을 상위 문서로 가리킨다.

## 알림이 셋에서 여섯이 됐다

| ID | 무엇 | 트리거 | 진입 | 제목 | 본문 |
|---|---|---|---|---|---|
| `P-01` | 사진 등록 | `C-106` 사진 배치 **확정 저장** | `C-001` | `{그룹명} 파르페에 체리 하나 톡!` | `{그룹 내 닉네임}님이 새 사진을 쌓았어요` |
| `P-02` | 오전 리마인드 | 스케줄러 10:00 KST | `G-001` | `새벽 3시에 오늘의 새 캔버스가 열렸어요` | `오늘의 파르페를 먼저 쌓아볼까요?` |
| `P-03` | 저녁 리마인드 | 스케줄러 20:00 KST | `G-001` | `새벽 3시에 오늘의 캔버스가 마감돼요` | `오늘의 파르페를 완성하러 가볼까요?` |
| `P-04` (신규) | 텍스트 등록 | 텍스트 추가 **확정 저장** (진입점·화면 코드 미정) | `C-001` | `{그룹명} 파르페에 체리 하나 톡!` | `{그룹 내 닉네임}: {미리보기}` |
| `P-05` (신규) | 배경 변경 | `C-304` 배경 탭에서 **변경한 시점** | `C-001` (`C-304`로 보내지 않음) | `{그룹명} 파르페에 체리 하나 톡!` | `{그룹 내 닉네임}님이 배경을 바꿨어요` |
| `P-06` (신규) | 활동 묶음 | 묶음 윈도우 종료 (모아 받기 ON 수신자만) | `C-001` | `{그룹명} 파르페에 체리가 또 톡!` | `그사이 새 소식이 {N}개 쌓였어요` |

**번호 원칙이 처음 적혔다** — 기존 `P-01`~`P-03`은 유지하고 신규는 뒤에 붙인다.
"서버·클라이언트에서 이미 쓰는 번호를 바꾸지 않기 위함."

### 토핑이 사진이 됐다

`v0.2`의 용어 변경이 이 판본에 남았다. `P-01`은 "토핑 등록"에서 **"사진 등록"**으로,
삭제 토스트는 `해당 토핑은 삭제됐어요`에서 `해당 사진은 삭제됐어요` /
`해당 텍스트는 삭제됐어요`로 바뀌었다. 리마인드와 권한 모달은 사진·텍스트를 아우르게
**"파르페"·"캔버스를 꾸미면"**으로 목적어를 바꿨다.

이 위키의 나머지는 여전히 "토핑"으로 적는다([[canvas]],
[[topping-placement-pipeline]]). 푸시 문서 밖에서도 용어가 바뀌었는지는 이 문서로는
알 수 없다.

### 원문이 말하지 않은 문구 변경

`P-01` 제목이 `v0.1`의 `{그룹명} 파르페에 체리 얹을 타이밍!`에서
`{그룹명} 파르페에 체리 하나 톡!`으로 바뀌었다. 원문 주석은 **본문**의
'토핑'→'사진' 교체만 적고("글자수 동일, 닉네임 뒤 13자") **제목 교체는 어느
개정이력에도 없다.** 이 제목이 이제 `P-01`·`P-04`·`P-05` 공통이다.

`P-03` 본문의 "올리러"(`v0.1`)도 사라졌다 —
[[src-common-서비스-공통-규칙-2026-09-20]]의 "`올리다` 사용 금지" 규칙과 이제
맞는다.

### 비트리거

신규 **등록만** 트리거다. 업로드 후 사진 편집(배치·테두리)·텍스트 수정(내용·스타일)·
삭제는 보내지 않는다(`E-19`, `E-20`).

## 텍스트 미리보기 (`P-04`)

**설계 의도가 적혔다** — 텍스트는 이미지화하지 않고 그대로 저장하므로 내용을 보여줄
수 있다. **메신저 형식(닉네임: 내용)으로 "누가 말을 걸었다"로 읽히게 해서 답장하러
들어오는 부담을 낮춘다.** 스타일(크기·색·테두리·배경)은 반영하지 않는다.

서버 생성 규칙:

1. 줄바꿈 → 공백 1개, 연속 공백 → 1개
2. 앞뒤 trim
3. 11자 이하면 그대로, 초과하면 **앞 10자 + `…`**
4. **grapheme cluster 기준**으로 센다. `String.length`는 UTF-16 단위라 이모지를 2자
   이상으로 세고, 중간에서 자르면 `�`가 노출된다(`E-21`)
5. 정규화 후 빈 문자열이면 발송하지 않는다(`E-22` — 업로드 단계에서 이미 막는다)

작성자가 탈퇴·나가기하면 닉네임 자리를 `누군가`로.

## 묶음이 생겼다 — 단, 수신자가 고를 때만

`v0.1`의 **"묶음·상한·쿨다운 없음"이 기본값으로 남고**, `S-105`의 **'알림 모아
받기'를 켠 수신자에게만** `P-06`이 적용된다. 기본은 OFF다.

| 항목 | 내용 |
|---|---|
| 대상 | `P-01`·`P-04`·`P-05`. 리마인드는 묶지 않는다 |
| 윈도우 단위 | **(수신자, 그룹, 캔버스 date)**마다 독립 |
| 윈도우 길이 | **10분.** 앱 UI에 노출하지 않는다 |
| TTL | 1시간 (원문 "제안") — "그사이" 문구라 늦으면 의미가 없다 |

발송 규칙:

1. 열린 윈도우가 없을 때 들어온 활동은 **즉시 개별 발송**하고 10분 윈도우를 연다.
2. 윈도우 안의 활동은 누적한다.
3. 윈도우가 끝나면 누적분을 `P-06` 1건으로. 누적 0이면 보내지 않는다.
4. 끝난 뒤 들어온 활동은 다시 1번.
5. 고정 주기로 돌지 않는다. 활동이 없으면 대기만 한다.

**활동이 계속되면 수신자당 10분에 최대 2건**이다. `v0.1`의 `E-08`(12인 동시 업로드 →
수신자당 최대 11건)은 모아 받기 OFF일 때 그대로이고, ON이면 첫 1건 + 10분 뒤
`P-06` 1건이 된다.

### N 집계는 서버 회신 대기다

원문 절 제목이 **"N 집계 (서버 회신 대기 — 확정 시 갱신)"**이다.

- 윈도우 안 누적 수. 즉시 보낸 첫 알림은 빼고, 사진·텍스트·배경을 각 1로 센다.
- 발송 시점에 재집계해 그사이 삭제된 활동을 뺀다. 0이면 발송 없음(`E-26`).
- **N 표기 상한(두 자리 이상)은 미정이다.**

### 묶음에 딸린 예외

| # | 케이스 | 처리 |
|---|---|---|
| `E-24` | 윈도우가 03:00을 걸침 | 03:00에 끊고 누적분을 **이전 date**로 발송. 이후 활동은 새 date의 첫 알림 |
| `E-25` | 대기 중 수신자가 그룹을 나감 | 대기분 폐기 |
| `E-26` | 대기 중 삭제로 재집계 0 | 발송 없음 |
| `E-27` | 대기 중 모아 받기 설정 변경 | 대기분 폐기. 이후는 바뀐 설정대로 |
| `E-28` | 대기 중 그룹명 변경 | 발송 시점 그룹명 |

## 앱 안에서 끌 수 있는 것은 리마인드뿐이다

| | `v0.1` | `v0.4` |
|---|---|---|
| 수신 거부 수단 | **OS 설정 only.** 앱 내 알림 설정·개별 토글은 MVP 범위 외 | 리마인드(`P-02`·`P-03`)는 **`S-105` '오늘의 캔버스 알림'**으로 끈다. 그룹원 활동 알림은 **받는 방식만** 고르고, 끄기는 **OS 설정뿐** |
| 권한 재요청 | 앱 안에서 배너·모달 없음 | 같음. **예외: 사용자가 직접 `S-105`에 들어왔고 OS 알림이 꺼져 있으면 꺼짐 안내와 이동 버튼을 화면 안에 보인다** — 팝업이 아니라 설정 화면의 상태 표시 |

'오늘의 캔버스 알림' OFF 수신자는 토큰이 유효해도 리마인드 대상에서 빠진다(`E-23`).
`P-01`·`P-04`·`P-05`·`P-06`은 영향 없다.

**MVP 범위 밖이던 앱 안 알림 설정이 들어왔다.** 그 이유는 이 문서가 아니라
[[src-푸시알림-인앱-알림-제어-정책-v0.3]] §1에 있다 — 내부 테스트에서 **푸시가
없으면 재진입이 거의 없었고**, 짜증난 사용자가 OS에서 전체 차단하면 복구 경로가
없다.

권한 모달 문구가 바뀌었다 — 제목 `그룹원이 캔버스를 꾸미면 알려드릴까요?`, 본문
`그룹원의 새 소식과 캔버스 마감 안내를 받을 수 있어요.` **"클라이언트 문구라 앱
업데이트 필요"**라고 원문이 표시했다. 모달 본문의 "알림은 언제든 기기 설정에서 끌 수
있어요"는 그대로다 — 리마인드는 이제 앱에서도 끌 수 있는데 모달은 기기 설정만
가리킨다.

## 억제 규칙을 폐기했다 — 운영이 동작하던 쪽으로

`v0.1`의 억제 규칙 둘은 운영에서 **동작하지 않았다**(09-20 백로그). `v0.4`는 고치지
않고 **규칙을 지웠다**(2026-10-31).

| 앱 상태 | `v0.1` | `v0.4` |
|---|---|---|
| 포그라운드 · 해당 그룹 `C-001` (`E-15`) | OS 배너 억제 → 상단 알림 띠 | **푸시 정상 노출.** 알림 띠 대체 폐기 |
| 사진 올리기(`C-101`~`C-106`)·텍스트 추가·본인 사진 수정(`C-305`·`C-306`)·캔버스 수정(`C-304`) 중 (`E-16`) | 인앱 배너 억제, 알림센터 적재 | **푸시 정상 발송.** `P-06`도 같다 |

**폐기 이유가 적혔다** — "억제하면 쌓기를 마친 뒤 알림이 남지 않아, 이용자가
사진을 눌러봐야만 새 활동을 알 수 있어 더 번거롭다." 상단 알림 띠 쪽(`E-15`)의 폐기
이유는 따로 없다.

**이로써 캔버스를 보고 있는 사람에게도 OS 푸시가 간다.** 같은 사건에 [[toast]]도
뜨는지는 이 문서가 다루지 않는다.

억제 대상 목록에 텍스트 추가·`C-304`가 들어간 것은 원문이 "v0.2 제안"이라 적었고,
**"사진 편집 플로우 개편(배치+테두리 통합, `C-305` 경로 대체)이 적용되면 화면코드
갱신 필요"**라는 주석도 함께 취소선으로 지워졌다. `C-305` 경로가 대체될 예정이라는
사실은 이 취소선 안에만 남아 있다.

## 그대로인 것

- 권한 요청 시점(`A-004`·`A-005` 직후 1회), `[나중에]` 재노출 없음.
- 리마인드 10:00 / 20:00 KST, 서버 KST 고정, 해외 체류자도 KST(`E-14`).
- 딥링크 생명주기(cold start 직행·미로그인 폐기·강제 업데이트 폐기·백그라운드 push).
- 도착 후 date 캔버스 진입, 마감분 편집 불가. **`P-05`로 왔는데 그사이 배경이 또
  바뀌었으면 현재 배경을 보여준다**(신규 한 줄).
- `E-01`~`E-07`, `E-10`~`E-14`, `E-17`·`E-18`. `E-11`의 "(5절)" 자기 참조도 그대로다.
- `E-09` TTL — `P-01`·`P-04`·`P-05` 6시간, 리마인드 1시간, 21:00 이후 리마인드
  도착 금지.

`v0.1` 개정이력의 "법적 요건 정리"는 이 판본에도 본문 절이 없다.
