# 푸시알림 인앱 알림 제어 정책 v0.3 (S-105)

## 요약

`S-105`(앱 사이드메뉴 > 알림 설정) 화면 정책이다. 날짜 **2026-10-31**, `v0.3`,
최종 편집 11-02(`DSN-B`). 상위 문서는 [[src-푸시알림-정책-v0.4]]이고, 발송
트리거·문구·묶음 규칙(`P-06`)은 그쪽이 단일 출처다. 이 문서는 **`S-105` 화면의 인앱
수신 제어만** 다룬다.

**새 계열의 첫 수집본이다.** `v0.2`(10-27)는 수집되지 않았고 개정이력으로만 안다.

| 버전 | 날짜 | 구조 |
|---|---|---|
| `v0.2` | 10-27 | 토글 A **그룹원 활동 알림 ON/OFF** + 토글 B 오늘의 캔버스·마감 안내 ON/OFF |
| `v0.3` | 10-31 | **오늘의 캔버스 알림**(리마인드 ON/OFF) + **알림 모아 받기**(활동 알림 묶음 ON/OFF). 활동 알림 끄기 토글과 확인 모달 폐기. OS 꺼짐·저장 실패 상태 정의 |

**나흘 만에 "끄기"가 "모아 받기"로 바뀌었다.** 10-27 회의가 이 문서 `v0.3`을 리뷰
항목으로 올리며 요약을 "그룹원 활동 알림과 리마인드 알림으로 나누어 제어 가능"이라
적었다([[src-회의록-2026-10-27-회의]]).

원문이 **"폐기 사항은 §6"**이라 적었는데 **수집본은 §4 예외 케이스에서 끝난다.**
`v0.2`에서 무엇이 왜 폐기됐는지 상세는 남지 않았다. 빨간 글씨 색도 수집 중 빠졌다.

## 왜 만들었나 — 범위가 다시 넓어진 이유

[[src-푸시알림-정책-v0.1]]은 **"앱 내 알림 설정 화면·개별 토글은 MVP 범위 외"**로
적었다. 이 문서가 그 결정을 뒤집고 이유를 적었다.

- 현 상태: 수신 거부 수단이 OS 전체 끄기뿐이다. 활동 알림은 상한이 없어 12인
  그룹이면 수신자당 최대 11건이 연달아 온다.
- **내부 테스트 관찰: "푸시가 없으면 앱 재진입이 거의 일어나지 않음" → 리텐션이
  푸시에 크게 의존.**
- 리스크: 짜증난 사용자가 **OS에서 전체 차단 1회 → 영구 이탈.** 복구 경로가 없다.
- 팀 내부 의견: 활동 알림을 끄기보다 **개수를 줄이고 싶다.**
- 정책 목표: **"'전체 끄기'를 유저가 선택할 이유 자체를 없앤다."**

**범위를 넓힌 계기가 사용자 관찰이 아니라 내부 테스트다.** 근거 데이터(재진입률
수치 등)는 적혀 있지 않다.

## 핵심 원칙

| # | 원칙 | 근거 |
|---|---|---|
| `P-1` | **앱 안에 "전체 끄기" 토글을 두지 않는다** | 전체 차단은 OS에만. 눈앞에 "전부 끄기" 선택지가 없게 (v0.2 유지) |
| `P-2` | **활동 알림은 끄는 대신 받는 방식만 고른다** | 리텐션 엔진이라 앱 안에서 끄는 수단을 주지 않는다 |
| `P-3` | **기본값은 현행과 같다** — 오늘의 캔버스 알림 ON, 모아 받기 OFF | 기존 사용자 체감 변화 없음 |
| `P-4` | **UI에 묶음 주기(10분)를 노출하지 않는다** | "10분마다 알림이 온다"로 읽혀 오히려 잦게 느껴질 수 있다 |

원칙 번호 `P-1`~`P-4`는 푸시 ID `P-01`~`P-06`과 접두사가 같다. 상위 문서가 이 원칙을
"S-105 정책 P-4"로 부른다([[screen-id-scheme]]).

## 화면

```
[상단 바]          <  알림 설정
[OS 알림 꺼짐 안내]  ← OS 알림이 꺼져 있을 때만
[토글 1]           오늘의 캔버스 알림
[토글 2]           알림 모아 받기
```

| | 토글 1 `오늘의 캔버스 알림` | 토글 2 `알림 모아 받기` |
|---|---|---|
| 보조 문구 | 아침 10시 오픈, 오후 8시 마감 알림을 보내드려요 | 그룹원 활동이 많아지면 모아서 한번에 보내드려요 |
| 대상 | `P-02` + `P-03` | `P-01` + `P-04` + `P-05` |
| 기본값 | **ON** | **OFF** |
| OFF | 리마인드 대상 제외 (상위 `E-23`) | 활동 1건 = 알림 1건 |
| ON | — | 첫 알림 즉시, 이후 10분 활동을 `P-06` 1건으로 |
| 전환 | 즉시 반영, 확인 없음 | 즉시 반영, 확인 없음 |

**토글 1 보조 문구의 "아침 10시 오픈"은 캔버스가 실제로 열리는 03:00과 다르다.**
`P-02` 문구는 "새벽 3시에 오늘의 새 캔버스가 열렸어요"다. 10시는 알림 시각이지
오픈 시각이 아니다.

### 저장

- **계정 단위로 서버에 저장한다.** 원문 근거가 **"단일 기기 로그인이라"**다 — 이
  제품이 단일 기기 로그인이라는 서술이 여기 있다([[account]]).
- 탈퇴 후 재가입은 기본값으로 초기화(상위 `E-13`).
- 두 토글은 서로 독립.

### 상태

| 상태 | 화면 |
|---|---|
| 기본 (OS 알림 허용) | 토글 2개 활성 |
| OS 알림 꺼짐 | 상단 안내 + 토글 2개 **비활성**(저장값만 표시). 상위 §3.3 예외 |
| 저장 실패 | 바꾸기 전으로 되돌리고 토스트 |

문구는 전부 **"(안)"**이다.

- OS 꺼짐 안내: 제목 `기기 알림이 꺼져 있어요`, 본문 `알림을 받으려면 기기 설정에서
  파르페 알림을 허용해 주세요`, 버튼 `[설정으로 이동]` → OS의 파르페 알림 설정.
- 저장 실패 토스트: `설정 저장에 실패했어요, 나중에 다시 시도해 주세요`. **공통 노출
  위치 y 121**을 따른다([[toast]]).

**권한을 거절했던 사용자가 앱 안에서 다시 켤 길이 처음 생겼다.** 다만 사용자가
`S-105`를 직접 찾아 들어와야 한다 — 프라이밍 `[나중에]` 재노출 없음은 그대로다.

## 함께 바뀌어야 하는 것

|---|---|
| `S-001` 앱 사이드메뉴 | `알림 설정` 항목 추가 → `S-105` |
| 개인정보처리방침 | 수신 거부 수단에 **`S-105`에서 리마인드 끄기** 추가. 활동 알림은 방식만 바꾸고 끄기는 OS뿐임을 구분 |
| 이용약관 | 알림 수신·거부 조항에 같은 취지 |
| 푸시알림 정책 v0.4 | §2.6, §3.3 예외, §3.4, §4.2·`E-15`·`E-16`, `E-23`~`E-28` — 10-31 반영 완료 |

담당은 전부 `DSN-B`다.
