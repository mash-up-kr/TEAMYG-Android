# 4/30 회의록 (2026-04-30)

## 요약

전체회의다. 2026년 4월 30일 21:30, Discord(`SPR-A`·`AOS-B`·`iOS-B` 불참).
**제품의 몸통이 처음 나온 회의다** — 사진을 찍고 누끼를 따서 친구들과 함께 쓰는
캔버스에 붙인다. 아파트 컨셉([[src-회의록-2026-04-23-회의]])은 언급되지 않는다.

회의 메모 표에서 팀원이 "꼭 들어갔으면 하는 기능"을 적었고, 그것을 **기능 우선순위
표 12행**으로 정리했다. **MVP에서 잘라낸 것과 그 근거가 처음 함께 적힌 문서다.**

## 팀원이 원한 기능 (요지)

- **누끼 + 스티커**를 "어떻게 힙하게 풀까", 친구와 편하게 공유하는 것이 UX의 핵심(`SPR-B`).
- **자동 배치** — "배치 잘 못하는 사람들은 혼자서 하라고 하면 피로 느낄 듯"(`DSN-A`,
  `AOS-A` 동의). 템플릿 여러 개. **한 달 달력에 오늘 올린 것 중 하나를 뽑아 넣기**
  — "너무 부가 기능이라 그냥 아이디어로 둡니다."
- 하루의 마지막에 쓰는 느낌으로 **알림**(`SPR-A`).
- 연속 사용 시 귀여운 스티커(7일차 🔥)(`iOS-C`).
- **사용자 지정 이미지 배경** — "인스스에도 그렇게 많이 하니까"(`DSN-B`, `AOS-A`).
- **누끼 테두리**로 스티커 느낌, **누가 만든 스티커인지 표시**, **비회원으로도
  남길 수 있으면 로그인 부담이 준다**(`AOS-A`).
- 공유·카카오톡 연동·인스타 포맷 저장으로 리텐션, **누끼 편집 기능** — "미적
  감각이 있는 사용자들이 쓰게 된다면 누끼가 본인 기준에 만족스럽지 않을 수
  있다", 기기 이동 시에만 소셜 로그인(`AOS-C`).

## 결정 사항 — 우선순위 표

| 기능 | 우선순위 | MVP | 원문 근거 |
|---|---|---|---|
| 촬영 | 0순위 (코어) | 포함 | 서비스의 시작점 |
| 배경 제거(누끼) | 0순위 (코어) | 포함 | **"누끼를 따서 인스타에 즉시 공유하기 좋은 감각적인 사진을 만들어주는 것이 서비스의 코어"** |
| 그룹 캔버스 공유 | 1순위 (필수) | 포함 | 친구들과 그룹을 만들어 하나의 캔버스에 누끼 사진을 올린다. **즉시성과 내부 공유성이 최우선** |
| 사용자 정의 배경 | 2순위 (확정) | 포함 | 필수는 아니므로 기술 검토 후 우선순위 |
| 작성자 표시 | 2순위 (확정) | 포함 | 스티커 제작자 확인은 필수 |
| 갤러리 내보내기 | 2순위 (확정) | 포함 | **인스타 직접 연동은 배제**, 기기 갤러리에 저장해 외부로 |
| 템플릿 | 2순위 (확정) | 포함 | 여러 템플릿 설정 |
| 누끼 테두리 효과 | 미정 | 미정 | 곡률·색상·두께 변수가 많아 기술 검토 후 |
| 비회원 접근 | 추후 검토 | 미정 | **작성자 표시와 그룹 기능이 모호해진다** |
| 연속 사용 보상 | 추후 검토 | **제외** | MVP 이후 긍정 검토 |
| 자동 배치 | 배제 | **제외** | **"기술적 문제로 MVP 단계에서는 아예 배제"** |
| 누끼 수동 편집 | 배제 | **제외** | **"'쉽고 느낌 좋은 사진을 만든다'는 기획 의도에 어긋나므로 배제. 수동 편집 대신 누끼 품질 자체를 높이는 방향으로 대체"** |

글 정리 쪽에는 표에 없는 한 줄이 더 있다 — **특정 시간 알림(제외): "하루의
마지막 알림 방식 대신, 아무 때나 즉시 찍고 올릴 수 있도록 기획을 변경하여
배제."**

## 템플릿과 달력

- **MVP 템플릿 범위**: 템플릿은 **배경 이미지**이고 개발은 누끼 이미지 위치만
  정한다. **최소 4개 최대 6개.** 수준은 흰 배경에 자유 배치(인 척).
- **마인크래프트 GUI를 템플릿으로 쓰는 안은 불가로 정리했다** — 사용 가이드라인이
  GUI 그래픽·텍스처를 자산·브랜드로 정의하고 EULA가 상업적 이용을 금지한다.
- **"생각보다 경쟁사가 많음"** — 비슷한 서비스 사례를 확인했다.
- **달력** — 아카이빙 역할. **당일 찍은 사진 중 마음에 드는 것을 골라 월간
  달력에 채운다(개인용, 친구 공유 X).** 템플릿과 다른 기능이라 개발팀 의견 필요.
- **테두리** — 리소스 절약을 위해 **고정 스펙 1개**(예: 흰색 3px) 방향. 자유도를
  준다면 "다 고정이고 색만". 머리카락 같은 지저분한 누끼의 스무딩은 결정 필요.

## 범위·정책에 미친 영향

**[[mvp-scope-limits]]에 근거가 달린 제외가 셋 생긴다** — 자동 배치(기술 문제),
누끼 수동 편집(기획 의도), 특정 시간 알림(즉시 업로드로 기획 변경). 기능정의서
계열은 이 근거를 옮겨 오지 않았다.

**그중 둘이 나중에 뒤집혔다.**

- **누끼 수동 편집** — 기획 의도에 어긋난다며 배제됐으나 v5에서 `C-104`(수동
  누끼 편집)가 신설됐고, [[src-C-104-누끼-편집-정책-v0.1]]이 **지운 배경을
  브러시로 되살리는 화면**으로 정의한다. 뒤집은 근거는 이 범위의 소스에 없다
  ([[topping-placement-pipeline]]).
- **특정 시간 알림** — [[src-기능정의서-v7]]이 **하루 두 번 리마인드
  푸시**(`P-02`·`P-03`)를 넣었다([[push-notification]]). 5월 14일에도 푸시는
  MVP에서 제외됐다([[src-회의록-2026-05-14-회의]]).

**외부 공유를 갤러리 저장으로 대신한 결정이 여기서 시작한다.** "인스타 직접 연동
배제"가 v7의 **"외부 공유 기능 미존재"**(저장 CTA 하나)로 이어진다
([[mvp-scope-limits]]).

**달력 아이디어는 형태를 바꿔 들어왔다.** "부가 기능이라 아이디어로 둔다"던
월간 달력이 뒤에 `C-201` 캘린더가 됐다([[src-C-201-캘린더-정책-v0.1]]). 다만
4/30의 달력은 **개인용**이고 `C-201`은 그룹 캔버스의 날짜를 고르는 화면이다.

**템플릿은 다른 뜻으로 살아남았다.** 4/30의 템플릿은 캔버스 배경 이미지 4~6종인데,
뒤의 "빈 토핑 템플릿"은 `G-001`에서 토핑이 없는 그룹 자리를 채우는 그래픽이다
([[infinite-parfait]]). 이름만 이어진다.

**대상 사용자 단서가 하나 더 나왔다** — "미적 감각이 있는 사용자", 그리고
인스타 스토리를 꾸미는 습관이 배경·저장 기능의 근거로 거듭 쓰였다.
