# 제품의 기원

## 정의

parfait가 **어떤 아이디어에서 출발해 지금의 형태가 됐는지**, 그 길에서 **무엇을
고르지 않았고 왜 그랬는지**를 모은 페이지다. [[purpose]]의 핵심 질문 1(무엇을
만드는가)과 3·4(무엇을 버렸고 무엇이 판단을 바꿨는가)에 답한다.

근거는 4월 1일부터 5월 28일까지의 회의록이다. **기능정의서 첫 판(05-16) 이전의
일이라 기능정의서 어느 판본에도 이 서술이 없다.**

## 04-01 — 아이디어 12안

첫 전체회의에서 각자 하나씩 던졌다 — 공공화장실 지도, **실시간 팀 동기화
포토·영상 위젯**(팀원 하나가 찍으면 나머지의 위젯 배경이 바뀐다), 음식 사진
체중 예측 AI, 웨이팅 매칭, 달리기 땅따먹기, 식재료 공동구매 매칭, 옷차림
리마인드, 소개팅·여행·카공 지도, 날씨·장소 음악 추천, 등산 루트.

**같은 그룹의 사진이 실시간으로 남의 화면에 뜨는 그림이 첫날 이미 있다** — 뒤의
그룹 캔버스와 닮았다. 다만 원본은 이 안이 채택됐다고 적지 않는다.

조건 하나가 함께 나왔다 — **"타겟이 너무 한정적인 마이너한 서비스는 피하고,
일상에서 가볍게 쓸 수 있는 서비스"**.

## 04-16 — 일상 기록으로 좁혔다

후보 넷을 비교했고 **장단점이 적힌 것은 둘뿐이다.**

| 후보 | 장점 | 우려 |
|---|---|---|
| **일상 기록 사진 앱** (채택) | 미션·알림으로 참여 유도, **MVP가 작고 LLM을 붙이기 좋다, 팀이 직접 쓴다**, **안드로이드 지원 = 셋로그 대비 차별점** | **비리얼·셋로그 아류 위험 → 핵심 차별점 필수**, 알림 피로, 직장인의 의지 저하, 서버 비용, 유행 종료 |
| 카공 카페 / 공공화장실 지도 | 체크인으로 콜드스타트 해결, 혼잡 예측 확장 | (빈 칸) |

결론 — **"친구 기반의 일상 기록 앱"**, 한 줄로 **"트렌디한 기록을 공유하며 친구와
함께 노는 일상 기록 플랫폼."** 코어는 일상 기록·트렌드·함께하는 재미, 리텐션은
랜덤 데일리 미션·협업 미션·트렌드 서플라이였다. 대상은 학생이었다
([[target-users]]).

**지도 계열을 고르지 않은 이유는 적혀 있지 않다.** 남은 단서는 일상 기록 쪽 장점
목록뿐이다. **경쟁 기준점이 비리얼·셋로그로 정해진 것이 이날이다.**

## 04-23 — 아파트, 그리고 소리 없는 폐기

**"멀리 있어도 한 건물에 사는 것처럼, 우리의 일상이 모여 아파트의 불을 밝히는
시간."** 영상을 올리면 내 방에 불이 켜지고, 업로드에 따라 방에 가구가 **자동으로**
차고, **24시 정각에 전체 소등**하고 하루를 앨범으로 남긴다. 노크(업로드 독촉),
방명록, CCTV 뷰.

**일주일 뒤 아파트는 언급조차 없이 사라졌다.** 컨셉을 바꾼 회의 기록이 없다 —
그 사이의 하위 페이지 "아이디어 방향성/컨셉 정하기"가 수집되지 않았다.

**뼈대 셋은 살아남았다.**

- **친구끼리만 보는 닫힌 공간** → [[group]](초대 코드로만 참여)
- **하루 단위로 끊고 앨범으로 남긴다** → `SY-001` 마감·이미지 추출. 경계는 00시로
  시작해 v4에서 03시가 됐다([[canvas]])
- **업로드가 공간을 채운다** → 캔버스에 토핑이 쌓이고 그룹 목록이 파르페 잔으로
  길어지는 그림([[infinite-parfait]])

## 04-30 — 제품의 몸통

**사진을 찍고 누끼를 따서 친구들과 함께 쓰는 캔버스에 붙인다.** 이 회의가
기능 우선순위 표 12행을 만들었고, **잘라낸 것과 그 근거가 처음 함께 적혔다.**
이때의 코어 문장은 **"누끼를 따서 인스타에 즉시 공유하기 좋은 감각적인 사진을
만들어주는 것"**이었다 — 편집이 중심이었다.

제외·보류된 것과 근거는 [[mvp-scope-limits]]에 있다 — 자동 배치(기술 문제),
누끼 수동 편집(기획 의도), 특정 시간 알림(즉시 업로드로 기획 변경), 인스타 직접
연동(갤러리 경유로 대체), 연속 사용 보상(MVP 이후).

**05-07이 기술 검토 결과 위에서 MVP를 확정했다.** 위치 지정 템플릿이 빠지고
자유 배치만 남았다. **비회원 접근(접속마다 임시 코드)이 MVP 방식으로 채택됐는데,
9일 뒤 05-16 초안은 소셜 로그인만 둔다** — 바꾼 기록이 없다([[account]]).

## 05-09 — 본질을 다시 맞췄다

**문제**: 팀원 사이에 **편집 앱 vs 소셜 앱 vs 아카이빙 앱**으로 시각이 갈렸다.
**원인**(원문): **"누끼 등 이미지 편집 기술 검증에 집중하다 보니, 서비스의 핵심
본질인 '친구와의 실시간 공유'라는 목적이 다소 흐려짐."**

결론 — **"친구들과 일상 사진을 캔버스에 공유한다."**

| 순위 | 무엇 |
|---|---|
| 0 | **친구와의 공유** |
| 1 | 사진 편집(누끼·테두리·크기·위치) — 공유를 위한 수단 |
| 2 | 실시간성 — 최소 기준 **5초 주기 갱신** |
| 3 | **싱글 플레이어 모드** — 친구 없이도 혼자 캔버스를 꾸민다 |

**04-30의 "누끼가 코어"를 뒤집었다** — 편집을 수단으로 내렸다.

**싱글 플레이어 모드는 이후 어느 소스에도 나오지 않는다.** 지금의 제품은 그룹에
들어가야 캔버스가 생긴다. 폐기 서술도 없다.

## 05-16 — 기능정의서는 AI 초안에서 출발했다

원문 첫 줄 — **"클로드가 도와줬어.. 여기서 같이 수정하자 처음부터 만들면 힘듦."**
초안을 AI로 만들고 회의에서 고쳤다. 화면 목록과 ID 체계(A/G/C/S/SY)가 2주 뒤
[[src-기능정의서-v2]]와 같다([[screen-id-scheme]]).

**그날 check point가 "정의 필요" 다수에 답했으나 표의 칸은 고치지 않았다** —
온디바이스 누끼, 폴링, 초대 코드 8자, 닉네임 정책, 그룹장 삭제, soft delete.
v2~v4의 비고에 남은 "정의 필요" 상당수는 **AI 초안의 문구가 그대로 남은 것**으로
읽힌다([[spec-version-history]]).

## 05-24 — 정체성을 문장으로 고정했다

회의 목적이 원본 머리에 있다 — **외부에서 '사진 편집 앱'으로 오해하는 상황을
타개하고 '공유 캔버스 SNS'로서의 정체성을 맞춘다.** 인터뷰 종합이 근거다
([[target-users]]).

- **한 줄 정의(확정)**: **"파르페는 친구들과 공유 캔버스에 일상을 스티커로 만들어
  붙이는 서비스다."** 필수 키워드 — 그룹 / 동시성 / 하루 단위 / 캔버스(누적).

| 파르페는 ___ 이다 | 파르페는 ___ 이 아니다 |
|---|---|
| 사이버 다꾸 | 사진 편집 앱 |
| 같이 꾸미는 일상 캔버스 | 누끼만 따주는 앱 |
| | 셋로그 |
| | 예쁜 필터나 스티커 제공 앱 |
| | 사진 스타일 변환 앱 |
| | 공유 앨범 (같이 꾸미는 느낌 추가 필요) |
| | 일기 — 하루 정리가 아니라 언제든 들어와 꾸미는 것 |

**"만들지 않는 것"이 제품 정체성 수준에서 적힌 유일한 자리다.**

1차 UT 가설(07-16)은 이를 **"친구 그룹과 매일 리셋되는 공유 캔버스에 일상을 쌓는
서비스"**로 다시 적었고, 리스크로 **사진 편집앱 오인**을 꼽았다
([[src-회의록-2026-07-16-회의]]). 실제로 1차 첫인상에서 "편집 느낌"이 둘, 2차
한 문장 설명에서 **"누끼 셋로그"**가 둘 나왔다([[src-회의록-2026-08-27-회의]]) —
**Is Not 표의 첫 줄과 셋째 줄이 사용자 입에서 그대로 나왔다.**

## 05-28 — 이름

05-21에 후보를 단톡방 투표로 정하기로 했고, 05-28에 **파르페(parfait)**로
확정했다. 뜻풀이는 **"완전한, 완벽한" + "아이스크림에 과일 등을 쌓아 만든
디저트"**. 이 이름에서 디저트 어휘(토핑, 쌓기, 파르페 잔)가 자랐다([[parfait]]).

## 고르지 않은 대안과 이유

| 대안 | 언제 | 결과 | 이유 |
|---|---|---|---|
| 지도 계열(카공 카페·화장실) | 04-16 | 탈락 | **적히지 않음.** 일상 기록 쪽 장점(작은 MVP, 팀이 직접 사용, LLM)만 남음 |
| 나머지 아이디어(매칭·공동구매·옷차림 등) | 04-16 | 탈락 | 비교표에 오르지도 않음 |
| 트렌드 모듈·랜덤 미션·협업 미션 | 04-16 → 04-30 | 소리 없이 사라짐 | **적히지 않음** |
| 스트릭(연속 사용 보상) | 04-30 | MVP 제외 | "MVP 이후 긍정 검토". 10-06에 다시 보류 — 첫 타자 문제엔 효과 없음([[first-upload-problem]]) |
| **아파트 컨셉** | 04-23 → 04-30 | 소리 없이 사라짐 | **적히지 않음.** 회의 기록 누락 |
| 마인크래프트 GUI 템플릿 | 04-30 | 불가 | **EULA가 상업적 이용 금지** |
| 위치 지정 템플릿 4~6종 | 04-30 → 05-07 | MVP 제외 | "위치 배치 기능은 MVP에서 제외" — 동어반복 |
| 비회원 접근 | 05-07 → 05-16 | 소셜 로그인으로 교체 | **적히지 않음** |
| 싱글 플레이어 모드 | 05-09 | 소리 없이 사라짐 | **적히지 않음** |
| "사진 편집 앱" 정체성 | 05-09, 05-24 | Is Not 표 첫 줄 | 공유라는 본질이 흐려짐 |

**절반이 넘는 행이 이유 없이 사라졌다.** [[purpose]]의 규약("답 없이 사라진
서술을 해소로 읽지 않는다")에 따라 미결로 남긴다.

## 정체성은 지금도 시험받는다

**무한 파르페 은유가 사용자에게 읽히지 않는다**는 반응이 두 UT 연속 나왔고
("쌓아서 뭘 하나", "왜 파르페지?"), 2차 UT는 이것을 **"UT로 못 고침. 제품 결정
사항"**으로 넘겼다. 런칭 뒤 Figma Development 페이지에서 팀은 파르페를 없애는
안까지 검토하고 **"무한파르페를 없애는 건 너무 서비스 정체성을 흐린다"**는 근거로
**유지**했다 — 사용자 이해도가 반대 근거였다
([[src-figma-주석-Development-페이지]], [[infinite-parfait]]).

## 미결

- **아파트 컨셉을 버리고 누끼 캔버스로 옮긴 계기가 없다.**
- **싱글 플레이어 모드의 행방** — 3순위였다가 소리 없이 사라졌다.
- **비회원 접근이 소셜 로그인 전용으로 바뀐 근거가 없다.**
