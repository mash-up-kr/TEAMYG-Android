# 화면 ID 체계

## 정의

기능정의서가 화면을 가리키는 식별자다. `접두사-세자리숫자` 꼴이다(`A-001`,
`C-103`, `SY-003`).

이 위키는 화면을 **항상 ID로 지칭한다**. 화면명은 판본마다 바뀌지만 ID는 대체로
유지되므로 판본 비교의 기준점이 ID이기 때문이다. 규칙의 출처는 [[purpose]]의
지역 규약이다. v4가 화면명 여럿을 한꺼번에 바꾸면서(누끼 사진 → 토핑) 이 규칙의
값어치가 드러났다 — 이름은 셋 바뀌었지만 ID는 하나도 바뀌지 않았다.

## 접두사

| 접두사 | 분류 | 범위 |
|---|---|---|
| `A-` | Auth | 스플래시, 소셜 로그인, 최초 진입 경로 선택, 그룹 참여·생성 |
| `G-` | Group | 그룹 목록, 그룹 진입 |
| `C-` | Canvas | 캔버스 열람, 토핑 투입·배치, 배경 변경, 과거 캔버스 |
| `S-` | Sidebar | 앱 레벨 메뉴와 그룹 레벨 메뉴 |
| `SY-` | System | 스케줄러가 돌리는 자동 동작 |

`C-`는 세 자리의 백 단위로 다시 갈린다 — `C-0xx` 캔버스 본체, `C-1xx` 토핑 투입과
최초 배치, `C-2xx` 과거 캔버스 열람, `C-3xx` 편집 모드(배경과 토핑 수정). `S-`는
`S-0xx` 앱 레벨, `S-1xx` 그룹 레벨로 갈린다.

## 접두사와 분류가 어긋나는 경우

접두사는 ID의 일부고 분류 열은 별개다. 세 판본 모두에서 `SY-002`(마감된 갤러리
저장)는 ID 접두사가 `SY-`인데 분류 열은 `Canvas`다. 사용자가 누르는 저장 버튼이라
분류상 캔버스 쪽이지만 마감이라는 시스템 사건에 딸려 있어서로 보인다.
**접두사를 분류로 읽지 않는다.**

## 화면명은 바뀐다 — ID로 따라간다

| ID | v2 | v3 | v4 |
|---|---|---|---|
| `C-301` | 캔버스 배경 변경 | 파르페 편집 모드 진입 | (유지) |
| `C-305` | 수정 완료 | 누끼 사진 편집 | **토핑 편집** |
| `C-306` | (없음) | 누끼 사진 테두리 편집 | **토핑 테두리 편집** |
| `C-202` | 작업한 친구 닉네임 노출 | (유지) | **작업한 그룹원 닉네임 노출** |

`C-305`는 v2와 v3 사이에서 **서로 관계없는 화면이 같은 번호를 쓴 완전한
재사용**이다. 이 ID를 언급할 때는 판본을 함께 적는다. v3와 v4 사이의 `C-305`는
같은 화면의 개명이다.

`C-301`은 화면명과 범위가 바뀌었을 뿐 "편집의 진입점"이라는 자리는 유지된다.
전체 비교는 [[spec-version-history]]에 있다.

## 사라진 ID

- **`C-002`** — v2에서 여섯 화면이 진입 경로로 참조했으나 표에 정의된 적이 없다.
  v3가 화면 자체를 제거했다. 번호는 다시 쓰이지 않았다.
- **`C-107`·`C-108`** — v2의 사진 삭제·위치 수정. v3의 `C-305`로 흡수됐다.

## 빈 칸 읽는 법

기능 정의 표의 빈 칸은 "제약 없음"이 아니라 **"미정"**이다. 이 구분을 흐리면
공백이 결정으로 승격된다.

- `C-304`(배경 색 설정)는 v2부터 세 판본 연속으로 사용자 액션·시스템 동작 열이
  비어 있다.
- v4에서 `S-103`의 분기조건과 비고가 **채워져 있다가 비워졌다.** 빈 칸이 된 경위가
  다르지만 읽는 법은 같다 — 미정이다. 답 없이 사라진 서술은 해소가 아니다
  ([[purpose]]).

## 행이 통째로 빠지는 경우

v4 캡처에서 `G-002`(그룹 진입) 행이 잡히지 않았다. 다른 화면들이 참조하므로 존재는
확실하지만 v4에서 무엇이 바뀌었는지는 알 수 없다. 원본 전사본은 v3 값으로 채우고
비고에 표시해 뒀다 — [[src-기능정의서-v4]]와 [[open-questions]]에 있다.
