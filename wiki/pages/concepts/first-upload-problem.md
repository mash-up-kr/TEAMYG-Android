# 첫 업로드 부재

## 정의

**그날의 캔버스에 아무도 첫 토핑을 올리지 않는 문제**와, 그것을 풀려고 낸 안들의
판정이다. 런칭 뒤 처음으로 **사용자 문제가 문제 정의의 형식으로 적힌** 자리다
([[purpose]] 질문 2·3).

계기는 실사용 수치다 — **10/5 업로드 0건.** 같은 날 DAU는 iOS 18 + Android 5 =
23이었다([[src-회의록-2026-10-06-회의]]).

## 문제 정의 (10-06 현행, [[src-회의록-2026-10-06-회의]])

원본이 상자로 강조한 문장이다.

> **매일 빈 캔버스로 시작 → 첫 타자만 부담을 짐 → 아무도 안 올림.**
> **목표: 올릴 게 없어도 올리게 만들기. 푸시는 안 씀.**

**이 정의는 조사 결과가 아니라 팀의 진단이다.** 근거는 팀이 쓰면서 본 것과 수치
하나다([[target-users]]).

## 원인 넷

| 원인 | 원문 | 무엇에서 왔나 |
|---|---|---|
| **올릴 사진이 없다** | **"3시~3시에 찍은 사진만 가능"**, 출근 사진 정도가 전부 | 갤러리 시간 창(아래) |
| **첫 타자가 민망하다** | "예쁜 걸 올려야 할 것 같은데 나한테 예쁜 게 없음" | 인터뷰의 "완벽한 피드 전시 피로"와 같은 결 |
| 그룹과 무드가 안 맞는다 | 무드가 안 맞으면 더 올리기 어려움 | — |
| **들어올 계기가 없다** | **"푸시는 많으면 그냥 끔"** | 푸시 피로 |

첫째 원인은 **제품이 스스로 만든 제약**이다. 갤러리 "오늘 사진" 디폴트는 05-24에
**"하루 단위로 리셋되는 무드를 강제한다"**는 이유로 정했고
([[src-회의록-2026-05-24-회의]]), 05-28에 기간 제한이 붙었으며
([[src-회의록-2026-05-28-회의]]), 06-04의 03시 경계와 묶여 `C-102`의 시간 창이
됐다([[src-회의록-2026-06-04-회의]], [[topping-placement-pipeline]]).

둘째 원인은 **닫힌 그룹으로 풀려던 불편이 빈 캔버스 앞에서 되살아난 것**으로
읽힌다 — 위키의 해석이고 원본이 둘을 잇지 않았다.

## 안 열 개와 판정

| 안 | 판정 | 이유 |
|---|---|---|
| A. **단톡 공유** — 텍스트를 올린 뒤 카톡으로 캔버스 링크 | **기각** (정리본 표에서는 보류) | 제안자가 B·C 우선으로 접음 |
| B. **`C-001` Empty state 개편** — 더미 사진(예쁜 것 + 일부러 별로인 것)으로 「뭐든 올려도 된다」를 보여주고 쌓기 버튼 위계를 올림 | **추진** | 공수 무난. 개수·랜덤 여부 미정 |
| C. **홈 화면 위젯** — 사진은 모자이크/블러/실루엣, 닉네임 + 시간대만 | **추진, iOS만** | Android는 개발 난이도로 제외 |
| D. **N개 올라오기 전까지 블라인드** | **기각** | 꾸미려는 사용자에게 당혹스러운 업데이트 |
| 찌르기 | 보류 | 푸시 기반이라 방침과 충돌 |
| 시간 기반 알림(듀오링고식) | **기각** | **푸시 지양** |
| 연속 일수 스트릭 | 보류 | 첫 타자 문제엔 효과 없음 + 구조 대개편 |
| 오늘의 주제 | 보류 | 효과 약함 |
| 무드별 그룹 나눠 쓰기 | 보류 | UX_1로 잡은 직관성이 다시 깨질 수 있음 |
| 공개 피드(인스타 스토리처럼 남의 것도 봄) | 참고 기록만 | 무드 불일치 해소용이나 공수가 위젯 이상 |

**판정의 축은 둘이다 — 푸시를 늘리지 않는다, 그리고 공수.** 세 안(찌르기, 시간
기반 알림, 그리고 원인 넷째의 "푸시는 많으면 끔")이 같은 방침에 걸렸다.

**같은 달 말의 정책서는 반대쪽 판단을 적었다.**
[[src-푸시알림-인앱-알림-제어-정책-v0.3]]은 **"푸시가 없으면 앱 재진입이 거의
일어나지 않음 → 리텐션이 푸시에 크게 의존"**(내부 테스트)을 근거로 활동 알림을
앱 안에서 끄지 못하게 했다. 푸시를 늘리지는 않되 줄이지도 않는다는 뜻으로 읽을 수
있으나, 두 문서는 서로를 언급하지 않는다([[push-notification]]).

## 03시 갤러리 창 해제 — 실험

원본은 **"3시~3시 사진 규칙이 지킬 가치가 있는 정체성인가, 바꿔도 되는
장치인가"**를 물었다. **「왜 3시까지냐」에 답하기 어렵고 타협한 느낌이 강하다**는
의견에 따라 **"갤러리 시간 제한을 일단 없애보고, 써보면서 판단 (안 되면
되돌림)"**으로 정했다([[src-회의록-2026-10-06-회의]]).

- [[src-회의록-2026-10-13-회의]] — Android·iOS 모두 **사진 앨범 시간 제한 제거**
  완료, 디자인이 안내 문구 수정(`UX_11`).
- [[src-회의록-2026-10-20-회의]] — 10-06에 4위였던 이 건은 이미 배포돼 우선순위
  목록에서 빠졌다.

**캔버스 마감·생성 경계 03:00 자체는 그대로다.** 바뀐 것은 어떤 사진을 고를 수
있느냐뿐이다 — **하루 경계와 갤러리 사진 범위가 처음으로 분리됐다**([[canvas]]).

**"안 되면 되돌림"의 판단 기준과 기한이 없고, 되돌렸다는 기록도 확정했다는
기록도 없다.** 그래서 이것을 범위의 확정 변경이 아니라 실험으로 둔다
([[mvp-scope-limits]]).

## 추진한 두 안의 진행

| 안 | 담당 (10-10) | 10-06 순위 | 10-20 순위 | 상태 |
|---|---|---|---|---|
| `C-001` Empty 더미 배경 | 디자인 `DSN-B` | 9위 | **5위** | 디자인 일정은 텍스트 개발 기간을 보고 정함. 배포 기록 없음 |
| 홈 화면 위젯 (iOS) | 디자인 `DSN-A` | 10위(PoC) | **6위** | 같음. 배포 기록 없음 |

위젯의 형태는 10-06이 정했다 — **1:1, 그룹을 통틀어 최근 토핑 1개**(그룹명·
닉네임·타임스탬프·토핑), 사진은 모자이크/블러/실루엣. 그룹별 위젯은 제약으로
어렵다고 적었다.

**두 안 모두 10-20에서 순위가 올랐으나 그 위에 새 넷**(푸시 인앱 제어·강제
업데이트·카메라 줌·공지사항)**이 끼었다**([[src-회의록-2026-10-20-회의]]). 11월
회의록에는 두 안의 진행이 다시 나오지 않는다.

## 이 문제가 범위에 남긴 것

- **범위를 넓힌 결정** — 03시 갤러리 창 해제(실험).
- **범위 밖으로 민 것** — 블라인드, 시간 기반 알림(근거: 푸시 지양), Android 위젯
  (근거: 개발 난이도), 공개 피드(근거: 공수). 단톡 공유·찌르기·스트릭·오늘의
  주제·무드별 그룹은 보류다. 목록은 [[mvp-scope-limits]]에 합쳤다.
- **그룹 내 무드 불일치는 이 건 해결 뒤로 미뤘다.**

**이 문제는 런칭 전 경고와 이어진다.** 인터뷰의 "특별한 날에만 쓰는가" 위험
신호, 그리고 런칭 직후 팀의 관찰 **"사람들이 생각보다 매일 사용하지 않음"**
([[src-회의록-2026-09-17-회의]])이 같은 방향이다 — 매일 리셋되는 캔버스는 매일
누군가 첫 장을 올려야 굴러간다([[target-users]]).
