# 푸시 알림

## 정의

앱 바깥의 OS 시스템 푸시다. ID 축은 `P-`다([[screen-id-scheme]]).

**앱 안에서 뜨는 [[toast]]와 다르다.** Toast는 앱을 보고 있는 사람에게 캔버스 위에서
뜨고, 푸시는 앱을 닫아 둔 사람에게도 간다.

**정본은 푸시 전용 정책 계열이다.** [[src-푸시알림-정책-v0.1]](08-30)이 문구·예외
18종까지 정의했고, [[src-기능정의서-v7]](09-21)의 `P-01`~`P-03` 세 행은 그 요약본이다
— v7이 "정책과 문구만 정의한다"면서 빠뜨린 문구와 예외 전문이 v0.1에 있었다. 현행은
[[src-푸시알림-정책-v0.4]](10-31)이고, 앱 안 수신 제어(`S-105`)는
[[src-푸시알림-인앱-알림-제어-정책-v0.3]]으로 갈라졌다. 발송 트리거·문구·묶음의
**단일 출처는 v0.4**다.

전용 화면 디자인은 없다 — OS 푸시라서다. `S-105` 알림 설정 화면만 앱 안에 있다.

## 어디서 왔나 — 뺐다가 넣었다가 줄였다

| 05-14 | **"푸시알림 (MVP에서 제외)"**. 후보 시나리오는 "아무도 안 올릴 때 / 너무 활발할 때 / 올리면서 찌르기 유도"([[src-회의록-2026-05-14-회의]]) |
| 08-27 | **2차 UT에서 요구가 사용자 입으로 나왔다** — **"비리얼처럼 푸시 알림이 오면 좋겠다"**, **"친구가 올리면 알림이 오면 그때 올릴 것"**([[src-회의록-2026-08-27-회의]]) |
| 08-30 | 정책 v0.1 — 3종, 개별 발송·상한 없음, 앱 안 알림 설정은 **MVP 범위 외** |
| 09-03 | UT 후속 2번으로 개발. 서버는 토핑 추가 알림 완료, 아침·저녁 리마인드 구현 중([[src-회의록-2026-09-03-회의]]) |

| 10-06 | 팀 방침 **"푸시는 안 씀" / "푸시 지양"** — 찌르기 보류, 시간 기반 알림 기각의 근거. 사용자 관찰 **"푸시는 많으면 그냥 끔"**([[src-회의록-2026-10-06-회의]]) |
| 10-07~13 | **배경 변경 푸시 추가**, 문구 "올리러 → 쌓으러", "토핑 → 사진"([[src-회의록-2026-10-13-회의]]) |
| 10-27~31 | 인앱 제어 리뷰 → `S-105` v0.3, 푸시 정책 v0.4(**모아 받기**)([[src-회의록-2026-10-27-회의]]) |
| 11-10 | 인앱 제어 **다음 주 배포**(1.3.0)([[src-회의록-2026-11-10-회의]]) |

**뒤집힌 계기가 둘 다 사용자 쪽에서 왔다.** 넣은 계기는 2차 UT 발화이고, 줄인
계기는 런칭 뒤 "너무 많다"는 반응이다. 다만 05-14 제외를 공식으로 뒤집는 결정 문장은
어느 회의록에도 없다([[open-questions]]).

**10-06 "푸시 지양"은 새 푸시를 만들지 않는다는 방침이다** — 기존 활동 알림을 줄인다는
뜻이 아니다. 그 뒤에도 배경 변경(`P-05`)·텍스트(`P-04`)가 더해졌다. 활동 알림은
[[src-푸시알림-인앱-알림-제어-정책-v0.3]]이 **"리텐션 엔진"**이라 부르는 것이다.

## 여섯 종류 (v0.4 현행, [[src-푸시알림-정책-v0.4]])

| ID | 무엇 | 트리거 | 진입 | 제목 | 본문 |
|---|---|---|---|---|---|
| `P-01` | 사진 등록 | `C-106` 사진 배치 **확정 저장** | `C-001` | `{그룹명} 파르페에 체리 하나 톡!` | `{그룹 내 닉네임}님이 새 사진을 쌓았어요` |
| `P-02` | 오전 리마인드 | 스케줄러 **10:00 KST** | `G-001` | `새벽 3시에 오늘의 새 캔버스가 열렸어요` | `오늘의 파르페를 먼저 쌓아볼까요?` |
| `P-03` | 저녁 리마인드 | 스케줄러 **20:00 KST** | `G-001` | `새벽 3시에 오늘의 캔버스가 마감돼요` | `오늘의 파르페를 완성하러 가볼까요?` |
| `P-04` | 텍스트 등록 | 텍스트 추가 확정 저장 — **진입점·화면 코드 미정** | `C-001` | `{그룹명} 파르페에 체리 하나 톡!` | `{그룹 내 닉네임}: {미리보기}` |
| `P-05` | 배경 변경 | 배경을 **변경한 시점** | `C-001` | `{그룹명} 파르페에 체리 하나 톡!` | `{그룹 내 닉네임}님이 배경을 바꿨어요` |
| `P-06` | 활동 묶음 | 묶음 윈도우 종료 (**모아 받기 ON 수신자만**) | `C-001` | `{그룹명} 파르페에 체리가 또 톡!` | `그사이 새 소식이 {N}개 쌓였어요` |

- **발송 대상은 본인 제외 전체 그룹원**이다. 리마인드는 **가입 그룹 1개 이상 + 알림
  권한 허용 + 유효 토큰** 셋을 갖춘 사람.
- **신규 등록만 트리거다.** 업로드 후 편집(배치·테두리)·텍스트 수정·삭제는 보내지
  않는다(`E-19`·`E-20`).
- **번호 원칙** — 기존 `P-01`~`P-03`은 유지하고 신규는 뒤에 붙인다. "서버·클라이언트에서
  이미 쓰는 번호를 바꾸지 않기 위함."
- 작성자가 탈퇴·나가기하면 닉네임 자리는 `누군가`.

**`P-01`의 트리거 화면 ID가 가리키는 화면이 바뀌었다.** v0.4는 여전히 "`C-106` 사진
배치"라 적는데, UX_1(10/15 배포) 뒤 Figma에서 `C-106`은 **텍스트 추가**이고 사진 배치는
`C-105-Arrange`다([[src-figma-주석-캔버스-C-SY]], [[screen-id-scheme]]). `P-05`의
트리거로 적힌 `C-304` 배경 탭도 같은 개편에서 `C-301`로 옮겨졌다. 정책서가 화면 ID를
따라가지 못한 상태다.

### 문구가 바뀐 이유 — 브랜드 동사와 "사진"

v0.1의 원래 문구는 `P-01` `{그룹명} 파르페에 체리 얹을 타이밍!` / `…님이 새 토핑을
쌓았어요`, `P-03` 본문 `오늘의 마지막 토핑을 올리러 가볼까요?`였다
([[src-푸시알림-정책-v0.1]]).

- **"올리러 → 쌓으러"**는 브랜드 동사 규칙(**쌓기 — `올리다` 사용 금지, 푸시 문구에도
  적용**, [[src-common-서비스-공통-규칙-2026-09-20]])을 어긴 **QA 결함**으로
  처리됐다(`[QA-11]`, [[src-회의록-2026-09-29-회의]]). 현행 `P-03` 본문은 "완성하러"다.
- **"토핑 → 사진"**(v0.2, 10-07). 은유 어휘 "토핑"을 사용자에게 보이는 문구에서 뺐다.
  리마인드·권한 모달은 사진·텍스트를 아우르게 목적어를 **"파르페"·"캔버스를
  꾸미면"**으로 바꿨다. **푸시 문서 밖에도 적용되는 용어 변경인지는 없다**
  ([[open-questions]]).
- `P-01` 제목 교체("얹을 타이밍" → "하나 톡")는 **어느 개정이력에도 없다.**

### 텍스트 미리보기 (`P-04`)

텍스트 기능 자체는 [[text-topping]]에 있다.

텍스트는 이미지화하지 않고 그대로 저장하므로 내용을 보여줄 수 있다. **메신저
형식(닉네임: 내용)으로 "누가 말을 걸었다"로 읽히게 해 답장하러 들어오는 부담을
낮춘다**가 설계 의도다. 서버가 줄바꿈·연속 공백을 공백 1개로 접고 trim한 뒤
**grapheme cluster 기준 11자 이하면 그대로, 넘으면 앞 10자 + `…`**. 이모지가 중간에서
잘려 `�`가 나오는 것을 막으려는 기준이다(`E-21`).

## 묶음은 수신자가 고를 때만 (v0.4 현행, [[src-푸시알림-정책-v0.4]])

**기본값은 여전히 "1 업로드 = 1 발송, 묶음·상한·쿨다운 없음"이다.** 12인 그룹에서
11명이 쌓으면 11건이 간다(`E-08`). 이 기본값을 둔 근거는 v0.1에도 v0.4에도 없다.

`S-105`의 **'알림 모아 받기'를 켠 수신자에게만** `P-06`이 적용된다. 기본은 OFF다.

| 항목 | 내용 |
|---|---|
| 대상 | `P-01`·`P-04`·`P-05`. **리마인드는 묶지 않는다** |
| 윈도우 | **(수신자, 그룹, 캔버스 date)**마다 독립, **10분**. UI에 노출하지 않는다 |
| 규칙 | 열린 윈도우가 없으면 **첫 활동은 즉시 개별 발송**하고 윈도우를 연다. 끝나면 누적분을 `P-06` 1건으로. 누적 0이면 안 보낸다 |
| 결과 | 활동이 이어져도 **수신자당 10분에 최대 2건** |
| TTL | 1시간(원문 "제안") |

**`N`의 집계와 표기 상한은 서버 회신 대기다**([[open-questions]]). 윈도우가
03:00을 걸치면 끊고 이전 date로 보낸다(`E-24`).

**UI에 10분을 쓰지 않는 이유가 적혔다** — "10분마다 알림이 온다"로 읽혀 오히려 잦게
느껴질 수 있다. 09-21 회의의 "한 시간에 N개 이상이면 묶기" 안이 이 형태로 정리됐다.

## 앱 안에서 끌 수 있는 것은 리마인드뿐 (v0.3 현행, [[src-푸시알림-인앱-알림-제어-정책-v0.3]])

`S-105`(앱 사이드메뉴 > 알림 설정)의 토글은 둘이다.

| 토글 | 대상 | 기본값 | 무엇을 하나 |
|---|---|---|---|
| `오늘의 캔버스 알림` | `P-02`·`P-03` | **ON** | **끈다.** OFF면 토큰이 유효해도 리마인드 대상에서 빠진다(`E-23`) |
| `알림 모아 받기` | `P-01`·`P-04`·`P-05` | **OFF** | 끄지 않고 **받는 방식만** 바꾼다 |

설정은 **계정 단위로 서버에 저장**한다 — 근거가 **"단일 기기 로그인이라"**다
([[account]]). 두 토글은 독립이고 즉시 반영, 확인 없음.

**활동 알림은 앱 안에서 끌 수 없다.** 끄기는 OS 설정뿐이다. 원칙이 직접 적었다 —
**"앱 안에 '전체 끄기' 토글을 두지 않는다"**, **"활동 알림은 리텐션 엔진이라 앱 안에서
끄는 수단을 주지 않는다"**, 목표는 **"'전체 끄기'를 유저가 선택할 이유 자체를
없앤다."**

### 범위가 다시 넓어진 이유

v0.1은 **"앱 내 알림 설정 화면·개별 토글은 MVP 범위 외"**로 적었고 근거가 없었다.
10-31에 뒤집혔고 이번에는 근거가 붙었다.

- 내부 테스트 관찰: **"푸시가 없으면 앱 재진입이 거의 일어나지 않음"** — 리텐션이 푸시에
  크게 의존한다.
- 리스크: 짜증난 사용자가 **OS에서 전체 차단 1회 → 영구 이탈.** 복구 경로가 없다.
- 팀 의견: 활동 알림을 끄기보다 **개수를 줄이고 싶다.**

**뒤집은 근거는 내부 테스트이고 수치는 없다.** 사용자 발화("알림이 너무 많아서 끄게
됨")는 09-21 회의에 먼저 있었다.

**나흘 만에 "끄기"가 "모아 받기"로 바뀌었다.** 10-27판(v0.2)은 **그룹원 활동 알림
ON/OFF** 토글과 확인 모달이 있었고 10-27 회의 요약도 "나누어 제어 가능"이었다. 10-31판이
그 토글을 폐기했다. **폐기 상세를 담았다는 §6은 수집본에 없다**([[open-questions]]).

## 권한은 프라이밍 모달로 받는다

`A-004`(초대 코드 참여)와 `A-005`(새 그룹 생성) 직후 **1회** 노출한다.

- 현행 문구: 제목 `그룹원이 캔버스를 꾸미면 알려드릴까요?`, 본문 `그룹원의 새 소식과
  캔버스 마감 안내를 받을 수 있어요.` 원문이 **"클라이언트 문구라 앱 업데이트
  필요"**라고 표시했다.
- **`[나중에]`면 OS 다이얼로그를 호출하지 않고 재노출도 없다.** 거부하면 토큰이 없어
  발송 시도 자체를 하지 않는다. 앱 안의 재요청 배너·모달도 없다.

### 다시 켜는 경로

**OS 설정이 처음부터 경로였다.** v0.1이 "기기 설정 > 알림 > 파르페"를 `S-004`(약관)
화면과 개인정보처리방침 본문에 안내한다고 적었다([[src-푸시알림-정책-v0.1]]).

**`S-105`가 앱 안 입구를 하나 더 만들었다.** OS 알림이 꺼진 채 들어오면 상단에
`기기 알림이 꺼져 있어요` 안내와 **`[설정으로 이동]`** 버튼이 뜨고 두 토글은 비활성으로
저장값만 보인다(문구는 전부 "(안)"). 팝업이 아니라 설정 화면의 상태 표시라서 "앱 안
재요청 없음"의 **예외로 허용**됐다. 사용자가 `S-105`를 스스로 찾아 들어와야 한다는
점은 같다.

**모달 본문은 여전히 "알림은 언제든 기기 설정에서 끌 수 있어요"다** — 리마인드는 이제
앱에서도 끄는데 모달은 기기 설정만 가리킨다([[open-questions]]).

## 열람 중에도 보낸다 — 억제 규칙 폐기 (v0.4 현행, [[src-푸시알림-정책-v0.4]])

v0.1은 둘을 억제했다 — 포그라운드로 해당 그룹 `C-001`을 보고 있으면 OS 배너 대신 **상단
알림 띠**(`E-15`), 사진 올리기·본인 사진 수정 중이면 인앱 배너 억제(`E-16`).

**둘 다 운영에서 동작하지 않았다**(09-20 백로그,
[[src-common-서비스-공통-규칙-2026-09-20]]). v0.4는 고치지 않고 **규칙을 지웠다** —
운영이 동작하던 쪽을 정책으로 올렸다.

- 폐기 이유(`E-16`): **"억제하면 쌓기를 마친 뒤 알림이 남지 않아, 사진을 눌러봐야만
  새 활동을 알 수 있어 더 번거롭다."**
- 상단 알림 띠(`E-15`) 쪽 폐기 이유는 없다.

**그래서 캔버스를 보고 있는 그룹원도 OS 푸시를 받는다.** 같은 사건에 [[toast]]도 뜨는지는
여전히 어느 문서에도 없다([[open-questions]]).

## 딥링크와 도착

- **종료 상태**: `A-001` → 토큰·버전 체크 → **목적지로 직행**, 세션에 저장해 **1회
  소비**한다. 백그라운드면 현재 스택 위에 push.
- **미로그인이면 폐기**한다. 로그인 후 `G-001` 일반 진입. **강제 업데이트 대상이어도
  폐기**한다.
- 날짜가 넘어갔어도 **푸시의 date 캔버스로 진입**한다. 마감분은 편집 불가. `P-05`로
  왔는데 배경이 또 바뀌었으면 현재 배경.

**v7이 "상세 내용 확인 필요"로 둔 `E-04`·`E-07`은 정책서 예외표의 행이다.**

| # | 케이스 | 처리 |
|---|---|---|
| `E-04` | 그룹 삭제 또는 도착 후 본인이 나감 | `G-001` + 토스트 `참여 중이 아닌 그룹이에요` |
| `E-07` | 사진·텍스트 신고·삭제 뒤 탭 | 캔버스 진입 + 토스트 `해당 사진은 삭제됐어요` / `해당 텍스트는 삭제됐어요` |

Figma 프레임 주석은 "정상 케이스에 대해서는 토스트 없음 / 자세한 사항은 정책문서
참고"뿐이다([[src-figma-주석-캔버스-C-SY]]). `E-`는 **푸시 정책의 예외 케이스
일련번호**(`E-01`~`E-28`)다.

## 시간과 수명

- **서버 KST 고정.** 해외 체류자도 KST로 받는다(`E-14`).
- TTL(`E-09`) — `P-01`·`P-04`·`P-05` **6시간**, 리마인드 **1시간**, `P-06` 1시간.
  **21:00 이후 리마인드 도착 금지.**

## 토큰은 계정과 다르게 지워진다

[[account]]의 탈퇴(`S-003`)와 로그아웃(`S-005`)에서 **계정·데이터는 soft delete인데
푸시 토큰만 즉시 하드 삭제**한다. 재로그인하면 다시 등록한다.

- **다른 기기 로그인 시 구 토큰 즉시 폐기**(`E-11`). 단일 기기 로그인과 맞는다.
- **탈퇴 후 재가입은 신규 이용자**다 — 토큰 신규, 권한 요청 다시, `S-105` 설정은
  기본값으로 초기화(`E-13`).

## 쓰지 않는 곳 — 공지사항

**새 공지는 푸시를 보내지 않는다**([[notice-board]]). 이유가 비용이다 — 새 푸시 종류를
만들면 이 정책, 이용약관 제5조의2, `S-105`가 함께 바뀐다
([[src-S-106-공지사항-운영-정책-v0.3]]).

## 미결

- `P-06`의 `N` 집계·표기 상한이 서버 회신 대기다.
- `P-04` 텍스트 등록의 트리거 화면이 없다. `P-01`의 `C-106`도 UX_1 뒤 다른 화면을
  가리킨다.
- `P-01` 제목 변경이 개정이력에 없다.
- 푸시 정책 개정이력의 "법적 요건 정리" 절이 수집본에 없다.
- `S-105` 정책의 "폐기 사항 §6"이 수집본에 없다.
- 리마인드를 앱에서 끌 수 있는데 권한 모달은 기기 설정만 안내한다.
- "토핑 → 사진" 용어 변경이 푸시 문서 밖에도 적용되는지.
- 05-14 MVP 제외를 뒤집은 결정 문장이 없다. 단서는 08-27 2차 UT 발화다.
- 기본값(묶음·상한·쿨다운 없음)을 둔 근거. 묶음은 opt-in으로 생겼고 앱 안 끄기를 주지
  않는 근거는 적혔다.
- 같은 사건에 Toast와 푸시가 둘 다 뜨는지. 푸시 쪽은 열람 중에도 보낸다로 확정됐다.
