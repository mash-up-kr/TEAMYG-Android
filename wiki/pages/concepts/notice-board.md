# 공지사항

## 정의

`S-106`(앱 사이드메뉴 `S-001` > 공지사항)이다. **새 버전 안내와 약관·개인정보처리방침
개정 고지**를 앱 안에서 하는 목록·상세 화면이다. 정본은
[[src-S-106-공지사항-운영-정책-v0.3]](11-11, 초안)이다.

**v7에는 없던 화면이다.** 10-20 회의가 후속 우선순위 4위로 "공지사항 추가"를 올렸고
([[src-회의록-2026-10-20-회의]]), 10-31~11-11 사이 정책이 세 판 나왔다.

## 왜 만들었나 — 약관이 먼저 있었다

- 앱 안에 공지 수단이 없어 **새 버전 안내와 약관 개정 안내를 할 곳이 없었다.**
- **이용약관 제3조와 개인정보처리방침 제12조가 "서비스 내 공지사항(사이드 메뉴 >
  공지사항)"을 개정 고지 채널로 이미 명시하고 있었다.** 약관이 가리키는 메뉴가 앱에
  없던 상태다.
- iOS와 Android는 패치노트가 조금씩 달라 업데이트마다 따로 나간다.

**그래서 공지사항은 법정 고지 수단이다.** 이것이 아래 삭제 금지·게시 시점 규칙의
근거가 된다.

## 출시 — 1.3.0, 알림 설정과 함께

**공지사항은 `S-105` 알림 설정과 같은 Minor 업데이트(예시 버전 `1.3.0`)로 나간다.**
정책이 첫 공지를 "푸시알림 인앱 제어 기능 추가와 묶여 나가는 Minor 업데이트"로 적고,
`S106-E03`이 **"v1.3.0 미만 앱 유저"**는 화면이 없어 볼 수 없다고 적는다.

**공지사항 오픈 버전 자체가 첫 공지다.** 신규 기능(`S-105`·`S-106`)이 있으니 Minor이고,
iOS·Android 각 1건이다. 11-10 기준 서버 개발 완료·미배포, **다음 주 배포**
([[src-회의록-2026-11-10-회의]]).

## 네이티브 화면이다 (v0.3 현행, [[src-S-106-공지사항-운영-정책-v0.3]])

**웹뷰가 아니라 앱 네이티브 화면이다.** v0.3에서 확정됐고 사유는 "개발 확인"이다.
작업 카드(`BL_04`)에는 웹뷰로 적혀 있었고, 11-03 회의가 "~~웹뷰~~ → 네이티브"로
고쳤다([[src-회의록-2026-11-03-회의]]).

11-10 작업 표는 여전히 "공지사항 (웹뷰)"다([[src-회의록-2026-11-10-회의]]). 11-03
회의와 11-11 정책서가 둘 다 네이티브라 **회의록 표 라벨이 갱신되지 않은 것**으로 읽는다.

**같은 메뉴의 약관(`S-004`)은 웹뷰다.** 약관·개인정보처리방침·오픈소스 라이선스·아동
안전 정책(Android만)은 웹뷰로 띄우고, 공지사항만 네이티브다
([[src-figma-주석-앱-사이드-메뉴-S-00n]]).

| 화면 | 구성 |
|---|---|
| 목록 | 게시일 최신순. 행마다 제목, 아래 날짜, 오른쪽 화살표. NEW 대상이면 **제목 뒤** `Chip-New` |
| 상세(`S-106-Detail`) | 카드 안에 제목·날짜·구분선·본문. NEW 칩 없음 |
| 오류(`S-106-Error`) | 상단 바 아래 토스트만 — `공지를 불러오지 못했어요, 나중에 다시 시도해 주세요`([[toast]]) |
| 0건 | "이럴 일 없음". 기능 배포와 함께 첫 공지를 게시하므로 빈 상태 디자인이 없다 |

**서버가 관리하고 앱은 받은 값을 그대로 표시한다**(원칙 `P-1`). 앱 업데이트 없이
올리고 고치려는 것이다.

## 무엇을 공지하나

| | 업데이트 공지 | 안내 공지 |
|---|---|---|
| 대상 | **Major·Minor만.** Patch는 올리지 않는다 | 약관·개인정보처리방침 개정 |
| 제목 | `파르페 v{버전} 업데이트 안내` | `이용약관 및 개인정보처리방침 개정 안내` / `이용약관 개정 안내` / `개인정보처리방침 개정 안내` |
| 날짜 | 게시일 `YYYY.MM.DD` | 공고일. 본문은 시행일 |
| 본문 | **해당 버전 패치노트 원문만** | 시행일 안내 문장 |
| 플랫폼 | **공지 1건 = 1플랫폼** | 공통 |

- **Patch를 빼는 이유** — Patch까지 올리면 중요한 변화가 묻힌다.
- **1건 = 1플랫폼인 이유** — 배포 시점·패치노트가 달라 게시·수정이 독립된다. 공통 내용을
  두 번 등록해야 하는 단점을 원문이 함께 적었다.
- **인사말·"스토어에서 업데이트해 주세요" 같은 문구를 쓰지 않는다**(원칙 `P-2`).
- **소급하지 않는다** — 공지사항이 처음 열리는 버전부터 쓴다.

## 게시와 보관

- **업데이트 공지는 스토어에 공개된 뒤 게시한다.** 먼저 보이면 "업데이트가 없다"는
  혼선이 생긴다. 한쪽만 먼저 나가면 그쪽만 먼저 게시한다(`S106-E01`).
- 사용자는 **자기 기기 OS의 업데이트 공지와 공통 공지만** 본다. 자기 앱보다 높은 버전
  공지도 보인다 — 업데이트 유도 효과(`S106-E04`).
- **안내 공지는 시행일 7일 전, 사용자에게 불리한 변경은 30일 전**까지 게시한다
  (이용약관 제3조, 개인정보처리방침 제12조).
- **수정은 서버에서 바로, 수정 표시 없음, 게시일 불변.**
- **삭제는 원칙적으로 하지 않는다.** 잘못 올리면 수정으로 정정한다. **안내 공지는
  법정 고지라 삭제 금지.**
- 노출 기간 제한 없이 전부 게시일 최신순. 같은 날이면 나중 등록이 위(`S106-E06`).

### 누가 올리는지는 정해지지 않았다

운영 절차는 다섯 단계다 — 버전 확정(Patch면 끝) → 플랫폼별 패치노트 → 스토어 공개
확인 → **서버 등록** → 앱 노출 확인. **누가 서버에 등록하는지, 어드민이 있는지는 없다.**

10-27 회의가 **"어드민을 구축할지, 구글 사이트에서 수동 등록할지"**를 정하지 못했다 —
"정해진 게 너무 없어서 진척이 X"([[src-회의록-2026-10-27-회의]]). 그보다 앞서 09-21
우선순위 회의에서 **어드민 개발은 2위로 집계됐다가 취소선이 그어졌고** 취소 이유는 없다
([[src-회의록-2026-09-21-우선-순위-정의-회의]]).

## NEW 칩 — 푸시 대신

**새 공지는 푸시를 보내지 않는다**(원칙 `P-5`). 목록 행과 `S-001`의 `공지사항` 라벨
오른쪽에 **같은 `Chip-New`**를 단다. 별도 뱃지를 만들지 않는다.

| 항목 | 규칙 |
|---|---|
| 노출 | 열어보지 않은 공지 |
| 소멸 | 상세를 열면, 또는 **게시 후 14일**이 지나면 |
| 사이드 메뉴 칩 | 목록에 NEW가 하나라도 있으면 표시, 다 사라지면 숨김 |
| 읽음 기록 | **기기에만 저장. 서버에 저장하지 않는다** |

**그래서 업데이트 직후·재설치·신규 설치면 14일 안 공지가 전부 NEW로 보인다**
(`S106-E05`). 의도된 동작이다.

**14일은 11-03 회의에서 정해졌다** — "~~일주일 간 new 보여줌~~ → 14일 지나면 new
안보이게, 클릭해서 봐도 new 안보이게"([[src-회의록-2026-11-03-회의]]).

**새 글 판단이 "마지막 확인 시점"에서 "공지 단위 읽음"으로 바뀌었다.** v0.1은 기기에
마지막 확인 시점을 두고 `S-106`에 들어가면 뱃지를 해제했으며, 첫 실행이면 그 시점을
현재로 초기화했다(`E05`). v0.2가 이 초기화를 폐기했다 — **업데이트한 사용자가 첫 공지의
NEW를 못 보게 되고, "재설치하면 다시 뜬다"와 모순된다.**

Figma 주석은 칩이 동시에 최대 2개(보통 1개), 제목이 두 줄을 넘으면 칩 자리를 남기고
말줄임이라 적었다([[src-figma-주석-앱-사이드-메뉴-S-00n]]).

### 푸시를 쓰지 않는 이유 — 비용

원문 근거는 **"푸시 종류를 새로 만들면 푸시알림 정책·이용약관 제5조의2·`S-105`가 함께
바뀐다"**다. 사용자 피로가 아니라 **문서·약관을 같이 고치는 비용**이 이유다. 범위를
좁힌 결정에 근거가 붙은 사례다([[mvp-scope-limits]]).

같은 시기 팀 방침도 같은 방향이었다 — 10-06 회의의 **"푸시는 안 씀" / "푸시 지양"**
([[push-notification]]). 다만 공지 정책서는 그 방침을 근거로 들지 않았다.

## 사이드 메뉴가 무거워졌다

`S-105`·`S-106`·아동 안전 정책(Android만)이 더해지며 `S-001`이 길어졌다. 11-03 회의가
**웹뷰 항목 넷(이용약관·개인정보처리방침·아동안전정책·오픈소스 라이선스)을 묶어
아래로 내리는 안**을 냈고, "별로면 이전 버전 유지"다([[src-회의록-2026-11-03-회의]]).
정책서는 "메뉴 내 위치·순서는 사이드 메뉴 정리 결과를 따른다"고만 적는다.

**`S-106`은 앱 레벨 메뉴인데 번호가 `S-1xx`(그룹 레벨) 대역이다.** `S-105`도 같다
([[screen-id-scheme]]).

## 미결

- 공지 등록 주체·어드민이 없다.
- `S-105`·`S-106`이 앱 레벨 메뉴인데 `S-1xx` 대역이다.
